# MODE:P vNext Golden Set 样本证据报告

> 状态：高权重设计证据
>
> 日期：2026-07-22
>
> 用途：记录故事板提示词、实际故事板、视频提示词、实际视频之间的可追溯关系，为 MODE:P vNext LOOP、数据模型、编译规则和 Golden Set 提供事实依据。

---

## 1. 报告目的

本报告不评价传统摄影理论是否“标准”，而是回答：

1. 哪些提示词设计真实地控制了故事板。
2. 哪些故事板信息真实地迁移到了视频。
3. 哪些视频提示词指令实际生效。
4. 哪些非字面执行改善了 AI 视频结果。
5. 哪些偏移破坏了故事板的预判能力或剧情事实。
6. 新 MODE:P 必须保留哪些机制。
7. 哪些机制应当进入知识库、Master、编译器或验收器。

---

## 2. 证据权重

### 2.1 A级证据

同一场景同时具备：

- 故事板提示词。
- 实际故事板图片。
- 视频提示词。
- 实际视频。
- 用户质量评价或明确用途说明。

本报告四组样本均达到完整四件套，用户对窄巷运镜给出明确高评价；其他样本可根据实际结果进一步区分成功与诊断价值。

### 2.2 B级证据

- 当前 MODE:P 实际输出。
- 当前项目代码和测试。
- 可复现的 FFmpeg 元数据与切镜检测。

### 2.3 C级证据

- 旧管道文件。
- 旧模板。
- 历史设计文档。
- 通用电影理论。

C级证据只用于解释或提出假设，不得推翻A级真实结果。

### 2.4 用户确认的生产失败类别

用户确认存在以下重复风险：当剧本写“人物在手机上打游戏”，而机位只拍手机背面时，视频模型仍可能把游戏画面贴到后壳、叠加到画面或错误生成透明结构。

该陈述属于用户确认的生产问题，不等同于本报告八个媒体文件中的逐帧证据。它可以定义项目级风险和文本回归测试；只有经过新的故事板—视频配对验证后，才可晋升为通用模型能力结论。

旧管道的“只描述当前机位真实可见物”规则属于 C 级佐证。它之所以在 vNext 中被保留，不是因为旧文件权威，而是因为它同时解释了观众席 UI 失败和用户确认的手机背面失败类别。

## 3. 分析方法

### 3.1 四层对照

每组样本按四层分析：

1. 故事板提示词 → 实际故事板。
2. 实际故事板 → 实际视频。
3. 视频提示词 → 实际视频。
4. 设计意图 → 用户感知结果。

### 3.2 时间分析

- 视频以0.5秒联系表为基础。
- 关键运动或表演区间可提高到4fps。
- FFmpeg scene filter用于发现切镜候选。
- 高运动镜头中的scene高分可能是运动变化，不自动视为切镜。
- 最终切点由联系表和相邻帧人工复核。

### 3.3 评价单位

不以像素重合为主要标准，使用以下层级：

- 事件拓扑。
- 注意力拓扑。
- Cinematic Shot 顺序。
- 摄影机运动方向。
- 人物和道具关系。
- 起幅。
- 过程阶段。
- 落幅。
- 光影职责。
- 身份与行为。
- 可核验禁止项。

### 3.4 偏移分类

- LOCKED violation：改变剧情、行为、方向、关键节点或落幅。
- ELASTIC deviation：不改变结果的小幅时间或构图变化。
- OPTIMIZABLE deviation：非字面执行但改善连接和观看效果。
- INCIDENTAL：只在个别样本出现，无法证明可迁移。

## 5. 共通媒体事实

四张故事板均为横向16:9，四个视频均为竖向734×1280。

由此可以确定：

1. 故事板不是视频像素模板。
2. 故事板主要传递人物关系、景别阶段、运动方向、注意力路径和落幅。
3. 横版到竖版允许语义重构。
4. 不应把人物精确像素坐标设为主要忠实度指标。
5. 必须锁定银幕方向、前中后景关系、视觉中心和注意力交接。

## 6. 样本一：第八集枪管

### 6.1 设计结构

时长约13秒，一个连续生成段，一个连续电影镜头。

注意力路径：

~~~
工作室与Rico背影
→ Rico右手进入灯光
→ 摄影机绕至右侧
→ 小物举至眼前
→ 管口成为视觉中心
→ 摄影机进入管口
→ 金属内壁填满画面
~~~

### 6.2 故事板提示词 → 实际故事板

成功转化：

- 13格时间控制。
- 0-3s门口全景和缓慢推进。
- 3-4s弧形绕至Rico右侧。
- 4-7s手部、物体和眼睛关系。
- 7-10s管口逐渐扩大。
- 10-13s管内纹理填满画面。
- 蓝色摄影机箭头。
- 红色身体运动箭头。
- 绿色构图中心。
- 橙色灯光方向。

实际故事板的重要特征：

- 画面从环境逐格减少元素。
- Rico、台面、手、眼睛依次退出。
- 最后只保留圆形管内结构。
- 视觉尺度收缩清楚。

故事板歧义：

- 后段螺旋线稿具有漩涡或幻觉感。
- 如果视频只依赖故事板图像，可能把机械纹理解释成魔幻旋涡。

### 6.3 实际故事板 → 实际视频

高度一致：

- 开场为门口或房间后方视角。
- Rico背对摄影机。
- 工作灯形成中心暖光区。
- 摄影机向前接近。
- 摄影机转到Rico右侧。
- Rico把圆管形物体举至眼前。
- 管口逐渐扩大。
- 最终进入并停留在金属内壁。

横竖画幅变化：

- 横版故事板的宽工作台被压缩为竖版纵深。
- Rico身体比例和台灯位置重新组织。
- 注意力路径没有改变。

### 6.4 视频提示词 → 实际视频

明显生效：

- ①、②、③的阶段定义。
- ①→②弧形绕行。
- ②→③进入圆管。
- 逐秒目标大小变化。
- 暖黄单灯环境。
- 最终金属内壁。
- 平滑推进。
- Rico脸部只在局部出现。

纠偏生效：

- 视频没有把管内结构表现为魔幻隧道。
- 金属纹理和暖色反光取代故事板的视觉歧义。
- “不是漩涡不是幻觉”属于有效的物理纠偏。

### 6.5 切镜与时长

- 实际时长：13.041667s。
- FFmpeg未检出真实硬切。
- 整段为连续摄影路径。

### 6.6 成功机制

1. 只有一条注意力路径。
2. 每个阶段都有明确起点和落点。
3. 主体数量持续减少。
4. 图像、编号、焦段、箭头和文字重复表达同一运动。
5. 最终画面具有唯一形状和唯一视觉中心。
6. 视频文字主动纠正故事板歧义。

### 6.7 可迁移知识

- camera.attention_contraction
- camera.continuous_path_start_process_landing
- composition.progressive_element_removal
- object.reveal_scale_chain
- prompt.physical_disambiguation

### 6.8 Golden 约束

LOCKED：

- 单一连续镜头。
- 背影到右侧到管口到管内。
- 最终金属内壁填满画面。

ELASTIC：

- 精确焦段视觉效果。
- 推进速度小幅变化。
- 横竖画幅重排。

FORBIDDEN：

- 硬切。
- 魔幻漩涡。
- 台灯移动。
- 管口没有成为最终焦点。

## 7. 样本二：第六集观众席

### 7.1 设计结构

一个约12秒Generation Segment，包含三个内部Cinematic Shot：

1. 观众席全景。
2. 伊莎贝拉与乔双人中近景。
3. 手机屏幕极近特写。

注意力路径：

~~~
场馆与观众
→ 伊莎贝拉和乔的关系
→ 手机中的未回复信息
~~~

### 7.2 故事板提示词 → 实际故事板

成功转化：

- 0-3s四格全景保持。
- 4-8s五格双人中近景。
- 9-11s三格手机特写。
- 伊莎贝拉画左、乔画右。
- 乔耳罩和防护镜。
- 乔转眼看向伊莎贝拉。
- 手机作为最终证据。
- 两次明确景别跳跃。

故事板中的风险：

- 手机界面包含平台符号和文字。
- 线稿中可能出现类似双勾的状态符号。
- “无回复”依赖负空间，但图像生成器容易自动补充聊天内容。

### 7.3 实际故事板 → 实际视频

保留：

- 三段镜头顺序。
- 全景到双人到手机的尺度递进。
- 伊莎贝拉左、乔右。
- 手机作为最终信息揭示。

偏移：

- 第一镜实际使用后方或中轴方向观察场馆，而不是故事板侧前方构图。
- 主要空间锚仍存在，但人物位置不逐像素一致。
- 第二段保持时间比计划略长。

### 7.4 视频提示词 → 实际视频

生效：

- 一个视频内出现两次真实硬切。
- 三个镜头景别差异清楚。
- 双人位置稳定。
- 乔的反应方向可读。
- 手机屏幕冷光与环境光区分。

失效：

- 手机出现额外灰色回复气泡。
- 屏幕部分文字或界面元素不稳定。
- “无回复、无已读、无正在输入”未被完全执行。

这说明：

- 切镜结构可以由视频模型执行。
- 剧情依赖的精确UI不宜只靠自然语言生成。
- 应使用预制屏幕参考、首帧或后期合成。

进一步判断：

- 这是“生成补全泄漏”，不只是文字渲染精度不足。
- 提示词把 WhatsApp、消息气泡和缺失回复同时交给模型，模型依据聊天界面先验自动补全了额外对话状态。
- “无回复、无已读、无正在输入”属于否定边界，但缺少对允许出现内容的严格白名单和对空白负空间的正向闭合。
- 因此，针对性 @禁止 必须保留用于验收，但不能成为唯一生成控制。

### 7.5 切镜与时长

- 实际时长：12.041667s。
- 真实切点：2.666667s。
- 真实切点：9.208333s。

与计划比较：

- 第一次切镜约提前0.33s。
- 第二次切镜约晚1.2s。
- Cinematic Shot数量、顺序和功能没有改变。

该偏移属于ELASTIC节奏偏移，不属于结构失败。

### 7.6 成功机制

1. Generation Segment层声明三段结构。
2. 编号含义再次声明三段结构。
3. 故事板图像提供三种显著不同构图。
4. 视频提示词用分隔块和“切”再次控制。
5. 信息尺度从空间到关系再到证据。
6. 镜头功能差异足够大，模型不易合并。

- editing.information_scale_progression
- attention.space_relationship_evidence
- ui.generated_text_risk
- visibility.generative_completion_leakage
- visibility.visible_information_whitelist
- visibility.positive_empty_state_closure
- capability.negative_instruction_routing
- reference.screen_insert_control

### 7.8 Golden 约束

LOCKED：

- 一个Segment包含三个内部镜头。
- 顺序为WS、双人MCU、手机ECU。
- 伊莎贝拉左、乔右。
- 手机表达未回复。
- 只存在设计中明确给出的发出消息，消息下方保持连续空白负空间。

ELASTIC：

- 两个切点各约±1s。
- 第一镜精确机位。
- 横竖构图重排。

FORBIDDEN：

- 合并为单一无切镜视频。
- 手机出现回复或正在输入。
- 自动补充通知、已读状态、额外气泡或其他未经设计的 UI 信息。
- 人物左右关系反转。
- 最终镜头不是手机。

## 8. 样本三：第六集贫民窟窄巷

### 8.1 设计结构

约13秒，包含：

- 低机位追球。
- 抬头和仰摇。
- 直升机经过。
- 回到巷口与Pedro背影。
- 发现黑色轿车。
- 推近轿车落幅。

注意力路径：

~~~
足球
→ Pedro
→ 天空
→ 直升机
→ Pedro的视线
→ 黑色轿车
~~~

### 8.2 故事板提示词 → 实际故事板

成功转化：

- 窄巷不足2m的挤压感。
- 低机位追球。
- Pedro弯腰捡球和抬头。
- 仰摇过渡格。
- 直升机画右向画左。
- 切回巷口。
- Pedro背影和远处轿车。
- 最终轿车与城市层次。

故事板时间结构：

- 不是严格一格一秒。
- 包含动作格、仰摇过渡格、切镜格和区间推近格。
- 9-11s推近被合并为一个运动区间Panel。

这证明成功故事板是时间控制图，不是机械逐秒表。

故事板小错误：

- 个别格的焦段标注与文字提示存在25mm/35mm差异。
- 视频提示词恢复了35mm方向。

### 8.3 实际故事板 → 实际视频

保留：

- Pedro、天空、直升机、轿车的事件顺序。
- 直升机画右向画左。
- 轿车作为最终威胁。
- 冷灰天气。
- 黑车静止。
- 最终摄影机收紧到轿车。

改变：

- 开场Pedro更多以正面或侧前方出现，不是完全背后跟拍。
- 直升机被拆成独立城市天空镜头。
- 回到Pedro和轿车的时间早于原计划。
- 9s处没有执行硬切。
- 摄影机在同一镜头中重构画面，让Pedro退出、轿车扩大。

### 8.4 视频提示词 → 实际视频

生效：

- 窄巷空间。
- Pedro与足球。
- 抬头到天空。
- 直升机方向。
- 黑色轿车静止。
- 最终推向轿车。
- 城市与贫民窟层次。

非字面但改善：

- 模型新增直升机独立镜头。
- 模型取消9s机械硬切。
- 连续重构完成注意力交接。
- Pedro退出与轿车扩大同步发生，威胁揭示更连贯。

### 8.5 切镜与时长

- 实际时长：13.041667s。
- 经逐帧复核的真实切点：4.583333s。
- 经逐帧复核的真实切点：7.375s。
- 2.3-3.7s出现的大量scene高分来自快速仰摇和画面变化，不是硬切。
- 9s附近没有真实硬切。

### 8.6 用户评价

用户明确指出：

- 最后一组的运镜和效果非常好。
- 以AI制作结果衡量，属于成功效果。

因此不能用“没有逐字执行切点”判为失败。

### 8.7 成功机制

1. 事件顺序锁定。
2. 运动方向锁定。
3. 最终落幅锁定。
4. 中间连接没有改变剧情事实。
5. 模型利用竖屏重新组织人物退出和轿车扩大。
6. 评价以叙事忠实和最终效果为准，不以字面切点为唯一标准。

### 8.9 Golden 约束

LOCKED：

- 事件顺序。
- 直升机方向。
- 黑车静止和熄灯。
- 最终黑车为绝对焦点。

ELASTIC：

- 切点时间。
- 开场Pedro精确朝向。
- 人物画面比例。

OPTIMIZABLE：

- 直升机是否独立切镜。
- 9s硬切是否替换为连续重构。
- Pedro退出方式。

FORBIDDEN：

- 直升机方向反转。
- 轿车移动、亮灯或出现人物。
- 蓝天或阳光。
- 最终焦点不是轿车。

## 9. 样本四：第六集备赛区擦肩

### 9.1 设计结构

约10秒，一个固定机位，一个连续镜头。

注意力和空间关系：

~~~
Rico在右侧前景擦枪
→ 伊乌里从左侧入画
→ 两人擦肩
→ Rico短暂停顿
→ 伊乌里走向远端亮区
→ Rico继续留在暗处
~~~

### 9.2 故事板提示词 → 实际故事板

成功转化：

- Rico在画面右侧。
- 金属桌位于前景。
- 中央通道通向远端靶场。
- 伊乌里从画左入场。
- 两人近距离擦肩。
- 伊乌里走向亮区。
- Rico留在暗区。
- 全程固定机位。

结构问题：

- 文本称10秒、10格，但实际故事板包含0-10s共11个状态格。
- 文字正文主要描述0-9s。
- 格数、时间和时长存在不一致。

可见性矛盾：

- 伊乌里主要以背影或侧背出现。
- 同时要求看见嘴角上提0.5秒。
- 当前机位难以验证嘴角变化。
- “不看Rico”与“通过面部确认表达潜台词”竞争。

### 9.3 实际故事板 → 实际视频

成功保留：

- 固定机位。
- Rico右前景。
- 中央通道。
- 伊乌里从画左经过。
- Rico不抬头。
- 伊乌里最终背对镜头走向远端。
- 明暗空间对角关系。

偏移：

- 实际视频只有9.041667s。
- 伊乌里约2.5s开始入画，而不是5s。
- 擦肩和人物交接整体提前。
- 伊乌里在约4s明显转头看向Rico。
- Rico手部停顿没有形成强而可验证的约1秒静止。
- 嘴角微表情无法可靠读取。

### 9.4 视频提示词 → 实际视频

生效：

- 固定机位。
- Rico低头擦枪。
- 伊乌里沿通道移动。
- 两人近距离经过。
- 远端亮区。
- Rico留在暗处。

未生效：

- 5s首次入画。
- 伊乌里不看Rico。
- 明确的0.8-1.5s手部停顿。
- 可见但不是微笑的嘴角动作。

### 9.5 切镜与时长

- 实际时长：9.041667s。
- FFmpeg未检出真实硬切。
- 摄影机整体固定。

### 9.6 失败机制

#### 等待被压缩

0-4s只有重复擦枪。时间线写“画面同前”不足以告诉模型：

- 中央通道必须保持空。
- 伊乌里在5s前绝不能出现。
- 这段等待本身具有叙事功能。

#### 不可见微表演

机位看不到嘴角，但叙事要求表达“确认”。模型用更明显的回头替代表达。

#### 禁止项不能修复设计矛盾

“不看Rico”虽然被写入禁止项，但正向剧情仍暗示两人发生可读交流。模型选择更容易读取的回头。

### 9.7 可迁移知识

- timing.locked_absence_window
- timing.first_appearance_boundary
- performance.observable_microreaction
- staging.back_view_expression_conflict
- prompt.negative_constraint_cannot_repair_design
- action.hold_requires_controlled_state

### 9.8 Golden 约束

LOCKED：

- 固定机位。
- Rico不抬头。
- 伊乌里首次入画时间。
- 伊乌里不看Rico。
- 擦肩距离。
- Rico停顿。
- 伊乌里走向亮区。

ELASTIC：

- 擦枪手部细微路径。
- 伊乌里步幅。
- 最终人物大小。

FORBIDDEN：

- 伊乌里提前入画。
- 伊乌里回看Rico。
- Rico抬头。
- 擦肩距离超过1m。

历史视频应被标注为：

- 构图成功。
- 空间方向成功。
- 行为失败。
- 时序失败。
- 微表演可见性失败。

## 10. 跨样本机制

### 10.1 必须保留

- Generation Segment 与 Cinematic Shot 分离。
- 事件和注意力拓扑。
- 起幅、过程、落幅。
- 机位阶段与阶段间路径。
- HOLD和首次入画。
- 参考职责分离。
- 最终保持。
- 针对性禁止项。
- 实际故事板作为视频模型的构图参考。
- 当前机位可见信息与叙事信息分离。
- 高风险表面的正向物理闭合。
- 模型负向指令能力分流。

### 10.2 有效冗余

以下重复不是格式浪费：

- 编号含义。
- 阶段标题。
- 每秒状态。
- 故事板箭头。
- 自然语言运镜。
- 焦段和景别变化。
- 正向物理状态。
- @禁止。
- 段末转场。

它们从不同表示层重复控制同一意图。

### 10.3 可优化区

- 非关键切点小幅偏移。
- 横向到竖向构图重排。
- 中间摄影路径自然化。
- 在不改变节点的情况下用连续重构替代硬切。
- 自然微动。

### 10.4 严重偏移

- 人物做出相反行为。
- 关键人物提前出现。
- 运动方向反转。
- 缺失内部镜头。
- 最终焦点改变。
- 增加不存在的剧情信息。
- 道具状态改变。
- 被遮挡、画外或只在叙事层成立的信息被生成到画面。
- 手机、镜面、玻璃、文字或 UI 自动补充未经设计的内容。

## 11. 三个核心解释

### 11.1 枪管为何几乎逐阶段复现

因为设计只有一条注意力收缩链，且同一链被时间、编号、箭头、焦段、构图和文字多次编码。模型的自由度集中在运动平滑度，而不是事件路径。

### 11.2 观众席为何保留三段内部切镜

因为三镜结构同时存在于：

- 编号。
- 时间范围。
- 故事板构图。
- 切镜分隔。
- 景别跳跃。
- 信息尺度递进。

一个Generation Segment内存在多个Cinematic Shot是已被实际视频验证的能力。

### 11.3 窄巷为何非字面执行仍更优秀

因为模型改变的是节点连接方式，没有改变事件顺序、运动方向、注意力交接和最终落幅。连续重构比机械硬切更适合竖屏和人物退出，因此属于受控优化。

## 12. 对 MODE:P vNext 的直接约束

### 12.1 知识

知识库必须包含：

- 注意力收缩。
- 内部镜头拓扑。
- 信息尺度递进。
- 锁定节点与弹性连接。
- 横竖画幅语义重构。
- 微表演可见性。
- 首次入画和空区保持。
- UI和文字风险。
- 物理纠偏。
- 生成补全泄漏。
- 表面朝向、遮挡和信息通路。
- 正向可见性闭合与负向能力分流。

### 12.2 Master

Master必须能表达：

- 一个Segment多个Shot。
- 显式HOLD。
- 首次出现时间。
- Panel类型。
- 内部Boundary。
- 四类Fidelity。
- 用户故事板纠正。
- 每个 Shot 的 Visibility Contract。
- visible_whitelist、occluded_state、narrative_only、audio_only、positive_closure、leakage_risks、forbidden_qa 和 negative_route。

### 12.3 编译器

编译器必须保留：

- 括号。
- 距离。
- 时间。
- 颜色和光源参数。
- 纠偏语句。
- @禁止。
- 有效冗余。
- Visibility Contract 字段的确定性路由。
- 人类 VIDEO_PROMPT 与实际 Render Payload 的字段来源记录。

### 12.4 DP

DP必须检查：

- 动作能否被当前机位看见。
- 背影与面部微表演是否矛盾。
- HOLD是否具有明确受控对象。
- 关键空区是否写出。
- 内部切镜是否被错误拆出Segment。
- 当前机位是否真的看见被描述表面。
- 隐藏或画外信息是否泄漏进视觉正文。
- 是否只写了否定句而没有正向物理闭合。
- negative_route 是否符合目标模型能力。

### 12.5 验收

验收必须先检查LOCKED/FORBIDDEN，再评价ELASTIC/OPTIMIZABLE。总分不能补偿剧情硬约束失败。

### 12.6 Visibility Contract 的证据结论

当前证据支持以下生产规则：

1. 剧本事实不能自动等同于当前镜头可见内容。
2. 模型容易依据常见物体语义补全未要求的信息，聊天 UI 已有实际视频证据。
3. 用户确认手机背面出现游戏画面是同类生产风险，但仍需进入新文本回归组和后续媒体验证。
4. 旧管道“只描述画面内可见物”只能作为佐证，不能直接复制整套旧规则。
5. 第一控制层必须是 visible_whitelist 和 positive_closure。
6. 第二控制层才是 forbidden_qa，并按模型能力决定是否进入 Render Payload。
7. 算法只能执行字段路由和来源校验；是否真实可见仍由 Director 设计、DP 审查和用户验收。

手机背面、镜面、玻璃、画外声音、聊天空白和物体背面必须形成独立文本回归组。该回归组不需要 MODE:P 在运行时读取图片或视频。

---

## 13. 证据限制

1. 四组样本来自同一项目，不能自动代表所有模型和题材。
2. 只有窄巷获得了明确的最高质量主观评价。
3. 观众席整体结构成功，但手机UI存在明确失败。
4. 备赛区不能作为完全成功案例。
5. FFmpeg能验证时长和切镜，不能独立判断人物视线、导演感和剧情语义。
6. 未经用户批准的推测不得晋升为通用知识。
7. 四组样本优先形成项目级知识和Golden Set，再通过新场景验证是否晋升。
8. 手机背面打游戏属于用户确认的问题类别，目前没有绑定新的配对媒体，因此不能伪装成逐帧验证结论。
9. 当前四组样本是机制发现与格式校准集，不是独立 Holdout；不能用同一批样本同时证明知识设计无过拟合。
10. 历史外部生成缺少统一 STORYBOARD_RUN_RECORD/RENDER_RUN_RECORD，现有配对依靠文件、内容和用户上下文确认；未来 K3 validated 必须绑定正式运行记录。
11. 样本文本存在秒数端点和格数歧义，尤其备赛区“10秒/0-10s/11状态”；vNext 必须使用 Canonical Timeline，而不是把历史歧义固化成模板。

---

## 14. 最终证据结论

真实成功机制不是“使用了旧模板”或“写得足够长”，而是：

> 导演先建立清楚的事件与注意力拓扑，再把起幅、过程、落幅、运镜方向、内部切镜、构图关系、参考职责和失败边界重复编码到故事板与视频提示词中。视频可以在节点之间优化，但不能改变人物行为、剧情事实、运动方向和最终注意力落点。

该结论是 MODE:P vNext LOOP 的最高权重设计依据。
