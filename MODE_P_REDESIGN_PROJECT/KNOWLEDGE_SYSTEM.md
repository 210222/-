# MODE:P 知识内化与持续学习规范

## 1. 目标

知识系统要让 Director 在面对剧本时形成稳定的导演判断，而不是机械套用历史镜头或输出规则引用。

知识系统必须同时满足：

- 可追溯：知道知识来自哪份原始资料或哪次真实生成。
- 可检索：只加载当前场景相关内容。
- 可应用：知识描述决策关系，而非孤立参数。
- 可验证：经验可以用生成结果确认或否定。
- 可回退：错误经验可以撤销，不污染核心知识。

## 2. 四层知识

### K0 原始来源层

位置：`03_知识库/source/`

内容：导演教材、现有知识库、SD2.0资料、项目参考资料。只读，不在运行时直接加载，不由 Agent 自动修改。

### K1 导演核心层

位置：`01_调度器/mode_p/knowledge/core/`

始终加载：

- `director_core.md`
- `sd2.md`
- `performance.md`
- `editing_transition.md`（需要新增）

核心层只保留跨场景稳定原则：叙事优先、空间裁决、视觉强度、镜头动机、视觉中心、物理光源、切换动机、表演可见化、镜间边界和 SD2.0 边界。`sd2.md` 必须说明纯提示词、首尾帧和全能参考的能力边界，但不得把任一模式设为通用默认。

### K2 场景知识胶囊层

位置：`01_调度器/mode_p/knowledge/capsules/`

每个胶囊采用统一结构：

```markdown
# 名称

适用信号：什么剧本特征需要该知识。
核心问题：导演必须先回答什么。
可用手段：机位、运镜、构图、光影、剪辑如何联动。
变化路径：视觉设计如何随戏剧变化。
空间条件：何时成立、何时不成立。
SD2.0适配：需要怎样降复杂度。
常见失败：可观察的失败，不是禁止词清单。
对比示例：同一事件的弱设计与强设计。
```

第一批胶囊：

- 双人对话与权力变化
- 多人对话与注意力交接
- 动作与追逐
- 悬疑、发现与信息控制
- 亲密、沉思与沉默
- 调查、证据与物体揭示
- 蒙太奇与时间压缩
- 多空间转场
- 环境建立与空间叙事
- 主观镜头与受限信息
- 全能参考与跨镜连续性

### K3 项目经验层

位置：`05_项目经验/`

```text
validated/
repeated/
candidates/
rejected/
render_cases/
```

经验记录必须包含：

- 适用条件。
- 原设计意图。
- 可观察生成结果。
- 使用的 Master 版本、参考素材 asset_id 和素材内容/版本哈希。
- 推测原因，明确标记为推测。
- 修订方案。
- 修订后的真实结果。
- 验证场景与日期。
- 当前状态和置信度。

## 3. 知识索引

建立 `knowledge_index.json`，只存元数据，不存整段知识：

- 文件路径。
- 场景类型。
- 戏剧意图。
- 空间条件。
- 人物数量。
- 运动复杂度。
- SD2.0风险标签。
- 生成模式与参考素材类型。
- 经验状态。
- 验证次数。

检索过程：

```text
Scene Context
  -> 形成检索信号
  -> 过滤不满足空间/人物/模型条件的条目
  -> 相关度排序
  -> 选择 1-3 场景胶囊 + 0-3 validated经验
  -> 写 KNOWLEDGE_CONTEXT 文件清单
```

禁止无匹配时回退到某个“通用历史模式”。无匹配时只加载核心知识，让 Director 从剧本出发设计。

### 3.1 能力与素材索引

`SD2_CAPABILITY_PROFILE.json` 不是导演知识，它记录当前画布可验证的能力事实：首尾帧、全能参考、素材类型、数量/时长限制、模式互斥关系和验证日期。能力变化先更新配置并使相关缓存失效，不能依靠模型记忆。

`ASSET_INDEX.json` 为实际参考素材分配稳定 `asset_id`，记录路径、媒体类型、内容哈希、可用状态和适用职责。Director 只能引用索引中存在的 asset_id。

DP 只加载剧本事实、空间/连续性事实、当前能力配置、Master 和两个视图。DP 不加载导演风格案例或场景 Pattern，避免把审查变成第二次创作。

## 4. 决策模式库改造

当前 `decision_patterns` 只能作为经过验证的案例参考，不能成为模板答案。

每个 Pattern 必须增加：

- `applicability`：成立条件。
- `non_applicability`：不适用条件。
- `evidence`：真实场景和生成结果。
- `invariants`：可继承的原则。
- `variables`：必须由当前剧本重新设计的部分。

删除“找不到匹配就回退面对面室内对话”的策略。无匹配不是错误。

## 5. 知识蒸馏

原始知识进入胶囊前，执行以下过程：

1. 合并语义重复条目。
2. 将孤立规则改写为“意图 -> 条件 -> 联动决策 -> 风险”。
3. 删除只为规则审计存在的 ID 和证据格式。
4. 加入正反例，测试模型能否迁移到新剧本。
5. 用至少三个不同场景问答检查是否过拟合单一案例。
6. 人工确认后进入核心或胶囊层。

## 6. 学习晋升门槛

| 状态 | 进入条件 | 可被 Director 加载 |
|---|---|---|
| candidate | 一次真实生成观察 | 否 |
| repeated | 至少两个真实 render case 和对应用户观察出现同类结果 | 仅实验运行 |
| validated | 修订方案在至少两个不同场景有效，且有人工批准和回归通过记录 | 是 |
| core candidate | 多项目稳定且与导演原则一致 | 否，需人工批准 |
| rejected | 复测不成立或只属随机结果 | 否 |

任何自动流程都不能绕过状态晋升。

## 7. 防知识漂移

- 每次晋升记录变更前后版本。
- 更新胶囊后运行固定剧本回归集。
- 若新知识改善一个案例却破坏其他案例，降级为条件化经验，不进入核心。
- 用户风格偏好存入项目 Visual Bible，不晋升为通用导演知识。
- 模型自我评价不能作为验证证据。

## 8. Claude Code 命令目标

```text
/mode-p-distill <原始知识文件>
```

生成胶囊候选与迁移测试，不直接覆盖正式知识。

```text
/mode-p-learn <session目录> <真实渲染文件或观察>
```

生成 `candidate`。

```text
/mode-p-promote <candidate-id> repeated
/mode-p-promote <candidate-id> validated --approved-by <name> --regression-command "<command>" --regression-passed
/mode-p-promote <candidate-id> rejected --rejection-reason "<reason>"
```

检查真实 render case、observation 链接、跨场景证据、人工批准、回归结果和素材版本，
保存回退快照，并且只有全部通过后才允许进入 `validated`。

这些命令不属于 `/mode-p-pilot` 的默认运行路径。
