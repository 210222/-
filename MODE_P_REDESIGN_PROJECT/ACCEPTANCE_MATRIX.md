# MODE:P 验收矩阵

## A. 剧本忠实度

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| A1 | 场景完整 | 所有显式场景进入队列，顺序一致 |
| A2 | 事件忠实 | 最终设计不存在剧本之外的新剧情事件、对白、动机或结局 |
| A3 | 事实追溯 | 每镜 `story_fact` 可对应剧本内容或必要人物反应 |
| A4 | 设计自由边界 | 导演可以创造机位、场调、光影和表演处理，但不能改变叙事事实 |

## B. 导演能力

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| B1 | 戏剧理解 | 每场有明确变化点、信息策略和人物关系变化 |
| B2 | 镜头必要性 | 每镜有叙事功能；无纯装饰性重复镜头 |
| B3 | 跨域统一 | 运镜、构图、光影、表演和转场表达同一意图 |
| B4 | 全片弧线 | Visual Bible 定义并在各场体现视觉强度、色彩和节奏变化 |
| B5 | 场面调度 | 人物、机位和道具在空间中有可执行路径 |

## C. 单一设计源

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| C1 | Shot ID | Master、Storyboard、Video 100%一致 |
| C2 | 时长 | 同一 Shot 时长100%一致且单段不超过15秒 |
| C3 | 统一时间线 | 每镜只有一条可见时间线；Video 使用全部节点，Storyboard 只使用 `[SB]` 节点 |
| C4 | 摄影语言 | Camera、Composition、Lighting、Transition 无语义反转 |
| C5 | 修订路径 | 任何修订先改 Master，再派生两份视图 |
| C6 | 共享镜间边界 | N 个 Shot 正好有 N+1 个 Boundary；continuous 交接只写一份并使用 `<same>`；elliptical 显式写省略前后状态 |
| C7 | 独立可用 | 每个 Video Shot 都重述绝对开场状态，不以“承接上一镜”代替内容 |
| C8 | 参考同源 | 生成模式、参考职责和优先级在 Master 与 Video 中一致；Storyboard 首尾 `[SB]` 与 Video 首尾为同一源节点 |
| C9 | Manifest边界 | Manifest 可由 Master 完全重建且不包含新增设计；本地同步检查不声称判断自然语言语义 |

## D. 知识内化

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| D1 | 相关性 | Director 每批显式选择 0-3 相关胶囊；程序只校验并筛 0-3 条 validated 经验 |
| D2 | 无强套 | 无匹配时不加载历史 Pattern |
| D3 | 无泄漏 | Storyboard、Video、DP反馈中无规则 ID 和知识证明 |
| D4 | 可迁移 | 同一胶囊在至少三个不同剧本场景中产生合理但不同的设计 |
| D5 | 注意力 | Director 不读取旧报告、全量知识库或无关场景输出 |
| D6 | DP最小证据 | DP 不读取 Master、Manifest、知识库、Agent定义、检查器源码、哈希或历史反馈 |

## E. DP Loop

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| E1 | 独立性 | 每轮 DP 为新子 Agent，不读取 Director 隐藏推理 |
| E2 | 边界 | DP 只阻断可观察的空间、连续性和生成风险 |
| E3 | 修复范围 | Director 只改问题镜和直接受影响镜头 |
| E4 | 结束条件 | 每个待审场景都有一行引用当前 Shot 的具体 READY 证据，且不与问题混合，才进入交付检查 |
| E5 | 防空转 | 同一问题无设计变化重复时暂停并请求人类裁决 |
| E6 | 参考审查 | DP 能发现参考职责冲突、参考过载以及生成模式与主要控制目标不匹配 |
| E7 | 边界审查 | DP 能发现相邻镜头动作阶段、银幕方向、道具和光线交接不成立 |
| E8 | 调用顺序 | ID、时长、字段、边界和参考存在性等结构预检通过后才调用 DP |
| E9 | 问题契约 | 每条问题包含稳定 Shot ID 和字段；同一 Master 哈希下可计算防空转指纹 |
| E10 | 缺失输入 | `DP_INPUT_BLOCKED` 作为显式阻断保留当前 DP 状态，不假 READY、不提交、不触发创意修订 |
| E11 | 对抗审查 | 显式实模验收中 fresh DP 能发现机位路径、光源、未裁决分支、共享 Boundary 和双视图不同步五类故意植入问题 |

## F. SD2.0

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| F1 | 时长 | 每个独立 Shot 满足 `0 < duration <= 15s`；场景总时长不受此限制 |
| F2 | 人脸 | 每镜最多两张需要清晰识别的脸 |
| F3 | 动作 | 每镜一个核心动作；复杂事件合理拆镜 |
| F4 | 描述 | 最终可执行提示词全文使用正向、可见、可拍摄语言，无占位符、否定指令、备选/条件分支、心理标签或文学比喻 |
| F5 | 文字 | 不依赖即梦生成可读画内文字 |
| F6 | 身份优先 | 身份、多人物和高速复杂动作冲突时主动降复杂度 |
| F7 | 动作时间轴 | 动作镜使用必要的 1 秒或 0.5 秒变化节点，并覆盖准备、发展、峰值和结果 |
| F8 | 非动作时间轴 | 对话和静态镜头按事件变化写时间节点，不重复相同画面填满时间网格 |
| F9 | 模式选择 | 每镜明确选择纯提示词、首尾帧或全能参考；选择理由符合主要控制目标 |
| F10 | 参考职责 | 全能参考中的每份图片、视频或音频都有明确职责和冲突优先级 |
| F11 | 首尾帧 | 首帧、尾帧分别对应 Master 的开场和结束状态 |
| F12 | 转场责任 | 明确由 SD2.0 镜内完成还是由后期剪辑完成，不要求模型生成本应后期完成的硬切或叠化 |
| F13 | 能力真源 | 生成模式和素材限制来自版本化能力配置；配置变化会使相关缓存失效 |
| F14 | 文字资产卡 | 模型不读媒体二进制；引用素材必须有与当前媒体哈希一致的 verified 文字卡，变化后自动 stale |

## G. 持续学习

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| G1 | 真实证据 | 无实际渲染或用户观察不能创建有效经验 |
| G2 | 分级 | candidate、repeated、validated、rejected状态不可跳级 |
| G3 | 晋升 | validated经验至少跨两个不同场景验证 |
| G4 | 人工确认 | 核心知识更新必须人工批准 |
| G5 | 回归 | 每次正式知识更新后固定回归集全部通过 |

## H. Claude Code 用户体验

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| H1 | 单命令 | `/mode-p-pilot script.md` 默认完成全剧本 |
| H2 | 零人工传递 | 用户不运行脚本、不创建Context、不转发DP反馈 |
| H3 | 可恢复 | 中断后从最后通过场景继续 |
| H4 | 清晰交付 | 最终明确报告各场景两份交付路径 |
| H5 | 无旧入口 | 活动路径不可调用 legacy Agent 或 Seko 流程 |
| H6 | 完整状态机 | `/mode-p-pilot` 自动执行 L0-L6，而不是在 DP READY 后跳过同步、边界或全片检查 |
| H7 | 恢复一致性 | 恢复时校验 Master 版本和检查状态，不把半写入视图标记为已通过 |
| H8 | 提交安全 | session锁、staging和Commit Manifest防止并发写入及半成品交付 |
| H9 | 全片闭环 | Episode Review 修订后必须重新回看，不能直接进入交付 |
| H10 | 独立分集 | `/mode-p-pilot` 不要求项目名或完整剧本；当前分集与背景冲突时当前分集优先 |
| H11 | 无资产运行 | 无图片、无资产卡时不阻断、不调用视觉模型，并明确使用 text_only |

## I. 回归场景集

必须至少包含：

1. 双人静态对话。
2. 权力关系反转对话。
3. 室内调查与证据揭示。
4. 单人沉思与环境叙事。
5. 动作或追逐。
6. 三人以上群像场面。
7. 多空间连续转场。
8. 无历史 Pattern 可匹配的新场景。
9. 含服装、道具或伤势状态变化的跨场景剧本。
10. 故意违反 SD2.0 时长、人脸和动作复杂度的压力案例。
11. 需要上一镜尾部视频维持动作方向的全能参考案例。
12. 必须精确控制开场与结束构图的首尾帧案例。
13. 图片、视频和音频参考互相冲突的参考过载案例。
14. 动作切、视线切、声音桥、遮挡切和多空间转场的边界案例。

## J. 性能目标

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| J1 | 本地冷启动 | BOOTSTRAP 不调用大模型；在固定回归机器上本地预加载目标不超过 10 秒 |
| J2 | 热恢复 | 剧本和实现版本未变化时，目标 3 秒内恢复状态且不重新生成已通过内容 |
| J3 | 模型调用预算 | 3-5 场无修订先导篇为一次持续 Director + 一次全新 DP；本地检查不调用 LLM |
| J4 | 持久 Director | 整个分集的所有批次、修订和 Episode Review 绑定同一 Director Agent ID 与实际模型 |
| J5 | 批处理 | 只因可计算的输入/输出安全预算拆批，不调用复杂度路由 Agent |
| J6 | 最小失效 | 修改单个 Shot 或参考素材时，只重算该 Shot、相关视图、相邻边界和对应审查状态 |
| J7 | 缓存正确性 | 缓存键包含内容与实现版本；指令、检查器或知识变化不会错误复用旧结果 |
| J8 | 注意力控制 | 每批只加载核心、Director 选择的 0-3 胶囊和 0-3 validated 经验，不加载完整知识库或旧报告 |
| J9 | 参考素材预算 | 全能参考只加载完成本镜意图所需的最小素材集合，不以平台最大输入数量为目标 |
| J10 | 无额外设计角色 | 固定镜头、简单对话、无 Pattern 命中和参考选择都不增加领域设计 Agent |
| J11 | 可观测性 | 记录模型调用次数、输入/输出量、本地耗时、缓存命中和失效范围 |
| J12 | 模型分配 | Director/DP 模型选择有固定回归和耗时证据，不以降低审查能力换取表面速度 |
| J13 | 资产卡预算 | Director 候选卡默认不超过6000字符、硬上限10000；DP实际卡证据每轮不超过2000字符 |

外部模型排队和推理速度不可由本地测试稳定约束。性能验收同时记录 LLM 调用次数、输入/输出量和本地耗时；不能只用一次墙钟时间判断。

## K. 最终完成判定

只有 A-H 全部通过、I 回归集执行完成、J 性能目标无明显回退，项目才可标记完成。文档完成、单一样本通过或 Agent 能生成长提示词，都不能作为项目完成依据。
