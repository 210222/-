# MODE:P 知识架构冻结备忘

> 状态：讨论结论已保存，暂缓实施  
> 记录日期：2026-07-18  
> 生效边界：本文件不是实施任务，不得由 Claude Code Loop 自动展开

## 1. 最终目标

MODE:P 应成为以戏剧意图为起点的导演系统，能够把知识库中的导演知识转化为统一的机位、人物调度、运镜、构图、光影、表演、声音和画面切换设计，并输出同源的故事板与即梦 SD2.0 视频提示词。

知识系统的目标不是让模型每次读取更多文本，而是让完整知识可追溯、相关知识可按需调用、单次导演上下文保持精简。

## 2. 已确认事实

1. 原始 GLM-OCR 项目没有丢失，主要保存在外部 D 盘资料目录。
2. 外部资料包含原始 PDF、GLM-OCR、补充 OCR、页面图像、Knowledge Cards 和已有提取结果。
3. “原始项目保存完整”不等于“每页 OCR 文字覆盖完整”；部分书籍仍有零 token、超时或识别错误页。
4. 不应将外部资料整体复制进 MODE:P，也不应在每次运行时加载全部书籍。
5. 后续实现不得在版本库中硬编码具体盘符或用户名，应通过本机忽略配置登记外部知识根目录。

## 3. 暂定知识架构

采用分层知识编译，而不是“全书直接加载”或“只保留摘要胶囊”。

```text
原始资料库
    ↓
导演决策模式库
    ↓
Director Core + 专题知识胶囊
    ↓
当前场景知识简报
    ↓
MODE:P Director
```

### 3.1 原始资料库

保存 PDF、OCR、补充文本、页面图像、Knowledge Cards 和既有知识库。该层可持续增长，但不进入常规 MODE:P 运行上下文。

### 3.2 导演决策模式库

知识不保存为简单规则或书籍摘要，而应表达为：导演问题、判断信号、可选方案、方案权衡、跨领域联动、不适用条件和来源依据。

这一层服务于知识维护、去重、冲突分析和验证，不要求 Director 在最终创作时输出规则编号或来源引用。

### 3.3 Director Core

只保存跨场景稳定成立的导演思维，例如先判断戏剧意图、技法服从信息变化、人物调度与摄影机联动、光源物理锚定、剪辑点由注意力或意义变化驱动。Core 不保存大量案例。

### 3.4 专题知识胶囊

胶囊继续保留，但定位改为“专题导演认知”，而不是书籍摘要或强制规则。候选专题包括对话关系、多人调度、主观视点、环境建立、动作连续性、焦段与空间、摄影机运动、动机光、色彩结构、视觉转场、声画剪辑和故事板关键帧。

### 3.5 当前场景知识简报

Director 根据剧本和精简胶囊目录选择相关专题，再由本地运行时加载对应内容并形成短小的场景知识上下文。知识只提供观察角度和权衡，不直接生成镜头答案。

## 4. 两类知识必须分离

```text
director_craft/
    专业导演、摄影、构图、光影和剪辑知识

sd2_execution/
    即梦 SD2.0 的提示词执行边界和模式差异

validated_cases/
    经真实生成和人工确认的经验
```

专业书籍回答“为什么这样设计”；SD2.0 经验回答“怎样表达更容易执行”。真实生成观察不能未经验证直接改写导演原理。

## 5. 运行时原则

1. 不新增独立的运行时 Knowledge Curator Agent。
2. Director 读取剧本和精简胶囊目录后，自主选择 0-3 个相关专题。
3. 本地程序只负责路径、数量、哈希、读取和上下文预算，不根据关键词替 Director 决定机位、焦段、运镜、构图、光影或切换。
4. 同一个 Director 会话完成知识选择和场景设计，避免新的创意 Agent 介入。
5. DeepSeek V4 Pro 的长上下文容量不能被视为可无限使用的有效注意力。

## 6. 暂定运行时间目标

- 本地知识加载：小于 2 秒。
- 知识选择额外模型交互：最多 1 次。
- 普通场景知识增量：目标约 30 秒至 2 分钟。
- 复杂场景知识增量：目标约 1 至 3 分钟。
- 整个分集知识增量：目标低于总运行时间的 10%。
- 知识系统不得引起额外的格式修订轮次。

知识目录建设、OCR 覆盖审计、知识提炼、迁移测试和人工批准属于离线工作，不计入每次 MODE:P 创作运行。

## 7. 恢复实施后再决定的事项

1. 原始资料目录和可移植外部根目录配置格式。
2. OCR 覆盖率与质量分级规则。
3. 导演决策模式的最终数据结构。
4. Core、胶囊和场景简报的实际上下文预算。
5. 知识覆盖矩阵和缺失专题优先级。
6. 迁移测试、反例测试和人工批准门槛。
7. 真实即梦经验的候选、重复、验证、拒绝和晋升流程。

## 8. 冻结边界

在用户明确要求恢复知识系统实施前：

- 不修改 `03_知识库/`。
- 不重新生成或扩充运行时 Core/Capsules。
- 不批量处理 PDF、OCR 或 Knowledge Cards。
- 不修改 Director/DP 的知识加载合同。
- 不将本备忘加入 `IMPLEMENTATION_PLAN` 的执行清单。
- 不让 Claude Code Loop 自动执行本文件中的后续事项。

后续 MODE:P 其他工作可以继续，但必须保持当前知识运行行为不变。
