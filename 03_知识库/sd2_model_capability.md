## §1 官方确认的6类失败模式 (arXiv 2604.14148)

> **信任层级:** 🔴 官方自认·不可忽视

| ID | 失败模式 | 官方描述 | P-FAL映射 | MODE:P规避策略 |
|------|---------|---------|:---:|---------|
| SD-FAL-01 | 极端运动形变伪影 | "Minor deformation artifacts in extreme motion" | P-FAL-09 | 动作降速·拆分复杂动作·Fix Ladder Rung3 |
| SD-FAL-02 | 多人说话口型误差 | "Lip-sync errors in multi-speaker scenarios" | P-FAL-10 | 多人对话拆为交替单人口型特写 |

## §2 社区验证的系统性退化模式 (3票对抗验证确认)

> **来源:** 社区实测数据 (WaveSpeed / PromeAI / seedance.tv)
> **信任层级:** 🟡 社区验证·非官方但高度一致

### 2.1 运动优先于身份 (Motion-over-Identity)

```
🔴 核心机制:
  当同时需要保持面部保真度和生动运动时，sd2.0系统性优先运动。
  身份从"具体特征"缓慢漂移为"类型特征"。
  不是bug——是模型注意力分配的内在优先级。

规避策略:
  1. Character Anchor逐字复制 (每个prompt前置固定身份文本)
  2. 2-3秒身份测试片段→确认稳定→锁定seed→扩展完整镜头
  3. 参考强度建议70% (平衡特征还原与动作自然度)
  4. 用正向约束锁定身份: "Face proportions locked to reference across all frames"
```

### 2.2 提示词泄漏 (Prompt Leakage)

```
🔴 核心机制:
  场景描述(光影/氛围/环境)会非预期改写角色。
  "暖夕阳光照" → 夹克变色
  "风吹头发" → 发型长度改变
  扩散模型中语义泄漏的已知现象。

规避策略:
  1. Character Block放在prompt最前面 (模型注意力权重最高位置)
  2. 场景描述放在Character Block之后
  3. 风格词精简 (一个具体锚点优于六个模糊形容词)
  4. 全片Style Spine + Palette Anchors固定
```

## §3 模型核心能力边界 (硬上限)

| 约束项 | 边界值 | 根因 | 来源 |
|--------|--------|------|------|
| 单段时长 | ≤15秒 (建议)·可到30秒但身份漂移加剧 | 模型时序注意力窗口衰减 | 官方论文+社区验证 |
| 时间精度 | ≈1秒·不描述亚秒事件 | 模型时间粒度不可微分到0.5秒 | P-FAL-03 |
| 空间精度 | ≈cm级·不描述mm级间距 | 潜空间缺乏mm级几何约束 | P-FAL-02 |
| 同时音效 | ≤2层 | Audio branch独立通道上限 | P-FAL-04 |
| VO语速 | ≤4字/秒 | TTS对齐窗口语速天花板 | P-FAL-05 |
| 单镜动作 | ≤1核心动作 | 多动作压缩帧→机器人式运动 | S4.2a |
| 多人面部 | ≥3人不可控 | 面部特征预算耗尽→融合/混淆 | SD-FAL-05 |
| 复合运镜 | 双运镜需精确参数·三运镜建议降级 | 稳定性随复杂度递减 | S3.2 |
| 瞳孔控制 | 不可控·随机化 | 训练数据中瞳孔变化与情绪标签弱关联 | P-FAL-01 |
| 画面文字 | 必乱码 | 文字渲染能力未优化 | P-FAL-07 |

## §4 模型解析特性 (影响prompt写法)

### 4.1 非线性的三层解析优先级

```
sd2.0对prompt的解析不是线性读取:

第一层·动作提取 (最高优先级):
  模型优先抓动词和运动轨迹
  → 动作词放prompt前段·模型优先执行

第二层·场景锚点 (次优先级):
  空间关系和物体位置
  → 场景词放prompt中段·模型据此建立空间参考

第三层·风格修饰 (最低优先级):
  光影/色调/画质修饰词
  → 风格词放prompt末段·避免稀释动作和场景的执行精度
```

### 4.2 正向指令解析

```
sd2.0将所有token当作正向指令:
  "不要抖动" → 模型看到"抖动" → 反而生成抖动
  "避免模糊" → 模型看到"模糊" → 反而模糊

→ 【生成指令】正文必须零负向词
→ 【禁止】块不进入Seko渲染 (仅供人类审核参考)
```

### 4.3 @引用用途声明

```
每个@引用的素材必须在【生成指令】中声明具体用途。
不能说"参考图1"这种模糊词——模型不知道参考什么。

四种标准@声明格式:

  场景线稿/九宫格 → "@图片N 作为首帧"
    锁定构图结构、空间纵深、物体相对位置。放在@声明区第一位。

  角色参考图 → "@图片N 作为主角，保持外貌服装一致"
    锁定面部特征、发型、服装。一旦使用→Subject字段不可再写外貌。

  场景色调参考 → "@图片N 参考场景色调和氛围"
    锁定色彩基调、光影氛围。使用后Style字段不能出现矛盾色调词。

  道具三视图 → "@图片N 作为道具[道具名]参照"
    锁定关键道具外观材质。道具名必须与剧本逐字一致。

排列顺序: 首帧 → 主角 → 色调 → 道具 (模型解析优先级递减)
多@组合: @图片(角色) + @图片(场景) + @视频(运镜参考) + @音频(配乐)
"保持图X的XX"句式: "保持图一的人物形象，换成图二的角度"

✅ "@图片1 作为首帧"
✅ "@图片2 作为主角，保持外貌服装一致"
❌ "@图片1"                           ← 无用途声明
❌ "参考图1的色调"                     ← 非@语法·模型不识别

最多: 9张图片 + 3段视频 + 3段音频
参考强度: 建议70% (平衡特征还原与动作自然度)
⚠️ 真人面部参考上传自2026年2月起已暂停
```
