# S1 铁律 (官方确证·不可违反)

> **信任层级:** 火山引擎官方文档明确记载
> **违反后果:** 渲染输出出现不可预知的漂移/崩坏/抖动

## S1.1 正向描述原则 — 无负面提示词架构

```
🔴 铁律 S1.1:
  Seedance 2.0 将 prompt 中所有文本都当作正向指令解析。
  "不要抖动" → 模型看到"抖动" → 反而生成抖动
  "避免模糊" → 模型看到"模糊" → 反而模糊

✅ 正确写法 (正向约束):
  原负面意图           →  正向化改写
  ───────────────────────────────────────────
  "不要抖动"           →  "画面稳定无晃动"
  "不要变形"           →  "面部稳定不变形、五官清晰"
  "不要多余手指"        →  "人体比例正常、五指结构完整"
  "没有字幕"           →  "无字幕画面"
  "没有Logo"           →  "无Logo画面"
  "眼睛不要眨"          →  "眼睛保持睁开、固定不眨"
  "光线不变"           →  "光线一致无闪烁"

❌ 错误写法 (保留负向词):
  "不要模糊" "避免穿帮" "不要生成水印" "禁止抖动"
```

## S1.2 八要素工程公式 (空间层 + 时间层)

```
🔴 铁律 S1.2:
  Seedance 2.0 模型内部分解为:
    空间层 (Spatial Layer): 处理画面内容——主体·场景·光影·风格
    时间层 (Temporal Layer): 处理变化——动作序列·镜头运动·事件顺序

  八要素公式:
    精准主体 → 动作细节 → 场景环境 → 光影色调 → 镜头运镜 → 视觉风格 → 画质 → 约束条件

  提示词应当清晰地分别向空间层和时间层投喂信息:
    · 前半段(主体→场景→光影→风格→画质) = 空间层投喂
    · 后半段(动作→运镜→约束) = 时间层投喂
```

## S1.3 具体视觉引用优于模糊情绪词

```
🔴 铁律 S1.3:
  Seedance 2.0 不理解抽象情绪概念。必须将情绪外化为身体细节。

✅ 情绪外化映射:
  抽象意图          →  具体视觉锚点
  ──────────────────────────────────────────────
  "悲伤的情绪"       →  "肩膀颤抖、眼眶泛红、嘴角下撇"
  "愤怒"            →  "下颌紧咬、太阳穴血管凸起、拳头握紧指节发白"
  "紧张"            →  "喉结滚动、瞳孔微缩、额头细密汗珠"
  "开心"            →  "眼睛弯成月牙、嘴角上扬露出8颗牙齿"
  "恐惧"            →  "瞳孔放大、嘴唇发白、手指无意识颤抖"

  风格/光影也需具体锚点:
  ❌ "电影感"        →  ✅ "shot on Arri Alexa 35, Kodak Vision3 500T film stock"
  ❌ "暖色调"        →  ✅ "3200K tungsten warm amber cast, practical lamp as key"
  ❌ "柔光"          →  ✅ "diffused window light, soft shadows with no hard edges"
  ❌ "赛博朋克"       →  ✅ "cyan-magenta neon palette, wet asphalt reflections, volumetric fog"
```

## S1.4 每一份上传素材必须在 prompt 中有明确用途声明

```
🔴 铁律 S1.4:
  每个 @图片N 或 @视频N 的引用素材必须被 prompt 明确声明其用途。
  未声明的素材 → 模型随机猜测用途 → 输出失控。

✅ 正确:
  "@图片1 中的人物外观作为主角参考，@图片2 的场景作为背景风格参考"

❌ 错误:
  上传了3张图片但 prompt 中没有提到任何一张。
```

### S1.4a @声明行是必须的 — 参考图类型与 @语法映射

**关键区分：照片参考 vs 线稿参考。** 照片参考 → 模型连色彩/纹理/光影一起抄。线稿参考 → 模型只应抄结构，不能抄黑白手绘风格。

**@声明行是必须的。** 只要有参考图，就必须写 @声明行（满足 S1.4 铁律）。「专用声明块」只针对手绘/线稿/俯视图——需要额外告诉模型不要抄手绘风格、不要渲染成示意图。

```
参考图类型              → @语法                          → 是否需要专用声明块
─────────────────────────────────────────────────────────────────────────────
场景俯视运动图           → "@图片N 作为场景俯视空间参考"      ✅ 必须加俯视图专用声明
场景线稿/手绘分镜         → "@图片N 作为分镜构图参考"         ✅ 必须加线稿专用声明
角色手绘设计稿            → "@图片N 作为主角外观参考"          ✅ 必须加线稿专用声明
场景照片参考             → "@图片N 作为首帧"                — 仅@行即可
角色照片参考             → "@图片N 作为主角，保持外貌服装一致"  — 仅@行即可
场景色调/氛围参考         → "@图片N 参考场景色调和氛围"        — 仅@行即可
道具三视图               → "@图片N 作为道具[道具名]参照"      — 仅@行即可

⚠️ "@行即可" ≠ "不需要引用"——@声明行始终必须写，只是照片类参考图不需要额外插入专用声明块
```

### S1.4b 线稿专用声明（有手绘参考图时必加）

当 @声明区 包含任何手绘/线稿/草图类参考图时，**必须在 @声明区之后、Subject 之前插入以下声明**：

```
使用线稿仅作为空间结构、人物位置和构图的参考。
生成照片级真实视频画面。不要渲染色黑白手绘风格。
不要保留线稿的笔触、轮廓线或草图质感。

线稿箭头标注说明:
  红色箭头 = 身体运动方向和路径 (人物怎么动)
  蓝色箭头 = 相机运动方向和路径 (摄影机怎么动)
  绿色标记 = 构图/构图笔记 (三分法·引导线)
  橙色标记 = 光线方向 (主光·轮廓光位置)
  黑色文本 = 镜头标签 (景别·焦距·运镜类型)
```

### S1.4c 俯视图专用声明（有俯视运动图时必加）

当 @声明区 包含俯视运动图时，**必须在 @声明区之后、Subject 之前插入以下声明**：

```
使用俯视图理解场景空间布局和摄影机运动路径。
生成照片级真实视频画面。不要渲染俯视示意图风格。
不要将俯视图的标注线和图标渲染到最终画面中。

图例说明:
  🎬+编号 = 摄影机位置和镜头序号
  实线箭头 = 摄影机运动方向和路径
  🪑+名字 = 人物站立/坐位置
  虚线箭头 = 人物运动方向和路径
  矩形框 = 墙面/家具/门窗
```

# S2 最佳实践 (社区验证·强烈建议)

> **信任层级:** 未在火山引擎官方文档中找到确切对应条文，但被 wavespeed / uisdc / api yi / 掘金 / V2EX / GitHub 等多个社区多次独立验证有效。

## S2.1 五段式骨架

```
🟡 最佳实践 S2.1:
  Subject → Action → Camera → Style → Constraints

  并非官方强制格式，但社区验证该顺序可有效降低画面漂移:
    · Subject 放在最前面 → 模型优先锚定"谁"
    · Action 紧随其后 → 模型锁定的主体直接进入动作
    · Camera 后置 → 模型先确定画面内容再执行运镜指令
    · Style 靠后 → 调味剂·不争夺模型注意力
    · Constraints 最后 → 护栏·防止前面元素跑偏

  社区验证的五段式示例:
    "A woman in a red dress, shoulder-length black hair. 
     Slowly turns her head to look over her left shoulder, 
     eyes wide with recognition. 
     Medium close-up, fixed camera, 85mm lens, shallow DOF f/2.8.
     Soft window light, Kodak Portra 400 color palette, minimal grain.
     Face stable, no distortion, consistent facial proportions across all frames."
```

## S2.2 角色一致性的分层锚定法

```
🟡 最佳实践 S2.2:
  四层锚定确保跨镜角色一致性:

  第1层 · 参考图卫生:
    · 最多3张静态图: 正面 + 四分之三侧面 + 侧面
    · 同光线·同表情·纯色背景
    · 避免拼贴图、混合光线、纯高清大头照
    · 中分辨率混入一张反而有助形状保持

  第2层 · Prompt 分层:
    · Character Anchor: 逐镜逐字复制的角色描述(不可改一字)
      例: "Hong Kong woman, early 30s, shoulder-length black hair, 
           tailored charcoal-gray blazer with white blouse"
    · Scene Anchor: 逐镜逐字复制的场景描述(同场景时)
    · Camera & Framing: 每镜可变(景别·角度·运镜)
    · Action Beat: 每镜一个具体动作

  第3层 · 锚定词逐字复制:
    · 不同措辞 → 模型理解为不同人物 → 面部/服装漂移
    · 锁定: 年龄范围 + 1-2个硬特征(如"左耳小银环")
    · 强硬约束句: "Keep facial proportions identical to reference across all frames"

  第4层 · 负面约束改为正向:
    · 用描述性否定而非负向词:
      "Face stable across all frames, consistent identity, 
       no identity drift during head turns"
```

## S2.3 修复阶梯 (Fix Ladder)

```
🟡 最佳实践 S2.3:
  当渲染结果持续出现问题时，按以下阶梯逐级排查(一次只爬一级):

  Rung 1: 换参考图
    · 只换一张(侧面或四分之三侧)·保留其余
    · 归一化表情为中性

  Rung 2: 收紧约束
    · 每次只加一条限制·逐步叠加
    · 用正向描述替代负向词

  Rung 3: 缩短动作窗口
    · 裁切到 1.5-2 秒·去掉多余节拍
    · 先让脸部稳住·再逐步加回一个动作

  Rung 4: 降低视觉熵
    · 简化背景·降低风格锚点对比度
    · 略微去饱和肤色·阻止冷暖色调漂移

  Rung 5: 退守轮廓
    · 如果独特下颌线无法稳定
    · 依靠发型形状+耳饰+服装版型维持远距离身份识别

  社区验证效果: 经过8次测试，该阶梯减少约1/3重试次数。
```

## S2.4 五维架构法 (uisdc)

```
🟡 最佳实践 S2.4:
  从 uisdc.com 社区验证的五维控制维度:

  技术基底 → 镜头运动 → 视觉元素 → 光影系统 → 情绪编码

  1. 技术基底: 导演名/胶片类型/摄影机型号·具体锚点
  2. 镜头运动: 景别(wide/mid/CU/ECU) + 运镜类型(仅一种)
  3. 视觉元素: 主体+场景+色彩·占prompt最大篇幅
  4. 光影系统: 主光来源+方向+色温+阴影质量
  5. 情绪编码: 动作细节替代情绪词·用身体传递情感
```

## S2.5 常见避坑清单 (多源交叉验证)

```
🟡 最佳实践 S2.5:
  ❌ 禁用古诗词/成语          → AI不理解文学意象·翻译为白话物理动作
  ❌ 一个镜头只写一种运镜       → 不能"先平移再推进"
  ❌ 不让AI生成画面内文字       → 必乱码·需后期添加
  ❌ "电影感"等抽象词无效       → 改用具体导演名或灯光方案
  ❌ 图生视频时别用文字重复图片  → 造成模型输入冲突·只描述新增动作
  ❌ 快速=抖动                 → 用物理感描述替代"快速"一词
  ✅ 越短越准                 → 前2-3句权重最高·后段指令被稀释
  ✅ Voice/对白用{}包裹        → {你好，世界} (小语种需标注语种)
  ✅ 音效用<>包裹              → <远处传来狗叫声>
  ✅ 音乐用()包裹              → (背景中播放着快节奏的摇滚乐)
```

## S2.6 Style Spine 与 Palette Anchors (故事板专用)

```
🟡 最佳实践 S2.6:
  多镜场景的全片级锁定:

  Style Spine: 15-25字的风格锚短语·逐镜重复
    例: "shot on Arri Alexa 35, Kodak Vision3 500T, 
         desaturated teal-orange grade, film grain subtle"

  Palette Anchors: 3-5个颜色锚点词贯穿全片
    例: "amber, cream, walnut brown, slate, olive"

  逐镜只需写差异部分(Camera & Framing + Action Beat)
  Character Anchor 和 Scene Anchor 全片统一·逐镜逐字复制
```

# S3 被否决的社区声称

> **信任层级:** 社区广泛流传但在火山引擎官方文档中找不到对应条文。
> **处理方式:** 不纳入质量标准。但可作为非强制参考。

## S3.1 字数区间 (30-100词)

```
⚪ 社区声称:
  "提示词控制在 50-200 词之间""30-100 词最佳""超过100词废片率翻倍"

  否决理由:
    火山引擎官方文档没有规定字数区间。
    "字数"本身是歧义度量——中文50字 vs 英文200词承载的信息量完全不同。
    实际约束来自模型的注意力窗口分布和指令稀释效应，而非一个魔术数字。

  MODE:P 策略:
    不设硬性字数上限，用信息密度和质量做约束:
      · 每个元素必须有渲染锚点(否则删除)
      · 不重复已有信息(避免注意力稀释)
      · 前段(主体+场景)权重最高 → 信息密度倾斜前段
```

## S3.2 "一镜一运镜"硬约束

```
⚪ 社区声称:
  "一个镜头只指定一种运镜方式·绝对不能复合运镜"

  否决理由:
    火山引擎官方文档说的是"一个镜头只指定1种运镜"，但同时在进阶公式中
    也提到可以"推近+下降"复合。模型支持复合运镜，只是稳定性随复杂度下降。
    这不是硬性禁令，而是稳定性建议。

  MODE:P 策略:
    已有: prompt_composer v1.0 §4.5 明确定义了复合运镜参数格式
      "极慢下降+缓慢推近。摄影机从约40m高度——0.2x匀速下降8秒降至约8m。
       同时推近——0.1x。"
    复合运镜允许但需精确参数(速度/方向/起止)。
    稳定性层级: 单运镜 > 双运镜同时 > 三运镜 > 运镜+跟焦+变焦
```

## S3.3 "镜头1/镜头2/镜头3"分镜标签格式

```
⚪ 社区声称:
  "分镜必须用'镜头1/镜头2/镜头3'格式组织"

  否决理由:
    火山引擎官方文档建议按事件发生顺序组织分镜，但没有规定必须用
    "镜头1/镜头2/镜头3"格式。这只是一个组织建议，不是格式要求。

  MODE:P 策略:
    已有: prompt_composer 使用 [A-B]秒 时间标注格式，不依赖
    "镜头1/镜头2/镜头3"标签。MODE:P 已有独立的分段逻辑
    (切=新段·每段≤15秒)，不需要额外的镜头编号语法。
```

## S3.4 各模块字数占比

```
⚪ 社区声称:
  "主体占30%·动作占20%·场景占15%" 等精确占比建议

  否决理由:
    火山引擎官方文档没有规定各模块字数占比。
    不同场景类型需要的信息密度不同: 对话场景需要更多场景锚定，
    动作场景需要更多动作细节。机械占比=削足适履。

  MODE:P 策略:
    不使用字数占比约束。使用信息质量约束:
      · 主体: 2-3个稳定静态特征·不浪费词在可有可无的描述上
      · 动作: 1个核心动词+精确程度量化
      · 场景: 时间+地点+天气+光源方向+关键背景元素
      · 其余元素按实际需要分配
```

# S4 分层具体写法规则

## S4.1 主体层 — 怎么写

```
🔴 信任层级: 官方确证 + 社区验证

规则 S4.1a: 2-3个稳定静态特征锁定主体
✅ "穿红色连衣裙、黑色短发、戴圆框眼镜的亚洲女性"
  → 三个不变特征形成唯一锚点

❌ "一个漂亮女人"
  → 模型理解的"漂亮"分布极广 → 每次生成可能是不同面孔

规则 S4.1b: 不同镜头中同一角色的描述必须逐字复制
  措辞不同 → 模型理解为两个不同人物 → 身份漂移

✅ 全片统一:
  "Asian woman, early 30s, shoulder-length black hair, 
   navy blazer over white blouse, silver ring on left index finger"

❌ 分镜1: "穿藏蓝色西装的女性" → 分镜3: "穿深蓝色外套的女主角"
  → "藏蓝"≠"深蓝"·"西装"≠"外套" → 服装颜色可能漂移

规则 S4.1c: 优先使用参考图的视觉要素
  不要用文字重新描述照片中已有的细节:
✅ "@图片1 的人物外观作为主角" (若参考图已包含所有外貌信息)
❌ "@图片1 的人物，黑色长发、大眼睛、高鼻梁、瓜子脸、皮肤白皙..."
  → 文字重复图片已有信息 → 模型输入冲突

规则 S4.1d: 人物数量建议 ≤ 4人
✅ 2-3个角色 + 无名的背景人物("background crowd")
❌ 5+个需要独立面部特征的角色 → 模型面部预算耗尽 → 崩脸
```

## S4.2 动作层 — 怎么写

```
🔴 信任层级: 官方确证 + 社区验证

规则 S4.2a: 一拍一动词
✅ "放下筷子。拿起杯子。转向门口。"
❌ "吃完饭站起来走到门口"
  → 三个动作塞进一句话 → 模型串行处理 → 急促/机器人式

规则 S4.2b: 优先低缓连续小动作
✅ "缓慢抬起右手，指尖轻轻触碰玻璃杯边缘"
  → 单动作+缓速+具体身体部位+程度量化

❌ "快速挥舞手臂"
  → "快速"=不可渲染·产生抖动

规则 S4.2c: 动作精确量化
✅ "转身约90度，面朝摄影机左侧"
✅ "走下三级台阶，每一步脚掌完全着地"

❌ "转身" "走向前"
  → 模型不知道转多少度/走多远 → 随机

规则 S4.2d: 情绪外化为身体动作
✅ "肩膀在每次呼吸间颤抖，眼眶逐渐泛红"
❌ "她感到非常悲伤"

规则 S4.2e: 用节拍标注替代时间模糊词
✅ "Beat 1 (0-2s): 放下筷子"
✅ "第3-5秒: 头部缓慢从左侧转向镜头"
❌ "缓缓走下去" "渐渐抬头" "正在走"
  → 模糊时间词 = 模型不可执行

规则 S4.2f: 🆕 解剖级精度 — 面部微表情 (社区高级·2026验证)
  格式: [部位] + [动作方向/角度] + [速度/力度]

  面部肌肉解剖级描述 (FACS动作编码体系):
    嘴角: "嘴角上扬15度" / "嘴角向左下牵动0.3cm" / "单侧嘴角上扬10度"
    眼轮匝肌: "眼轮匝肌轻微收缩" / "眼角出现放射状鱼尾纹"
    眉间肌: "眉头内侧下压并聚拢" / "眉心舒展"
    下眼睑: "下眼睑微颤" / "下眼睑内侧聚满泪水"
    鼻翼: "鼻翼节律性翕动" / "鼻翼轻微扩张"
    下颌: "下颌线绷紧" / "下颌轻微颤抖"
    颧大肌: "颧骨明显隆起"
    口轮匝肌: "嘴唇轻闭呈直线" / "下唇咬紧"

  真笑vs假笑解剖区别:
    真笑: 嘴角上扬(15°) + 眼轮匝肌轻微收缩 + 眼角鱼尾纹 + 下眼睑略隆起
    假笑: 嘴角上扬(15°) + 眼周肌肉不动 → 皮笑肉不笑

  强度分级:
    低幅→"微"(微蹙眉、微抿唇)
    中幅→"略"(略扬嘴角、稍抬眼睑)
    高幅→"明显""强烈""骤然"

规则 S4.2g: 🆕 环境物理精确量化 (风/光影/流体)
  风:
    方向: "风从西南方向吹来" / "左侧逆风，发丝向右飘动"
    速度: "3m/s" / "轻风(0.5-1.5m/s)" / "强风(5-8m/s)"
    时间绑定: "0-2秒无风静止，2-4秒微风渐起至3m/s，4-6秒增强至5m/s"
    物理效果: "风速3m/s，发丝轻微摆动" / "风速8m/s，衣摆剧烈翻飞"
  
  光影联动:
    "左侧柔光照射，风从西南方45°吹来，发丝在光照下产生动态阴影"
    "风经过时，衣料褶皱随气流方向变化，光影在褶皱上流动"

规则 S4.2h: 🆕 秒级时间轴分解 (所有精确描述通用)
  格式: "[N-M秒]: [部位]+[动作]+[程度]。"
  原则: 情绪是连续曲线·不是孤立节点·按秒拆解
  
  示例:
    0-2秒: 眼眶微红，睫毛轻颤。无风，发丝静止
    2-4秒: 嘴角下拉0.2cm，眉头内侧轻微上抬。微风从左侧2m/s吹来
    4-6秒: 第一滴泪从右侧脸颊滑落。风速渐强至4m/s
    6-8秒: 眼神空洞望向虚空。风减弱至1m/s，发丝缓缓落回
    8-10秒: 含泪微笑（嘴角仅上扬8度，眼轮匝肌不动）。风停止，画面静止
```

```
规则 S4.3a: 五要素锁定场景
  地点 + 时间 + 天气 + 光源方向 + 关键背景元素

✅ "傍晚的老城石板路，雨后积水反光，两侧红砖建筑墙面潮湿，

❌ "一个街道"
```

## S4.4 光影层 — 怎么写

```
🔴 信任层级: 官方确证

规则 S4.4a: 所有光源必须有物理锚点
✅ "暖黄色路灯从画面左侧照射，在湿石板路面形成长条反光带"
  → 光源=路灯·锚点=灯柱

✅ "窗外透过百叶窗的下午阳光，在墙面投下条纹阴影"
  → 光源=太阳·锚点=窗户

❌ "一束神秘的光从上方照下来"
  → 光源是什么？在哪？模型随机生成不可控的虚假光源

规则 S4.4b: 用色温数值而非模糊形容词
✅ "3200K tungsten warm amber cast"
✅ "5600K daylight, cool blue shadows"
❌ "暖光" "冷光"

规则 S4.4c: 固定灯光+色温·逐帧重复
  光照条件是跨帧最容易漂移的元素之一:
✅ 每个关键帧中重复: "single key light from window left, 5600K, 
   soft shadows on wall"
```

## S4.5 运镜层 — 怎么写

```
🔴🟡 信任层级: 官方确证(术语) + 社区验证(实践)

规则 S4.5a: 用标准术语 + 精确参数
✅ "极慢推近——0.03x——3秒推约15cm——右手和手枪进入画面下方"
✅ "slow dolly-in, 50mm lens, shallow DOF f/2.8, 
   focus rack from background to subject's eyes"

❌ "镜头慢慢靠近"
  → "慢慢"=不可执行的时间模糊词

规则 S4.5b: 景别用标准术语
✅ wide / mid / medium close-up / close-up / extreme close-up
✅ 全景 / 中景 / 近景 / 特写 / 大特写

❌ "稍微近一点" "拍到一部分身体"

规则 S4.5c: 复合运镜需精确参数(稳定性降级)
  单运镜 > 双运镜同时 > 三运镜
  每增加一种运镜 → 稳定性降一级 → 需要更精确的参数补偿

✅ 双运镜精确写法:
  "极慢下降(0.2x·8秒·40m→8m) + 缓慢推近(0.1x)"
  → 两个方向的速度/起止状态都精确量化

❌ 双运镜模糊写法:
  "从高处慢慢降下同时推近"
  → 两个模糊词叠加 → 几乎必然抖动

规则 S4.5d: 镜头运动与主体运动分开写
✅ "The dancer spins slowly. Camera holds fixed framing."
❌ "spinning camera around a dancing person"
  → 谁在转？镜头在转还是人在转？模型困惑 → 抖动
```

## S4.6 风格层 — 怎么写

```
🟡 信任层级: 社区验证

规则 S4.6a: 一个视觉锚点优于六个形容词
✅ "shot on Kodak Portra 400, subtle film grain"
  → 一个导演名/胶片类型 = 整套视觉参数的速记

❌ "电影感、复古、暖调、柔光、胶片质感、文艺风"
  → 不同形容词指向不同方向 → 模型困惑

规则 S4.6b: 使用导演名/影片名作为视觉速记
✅ "lighting inspired by Roger Deakins, Blade Runner 2049"
✅ "color palette reminiscent of Wong Kar-wai, In the Mood for Love"

❌ "王家卫风格"
  → 太泛·模型可能只理解"慢镜头"而忽略"色调"

规则 S4.6c: Style Spine 15-25字·逐镜重复
  MODE:P 映射: 每个分镜的画面描述不需要重复风格描述。
  风格描述放在分镜组级别的统一声明中(Style Spine)。
```

## S4.7 约束层 — 怎么写

```
🔴🟡 信任层级: 官方确证(约束词重要) + 社区验证(正向改写)

规则 S4.7a: 所有负向意图改写为正向量化约束
✅ "画面稳定无晃动、面部比例全程保持一致、光线色温全程一致"
❌ "不要抖动、不要变形、光线不要变化"

规则 S4.7b: 精选3-5条约束·不宜过多
  过多约束项 → 模型注意力稀释 → 每条都半执行 → 整体失控
✅ 3-5条关键约束
❌ 15条"不要XX"

规则 S4.7c: 约束的优先级排序
  1. 面部稳定性   >  "面部比例全程保持一致、五官不漂移"
  2. 物理合理性   >  "人体结构正常、重力效果自然"
  3. 画面清洁度   >  "无字幕、无Logo、无水印"
  4. 运动稳定性   >  "画面稳定、动作流畅自然无卡顿"
  5. 光线连续性   >  "光线色温全程一致无闪烁"

规则 S4.7d: 约束项必须可逐条检查
  每条约束写完后问自己: "如果渲染结果回来了，我能逐条打勾吗？"
✅ "面部五官清晰·比例自然" → 能打勾
❌ "注意质量" → 不能打勾
```

## S4.8 分镜时序层 — 怎么写

```
🔴🟡 信任层级: 官方确证(按事件顺序组织) + 社区验证

规则 S4.8a: 按事件发生顺序组织分镜
  官方建议: "使用镜头1/镜头2/镜头3按事件发生顺序组织"
  MODE:P 映射: 使用 [A-B]秒 时间标注格式·已完成顺序组织

规则 S4.8b: 关键帧标注
  每个段至少1个关键帧·变化密集段每2-3秒一个关键帧
✅ "第3秒——画面中央地面出现一个人形暗色轮廓"
✅ "下降第5秒——人形越来越清晰"

规则 S4.8c: 静止时间
  每段末尾必须留有静止时间(≥0.5秒)
  静止=让观众吸收画面·也减少模型在段末的漂移
```

## S5.6 失败模式速查

```
写法                          →  渲染失败表现
────────────────────────────────────────────────────────
"缓缓地"                      →  动作速度随机·可能过快或静止
"渐渐地"                      →  变化过程无控制·可能跳跃
"刚/正在/刚刚"                →  模型渲染成已完成态·动作不在画面上
复合运镜无参数("推近+旋转")    →  画面抖动·两个方向竞争
情绪词当动作("他很悲伤")       →  无可见动作·静态面孔
"一束光从上方"                →  凭空出现光源·物理不合理
"不要XX"                      →  模型看到"XX"→ 触发XX
多个动作词塞一句话             →  机器人式急促运动
"电影感""高质量"              →  无效词·模型忽略或随机理解
古诗词/成语                   →  完全无法理解·可能生成文字
省略场景描述                  →  场景漂移·背景随机
跨镜角色描述不一致             →  角色变形·服装颜色漂移
"镜头1/镜头2"无动作区别        →  每个镜头的画面几乎相同
```

```
  §2 铁律#3 已排除时间模糊词·要求精确参数

冲突:
  社区声称"一镜一运镜"=禁止所有复合运镜。
  但官方文档只说不建议，不是禁止。MODE:P已有精确参数补偿。

风险: 低
  MODE:P做了社区没做的事——给复合运镜精确参数。
  精确参数(速度/方向/起止/时长)可以补偿复合的不稳定性。

建议: 保持现有做法。增加一个"运镜复杂度稳定性评级":
  L1(最稳): 固定机位 / 缓慢单一方向
  L2(较稳): 缓慢推近 / 缓慢拉远 / 缓慢横移 → 单一运镜有参数
  L3(注意): 推近+下降 / 推近+跟焦 → 双运镜精确参数
  L4(高风险): 三运镜 / 运镜+变焦+跟焦 → 需要降级到L3
```
