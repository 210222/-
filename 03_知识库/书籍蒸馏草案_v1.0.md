# 书籍蒸馏草案 v1.0 — 导演书籍 → 可执行 Agent 知识

> **版本**: v1.0 草案 · 2026-08-05
> **目标**: 把导演书籍蒸馏为项目 Agent 可直接调用的知识,让 Director/DP 拥有"导演思维"——
> 根据整个剧本设计画面张力、运镜、调度观众情绪的能力
> **依据**: GitHub 开源蒸馏范式归纳(cangjie-skill RIA-TV++ / book-to-skill / lineage-skill /
> Distill-Novel)+ 导演 Agent 项目演绎(Spilbergian / DirectorSKILL / visual-skills / OpenMontage / FilMaster)
> **与现有引擎的关系**: 现有 `distillation_engine_v1.0.md` 负责"从项目运行失败中学习";
> 本文档负责"从书籍中蒸馏",两者输出汇入同一处:胶囊 / KB 规则文件

---

## 一、核心结论

1. **"把书蒸馏进 Agent"和"让 Agent 拥有导演思维"是两件事。** 蒸馏管线产出的是知识层(规则、
   术语、案例);导演思维是逻辑层——一条显式编码的推理链:**全剧情绪弧 → 场景张力 → 镜头选择**。
   缺逻辑层的蒸馏 = 得到搜索引擎,不是会思考的导演。
2. **胶囊是现成的容器。** `01_调度器/mode_p/knowledge/capsules/` 的形态与 RIA 技能几乎同构
   (可执行规则 + 触发条件 + 边界),书籍蒸馏结果直接落胶囊 + `knowledge_index.json` 注册。
3. **书不能整本进上下文,也不能整本进 agent 定义。** MODE:P 是 minimal-context 运行时,
   蒸馏必须走"编译一次、按需加载"路线。

## 二、方法论:RIA-TV++ 全套(归纳自 GitHub 范式)

| 阶段 | 做法 | 产出 |
|---|---|---|
| 0 整书理解 | Adler 四问(结构/诠释/批判/应用),先读目录+序言+全书速览 | `BOOK_OVERVIEW.md` 蓝图 |
| 1 并行提取 | 按章拆书,每章一个独立子 Agent,五路提取:框架/原则/案例/反例/术语 | 候选知识池 |
| 1.5 三重验证 | (V1) 跨域证据:书中 ≥2 处独立佐证 (V2) 预测力:能答书未明说的问题 (V3) 非平庸:不是常识。通过率 25–50%,落选进 `rejected/` | 验证通过的候选 |
| 2 RIA 构造 | 每条=**R** 原文引用(≤150字)→ **I** 自己的解释 → **A1** 书内应用 → **A2** 未来触发场景(→ 胶囊元数据)→ **E** 可执行 1-2-3 步骤 → **B** 边界(何时不用/作者盲点) | 原子技能单元 |
| 3 链接 | Zettelkasten:单元间依赖/对比/组合关系 → `INDEX.md` 知识地图 | 索引与关系图 |
| 4 压力测试 | 每单元 5–10 条测试提示,含**诱饵题**(不该触发时不许触发)与边界题;失败回炉阶段 2 | 测试通过清单 |
| 5 安装 | 写入胶囊目录 + 注册索引 + 更新统计;人工确认闸门 | 可用的胶囊 |

关键纪律:
- **证据可溯**:每条规则带 source_id(章节/页码),拒绝跨书串味(借鉴 distill-novels 的 source_id 设计)。
- **先验证再构造**:V1/V2/V3 不过的候选不进 RIA 阶段。
- **诱饵测试是硬门槛**:Agent 必须在不该调用时也不调用,防止规则误触发。

## 三、演绎:导演思维的四级推理链(逻辑层编码)

**大前提**: 思维 = 固定决策序列 + 判断标准,可显式编码。
**小前提**: 导演的决策序列是"剧本 → 情绪 → 镜头"(先决定观众感受,再选视听手段)。
**结论**: 按从大到小、情绪先行,编码四级链:

### ① 剧本级 — 调度观众情绪(全剧张力曲线)
- 9-beat 叙事弧:ordinary_world → inciting_incident → reluctant_hero → threshold_crossing →
  rising_action → midpoint_reversal → dark_night_of_soul → climactic_showdown → resolution
- 每个 beat 显式赋情绪基调(如 calm_yearning / mysterious_awe / transcendent_wonder)
- 输出: 全剧情绪弧表(beat × 情绪基调 × 张力目标 × 信息释放)

### ② 场景级 — 画面张力
- 每个 beat 必须定义:action + **emotional turn**(情绪转折)+ visual revelation + camera intention
- 规则:"每一拍都要提高 stakes、揭示新信息或反转权力"
- Murch Rule of Six 权重:情绪 51%、故事 23%、节奏 10%(其余 16%)——情绪永远优先

### ③ 镜级 — 运镜(情绪 → 构图/运动的映射表)
- 映射表示例:Heroic Reveal → 低角度/宽画幅 + 升降 + 轮廓光;Tense → 荷兰角 + 手持晃动 +
  低调硬阴影;Intimacy → 大特写;Isolation → 全景
- 运动三分法:平移(dolly/truck)≠ 旋转(pan/tilt)≠ 纯镜头(zoom/focus),强制消歧
- 判断标准(每镜必答):"这一镜让观众感觉到什么?"——答不出就重做

### ④ 验证环 — 思维闭环
- 独立 scorer 按维度打分(情绪弧 / 张力 / 连续性 / 视觉可行性),阈值通过制,不通过重试

## 四、落地到本项目(MODE:P)

### 4.1 知识层 → 胶囊
- 蒸馏产物按 `capsules/*.md` 格式写入(参照 suspense_reveal.md 密度:数百字、动作性指令)
- 注册 `knowledge_index.json`,映射检索元数据:scene_types / drama_intents / space_conditions /
  character_count_range / motion_complexity / sd2_risk_tags + content_sha256 / byte_size
- 每集 Director 按场景最多选 3 个胶囊 → 新胶囊必须与现有 9 个正交,元数据必须精确
- 边界:不进 `core/`(4 个 core 是 always_load,只有全局法则才配常驻)

### 4.2 逻辑层 → 导演思维推理链
- 在 `director_core.md`(或导演逻辑)补三级链:"全剧情绪弧 → 每场景张力目标 → 镜头选择",
  让每个镜头能回答"这镜让观众感觉到什么"
- DP 已有 scorer 职责,对照四维评审(可参考 oh-my-opencinema 6 维评分)

### 4.3 与现有蒸馏引擎的关系
- `distillation_engine_v1.0.md`(运行失败→规则)与本文档(书籍→规则)输出汇合,
  按场景类型归入 KB 规则文件,人工确认闸门沿用

## 六、范围与风险

- **不是模型训练**:本项目是提示词/检索层注入;参数级训练(prompt distillation)是另一条路线,成本
  约 2.5–4M token/本 640 页书,本草案不涉及。
- **版权边界**:书籍正文不进公开仓库;蒸馏产物是规则化改写(引文 ≤150 字),不在 git 中存放
  整本抓取数据。
- **上下文预算**:每胶囊数百字、按需加载,单集成本可忽略;全书不常驻。
