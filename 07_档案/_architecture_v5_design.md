# 导演系统 v5.0 架构设计 — 基于前沿调研

**设计日期**: 2026-06-28
**调研基础**: 107个Agent深度调研·3.2M tokens·6篇核心论文
**核心洞察**: 多Agent不如单Agent（NeurIPS 2025）、Agent辩论适得其反（CAIS 2026）、层级技能树优于向量搜索（ICLR 2026）

---

## 一、架构原则（调研提炼）

| # | 原则 | 调研来源 | 对导演系统的含义 |
|---|------|------|------|
| 1 | **少Agent优于多Agent** | NeurIPS 2025: 多Agent性能退化39-70% | 维持3 Agent，不再增加 |
| 2 | **独立验证优于自我审查** | Fable 5实验: 6x差距; CAIS 2026: 辩论无效 | Verifier在自己的上下文中运行 |
| 3 | **功能分离优于Agent辩论** | MAVEN 2026: Skeptic-Researcher-Judge | Verifier用三角色内部结构 |
| 4 | **层级导航优于向量搜索** | Corpus2Skill ICLR 2026: ls/cat树 | KB Index改为可导航层级树 |
| 5 | **优先级淘汰优于全部载入** | CWL 2026: 确定性LLM-free淘汰 | 规则按场景路由，不是全部载入 |
| 6 | **蒸馏是研究空白** | 调研未发现相关研究 | 我们自己设计五段记忆+蒸馏 |

### vs 旧架构的关键变化

| 变化 | 旧 v4.0 | 新 v5.0 | 调研依据 |
|------|------|------|------|
| KB路由 | 平铺索引(kb_index.md) | 层级技能树 | Corpus2Skill ICLR 2026 |
| 合并方式 | 交叉辩论+冲突升级 | 直接合并+冲突标记 | CAIS 2026: 辩论无效 |
| Verifier | 同一Agent立场切换 | 独立上下文+三角色 | Fable 5 + MAVEN 2026 |
| 知识更新 | feedback衰减 | 五段记忆+蒸馏 | 研究空白·自研 |
| 规则载入 | 全部载入上下文 | 按场景类型路由 | CWL 2026 淘汰策略 |

## 三、核心子系统设计

### 3.1 KB Router v2.0 — 层级技能树

```
导演知识库/
├── 1.对话场景/
│   ├── 1.1 双人对话/
│   │   ├── 基础机位 (三角形原理·外反拍·内反拍·平行位)
│   │   ├── 九种变体 (面对面·并排·一前一后·镜子·电话)
│   │   └── 运镜规则 (推近·分享镜头·不同高度·互瞥)
│   ├── 1.2 三人对话/
│   └── 1.3 多人对话/
├── 2.动作场景/
│   ├── 2.1 打斗 (长焦特效·重拳·倒地·分别拍摄·近地仰拍)
│   ├── 2.2 追逐 (紧跟·长焦摇拍·狭窄空间·制造惊恐)
│   └── 2.3 悬疑 (后退·未知之惧·紧张期待·危险逼近)
├── 3.空间与轴线/
│   ├── 3.1 180度线 (关系线·三角形原理·视线匹配)
│   └── 3.2 空间可行性 (障碍物·演员走位路径)
├── 4.构图与美学/
│   ├── 4.1 机位 (共同视轴·高低角度·距离选择)
│   ├── 4.2 构图 (三分之二法·留白·剪影前景·对角换位)
│   └── 4.3 光影色彩 (冷暖对比·光源方向·色温·饱和度)
├── 5.剪辑与节奏/
│   ├── 5.1 平行剪辑 (动作反应·高峰瞬间·单镜头vs主镜头)
│   └── 5.2 匹配 (位置·动作·视线·注意中心)
└── 6.故事板与设计/
    ├── 6.1 镜头表示法 (景框中景框·箭头法·立方体法)
    └── 6.2 导演思维 (戏剧流动·影像化·省略原则)

路由逻辑:
  输入: 剧本段落
  1. 检测场景类型 → 锁定一级目录
  2. 检测角色数量+动作类型 → 锁定二级目录  
  3. 加载该路径下规则 (约30-50条, 而非全部1400条)
  4. P0规则(安全)始终加载, 不参与路由
```

### 3.2 规则优先级编码

```
优先级铁律 (注入dispatcher开头·不可违反):
  
P0 — 安全物理法则 (180度线·轴线·空间可行性·物理连续性)
     > 来源: Arijon Ch.4 + Katz Ch.6
     > 🛑阻断级, 不可降级, 不参与上下文淘汰
     > 同级冲突: Arijon > Katz > 导演经验

P1 — 空间连续性 (位置匹配·动作匹配·视线匹配)  
     > 来源: Arijon Ch.3 + Katz Ch.4
     > ⚠️警告级, 用户可覆盖但需标注
     > 同级冲突: Arijon > Katz

P2 — 美学质量 (构图·光影·色彩·运镜动机)
     > 来源: Kenworthy + Katz + Gurney + Framed Ink
     > 💡建议级, 不阻断
     > 同级冲突: 导演基线优先 > 系统建议

P3 — 风格选择 (速度·节奏·情绪·表演)
     > 来源: 导演基线表 + Invisible Cut + 眨眼之间
     > ℹ️ 标记但不强制执行
     > 冲突: 用户意图始终覆盖

跨级裁决: 高优先级覆盖低优先级
同级裁决: 来源权威性 > 规则具体性 > 用户偏好
```

### 3.3 Verifier v2.0 — MAVEN架构

```
Verifier Agent (独立上下文·不能读enhance推理过程)

内部三角色:
  ┌─────────────────────────────────────────┐
  │  Skeptic (质疑者)                        │
  │  默认立场: "这个增强方案有遗漏"            │
  │  任务: 找出enhance未覆盖的KB规则          │
  │  输出: 遗漏清单                           │
  ├─────────────────────────────────────────┤
  │  Researcher (研究者)                     │
  │  默认立场: "检查每个修改是否违反KB规则"     │
  │  任务: 逐镜比照所有P0+P1规则               │
  │  输出: 违规清单                           │
  ├─────────────────────────────────────────┤
  │  Judge (裁决者)                          │
  │  综合Skeptic遗漏 + Researcher违规         │
  │  输出: 🛑阻断/⚠️警告/✅通过               │
  │  规则: ≥1 P0遗漏或违规 → 🛑              │
  │        ≥2 P1遗漏或违规 → ⚠️              │
  │        仅P2-P3问题 → ✅ + 标记             │
  └─────────────────────────────────────────┘

隔离保证:
  - Verifier看不到enhance的推理过程
  - Verifier只能看到原始剧本 + 增强剧本 + KB规则
  - 防止"合理化确认偏差"
```

### 3.4 知识蒸馏层 — 研究空白自研

```
STATE.md 五段记忆 (借鉴Fable 5 + 导演系统场记库):

Section 1: Verified Facts (已验证的事实)
  - 每次管道成功运行后提取的"这次学到了什么"
  - 格式: [发现] + [证据] + [来源]

Section 2: General Rules (通用规则)  
  - 已蒸馏为KB规则的长期知识
  - 格式: [规则ID] + [规则] + [来源]

Section 3: Open Failures (未解决的失败)
  - 2轮返工上限后仍存在的问题
  - 格式: [问题] + [尝试方案] + [为什么失败]

Section 4: Lessons Learned (教训)
  - 从失败中提取的可避免错误
  - 格式: [错误模式] + [触发条件] + [避免方法]

Section 5: Last Session (上次会话摘要)
  - 跨会话状态继承
  - 格式: [上一集] + [关键决策] + [待回收线索]

蒸馏管线:
  MODE:A postcheck → 提取发现 → STATE.md更新
  MODE:F 用户反馈 → FSRS衰减 → 规则权重重调
  MODE:R 离线体检 → 系统弱点 → 规则补充
  每10次运行 → Distill → 候选规则 → 人工确认 → KB追加
```
