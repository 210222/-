# MODE:P 架构设计 v2.0 — 基于 Fable 5 双循环架构

> **设计日期:** 2026-07-01
> **设计依据:** Claude Fable 5 架构深度分析 + Security Boulevard "Why Fable 5 Still Needs a Second Loop" + AC/DC 确定性验证框架
> **核心洞察:** Fable 5 系统卡自认 "self-oversight is real but defeatable" → MODE:P 必须从单循环升级为真正的双循环

---

## 一、Fable 5 核心架构原则（MODE:P 映射）

### 1.1 双循环架构（The Dual Loop）

```
Fable 5 架构                          MODE:P 映射
──────────────────────────────────────────────────────────
内循环 (概率性·共享权重):              prompt_composer Steps 4-8 自检
  · 模型自我生成→自我测试→自我反思       · 同Agent检查自己的输出
  · 系统卡: "real but defeatable"      · 共享权重·共享盲区·共享激励
  · 结果随运行变化(mean@5)              · 可能漏检与生成相同类型的错误

外循环 (确定性·独立验证):              P-Verifier (需升级为双门)
  · 独立于生成权重的验证层               · 独立上下文·不读prompt_composer推理
  · AC/DC: GUIDE→GENERATE→VERIFY→SOLVE · 需区分确定性门 vs 概率性验证
  · 验证者必须"无利害关系"               · P-Verifier对台本质量无既得利益
```

### 1.2 确定性门 vs 概率性验证（AC/DC 框架核心）

Fable 5 AC/DC 框架的关键区分——这是当前 MODE:P 架构最缺失的部分:

```
┌─────────────────────────────────────────────────────────────┐
│  确定性门 (Deterministic Gate)                               │
│  · 基于规则·不依赖模型判断·每次运行结果相同                       │
│  · 可追溯到具体规则ID·可在代码层面实现                          │
│  · 适用: 数值约束/格式检查/关键词扫描/模式匹配                   │
│                                                             │
│  MODE:P 示例:                                                │
│    □ 每段时长 ≤ 15秒? → 时间戳减法·不需要模型"判断"              │
│    □ 有无"缓缓/渐渐/慢慢"? → 关键词扫描·不需要模型"感觉"          │
│    □ @图片引用是否有效? → 模式匹配·不需要模型"推断"              │
│    □ 进程动词("正在/刚")? → 正则扫描·零模型判断                  │
├─────────────────────────────────────────────────────────────┤
│  概率性验证 (Probabilistic Verification)                     │
│  · 依赖模型判断·结果随运行变化·需要独立权重                       │
│  · 可被" grader awareness"影响·需要独立上下文                    │
│  · 适用: 空间一致性/光源溯源/人物占位/道具状态                    │
│                                                             │
│  MODE:P 示例:                                                │
│    □ 光源是否有物理锚点? → 需要模型"理解"场景                    │
│    □ 人物位置是否与空间地图一致? → 需要模型"比对"多个信息源         │
│    □ 道具状态是否跨镜连续? → 需要模型"追踪"状态链                 │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 子Agent编排（Sub-Agent Orchestration）

Fable 5 的子Agent模式（主Agent分解→并行子Agent→仅返回结论）对 MODE:P 的启示:

```
当前 MODE:P:                       Fable 5 模式:
  单Agent串行处理所有场景             主调度器→每场景独立子Agent→汇总
  ↓                                  ↓
  上下文随场景数线性增长               子Agent共享前缀缓存(CONSTITUTION/Seko规则/空间地图)
  场景5+时上下文接近警戒线             KV cache复用·传输开销降低~20x
  无法并行处理                        所有场景可同时生成台本
```

### 1.4 跨会话记忆（Cross-Session Memory）

Fable 5 STATE.md 五段记忆机制对 MODE:P 的意义:

```
当前 MODE:P: 无独立跨会话记忆
  → 每次运行从零开始
  → 同样的Seko渲染失败可能重复出现
  → prompt_composer无法从历史错误中学习

应增加 P-STATE.md:
  §1 Verified Rendering Patterns (已验证可渲染模式)
  §2 Known Seko Failure Modes (已知失败模式)
  §3 Open Rendering Issues (未解决的渲染问题)
  §4 Seko Capability Changes (平台能力变更)
  §5 Last Session Summary (上次会话摘要)
```

### 2.1 完整管道（AC/DC 双循环）

        │ Scene 1  │   │ Scene 2  │   │ Scene N  │  ← 并行子Agent

             │               │               │

### 2.2 P-Verifier 双门结构（核心升级）

```
P-Verifier v2.0
  │
  ├─ GATE 0: 确定性规则门 (Deterministic Rule Gate)
  │   └─ 执行时机: P-Verifier启动后·PASS 1之前
  │   └─ 执行方式: 规则引擎·零模型判断·每次运行完全相同
  │   └─ 失败处理: 立即🛑·不需要进入概率性验证
  │
  │   规则门检查项:
  │   ┌──────────────────────────────────────────────────────┐
  │   │ R01 时长硬约束:   任一段 > 15.0秒 → 🛑               │
  │   │ R02 时间模糊词:   含"缓缓/渐渐/慢慢/逐渐/徐徐/冉冉" → 🛑 │
  │   │ R03 进程动词首帧: 段首句含"正在/刚/已/开始/持续" → 🛑   │
  │   │ R04 跨镜引用:     含"同上/参考上镜/如前所述" → 🛑      │
  │   │ R05 参考图引用:   @图片引用格式异常或引用不存在 → 🛑    │
  │   │ R06 禁止清单格式: 禁止项含模糊词("稳/好/自然/舒服") → 🛑│
  │   │ R07 段结构完整:   缺【镜头参数卡】/【生成指令】/【禁止】→ 🛑│
  │   │ R08 KB引用门禁:   叙事关键镜的【设计依据】KB未覆盖 → ⚠️  │
  │   └──────────────────────────────────────────────────────┘
  │
  ├─ PASS 1: Skeptic — 六条铁律概率性扫描 (不变·模型判断)
  │   立场: "这个台本有不可渲染的元素"
  │   验证: 铁律2(画面外描述)·铁律3(空间追溯)·铁律4(光源锚点)
  │         铁律7(空间自洽)·铁律8(结构一致)
  │
  ├─ PASS 2: Researcher — 六维深度验证 (不变·模型判断)
  │   2A跨镜时间·2B人物占位·2C道具状态·2D禁止一致性·2E转场连接·2F全片统一
  │
  └─ PASS 3: Judge — 综合裁决 (合并确定性门+概率性验证)
      输入: Gate 0规则违规 + Skeptic铁律违规 + Researcher深度违规
      裁决矩阵:
        ≥1项 Gate 0 🛑 → 🛑 阻断(规则违规·无协商空间)
        ≥1项 铁律 🛑    → 🛑 阻断
        ≥1项 时间-内容🛑 → 🛑 阻断
        ≥1项 空间占位🛑 → 🛑 阻断
        ≥3项 ⚠️         → 🛑 阻断
        1-2项 ⚠️        → ⚠️ 标注通过
        仅P2建议         → ✅ 通过
```

### 2.3 子Agent并行模式（场景≥3时启用）

```
场景数判定:
  ≤2场景 → 单Agent串行(当前模式·上下文充裕)
  ≥3场景 → 子Agent并行模式

并行模式执行:
  ┌─ Main Conductor (dispatcher)
  │   1. 读取所有场景参考图 + 空间地图 (共享前缀)
  │   2. 按场景拆分剧本段落
  │   3. 为每个场景启动独立 composer Agent
  │   4. 传递共享前缀: CONSTITUTION + Seko规则 + kb_index路由
  │   5. 等待所有子Agent返回台本片段
  │   6. 执行 Step 9 全片统一性汇总 (跨场景检查)
  │   7. 组装完整台本 → 交付 P-Verifier
  │
  ├─ Scene Agent 1 (独立上下文)
  │   加载: prompt_composer + 场景1空间地图 + 场景1参考图 + 场景1剧本
  │   执行: Steps 1-8 → 输出该场景台本片段
  │
  ├─ Scene Agent 2 (独立上下文)
  │   ...
  │
  └─ Scene Agent N (独立上下文)
      ...

前缀缓存优化:
  所有子Agent共享: CONSTITUTION.md + shared_agent_runtime.md §7 + kb_index_v2.0.md P0规则
  每个子Agent独有: 场景空间地图 + 场景参考图 + 场景剧本段落
  
  预期效果: 上下文消耗从 O(全场景×全规则) → O(单场景×路由规则) + O(共享前缀)
           多场景下节省50-70%上下文
```

### 2.4 P-STATE.md 跨会话记忆（MODE:P 专属）

```
P-STATE.md 四段记忆 (精简版·专为MODE:P设计):

§1: Verified Rendering Patterns (已验证可渲染模式)
  格式: [模式ID] + [描述] + [验证次数] + [最近验证日期]
  示例:
    P-REN-01: "硬闪白转场(0.3s·硬切音频)在Seko上渲染稳定" · ✅×12 · 2026-06-28
    P-REN-02: "面部大特写+浅景深(85mm等效·f/2.8)可渲染" · ✅×8 · 2026-06-30
    P-REN-03: "雨滴打在表面·中低频持续环境声" · ✅×5 · 2026-06-29

§2: Known Seko Failure Modes (已知失败模式)
  格式: [失败ID] + [触发条件] + [失败表现] + [规避方案]
  示例:
    P-FAL-01: "瞳孔收缩/扩张描述 → Seko忽略·随机化" · 规避: 固定瞳孔状态描述
    P-FAL-02: "5mm级唇间距 → Seko无法精确到mm" · 规避: 用"微张"替代精确数字
    P-FAL-03: "0.5秒间隔水滴 → 时间精度不足" · 规避: 描述为"雨水持续滴落"

§3: Open Rendering Issues (未解决的渲染问题)
  格式: [问题ID] + [描述] + [尝试方案] + [状态]
  示例:
    P-OPN-01: "VO语速与画面时长的精确匹配" · 尝试: 标注字数/秒 · 状态: 待Seko验证

§4: Session Log (最近会话日志)
  格式: [日期] + [剧本] + [场景数] + [P-Verifier裁决] + [关键发现]
  自动轮转·保留最近10次会话
```

### 3.3 优先级体系

```
MODE:P v2.0 优先级 (Fable 5 六层映射):

  P0 确定性规则 (Gate 0)        ← Fable 5: 外循环确定性门
     > 铁律阻断 (PASS 1 🛑)      ← Fable 5: 安全层
     > 物理不可能 (PASS 2 🛑)    ← Fable 5: 边界层
     > 空间/道具 ⚠️              ← Fable 5: 能力层
     > 美学/风格 💡              ← Fable 5: 工具层
     > 全片统一性建议            ← Fable 5: 运行时层

  跨级裁决: 确定性门违规 → 立即阻断·不进入概率性验证
           铁律违规 → 阻断·不可降级
           物理不可能 → 阻断·不可降级
```
