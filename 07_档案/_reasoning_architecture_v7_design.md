# 导演系统 v7.0 推理架构设计

> **设计日期:** 2026-07-07
> **设计动机:** 当前推理模式 = "LLM 翻字典"。每次 Agent 调用从头读 866 条规则→理解→应用→输出。
>   这不是算法。这是让一个聪明人每次干活前重读一遍百科全书。
> **设计目标:** 规则不是让 LLM "读"和"理解"的。规则是系统的硬约束——LLM 在约束空间内做创意工作，约束的检查由系统完成。

---

## 二、每层详细设计

### Layer 0: 硬约束引擎

**现状:** gate0_scan.py (508行·已测试通过·R01-R15全部实现)
**待建:** spatial_check.py (空间碰撞检测·180度线验证)

**工作原理:**
```
LLM调用前:
  检查输入完整性: 参考图是否存在? 空间地图是否覆盖所有拍摄区域?
  → 阻断项>0 → 不启动Agent → 返回补全

LLM调用后:
  检查输出合规性: 段长>15s? 过程动词? 负向词? KB规则ID泄漏?
  → 阻断项>0 → 自动迭代修复(§-5.1)
```

**spatial_check.py 设计:**
```
输入: 每镜机位坐标 + 空间地图(墙面/障碍物/可放置区域)
检查:
  1. 摄影机位置是否在可放置区域内
  2. 运镜路径是否与墙面/障碍物相交(碰撞检测)
  3. 相邻镜是否在180度线同一侧
  4. 角色位置是否在可站立区域内
  5. 视线是否被障碍物遮挡
输出: P0违规清单(每条含: 规则ID·违规镜头·坐标证据·修复建议)
```

### Layer 1: 结构化约束

**现状:** Agent 输出格式改造中·必填字段已标注·但合法值域未定义
**待建:** constraint_definitions.json (所有P0+P1规则的结构化约束定义)

**约束定义格式:**
```json
{
  "shot_type": {
    "rule_ref": "D-TRI-04",
    "type": "enum",
    "valid_values": ["全景","中全景","中景","中近景","近景","特写","大特写"],
    "violation": "🛑阻断",
    "fix_hint": "景别必须使用标准术语"
  },
  "axis_side": {
    "rule_ref": "D-TRI-02",
    "type": "enum",
    "valid_values": ["左","右"],
    "cross_shot_check": "相邻镜axis_side必须一致·否则需有过波镜",
    "violation": "🛑阻断",
    "fix_hint": "调整机位到关系线同一侧·或插入过波镜"
  }
}
```

**Agent 看到的不是规则文本，是可选菜单:**
```
shot_type: 请从以下选择:
  [全景] [中全景] [中景] [中近景] [近景] [特写] [大特写]
  
axis_side: 本场景关系线在 [左] [右] 侧
  注意: 选定后全场景保持一致·切换需过波镜
```

### Layer 2: 历史模式库

**现状:** P-STATE.md 记录了失败模式·但审核通过的成功模式未系统化

**待建:** decision_patterns/ 目录·按场景类型+空间布局索引

**索引结构:**
```
decision_patterns/
├── 室内对话_单室_工作台前/
│   ├── EP15_Rico工作室/  (21镜·台本+故事板·审核通过)
│   └── pattern.json       (提取的通用模式)
├── 室内对话_单室_面对面/
│   ├── EP14_案情室/       (7镜·审核通过)
│   └── pattern.json
├── 室内调查_实验室/
│   ├── EP13_鉴证科/       (17镜·审核通过)
│   └── pattern.json
```

**pattern.json 内容:**
```json
{
  "scene_type": "室内对话_单室_工作台前",
  "reference_ep": "EP15",
  "verified_patterns": {
    "camera_setup": [
      {"position": "工作台正上方", "shot_type": "ECU", "focal_length": "100mm", "angle": "俯角60°"},
      {"position": "工作台前·中距", "shot_type": "中景", "focal_length": "35mm", "angle": "眼平"},
      {"position": "门口方向", "shot_type": "全景", "focal_length": "24mm", "angle": "眼平"}
    ],
    "lighting": {
      "key_light": "吊灯·2800K·暖黄",
      "secondary": "门缝冷白·4000K",
      "style": "chiaroscuro·大面积暗部"
    },
    "movement": {
      "static_ratio": "86%",
      "only_movement": "极慢推近0.05x·仅1镜"
    }
  }
}
```

**Agent 的工作流:**
1. 收到新场景 → 提取空间类型+角色数量+对话模式
2. 检索 decision_patterns/ → 找到最相似的历史场景
3. 提取已验证的机位/运镜/光影模式
4. 适配到当前场景（角色不同·空间类似·机位可复用）
5. 只输出差异部分（角色锚点不同·道具不同·对白不同）

### Layer 3: LLM 创意判断

**Agent 收到的输入（大幅精简）:**
```
[Layer 0 检查结果]: 输入完整·无阻断·✅可启动
[Layer 1 约束]: 你必须从以下选项中选择机位/景别/焦距 (具体列表见下)
[Layer 2 历史模式]: 类似场景 EP15_Rico工作室 的成功方案 (机位/光影/运镜摘要)
[Layer 3 创作空间]: 以下是Layer 0-2没覆盖的·你需要判断:
  - 人物表情的细节描述
  - 道具与角色互动的节奏
  - 台本对白的音轨设计
  - 转场方式的选择
```

**Agent 不需要读的东西:**
- ❌ 866条KB全文
- ❌ P-CONSTITUTION全文
- ❌ canvas_runtime全文
- ❌ kb_index全文
- ❌ 其他Agent的推理过程

## 三、规则知识图谱

### 当前: 平铺表格

```
D-TRI-01 | 两个对话演员之间有一条关系线 | P0
D-TRI-02 | 保持关系线一侧·不跳轴 | P0
D-TRI-05 | 外反拍角度 | P0
D-DUO-01 | 面对面·基本对话构型 | P0
```

Agent 必须自己理解这些规则之间的关系。

### 设计: 规则网络

```
D-TRI-01(关系线) 
  ├─ 触发 → D-TRI-02(不跳轴)
  ├─ 触发 → D-TRI-05(外反拍) 
  │         └─ 关联 → D-DUO-01(面对面)
  ├─ 触发 → D-TRI-06(内反拍)
  └─ 触发 → D-DUO-13(跨线检查)

当: scene_type = "双人对话" + character_layout = "面对面"
→ 自动激活: D-TRI-01,02,05,06 + D-DUO-01,13
→ 编译为 Layer 1 约束: axis_side必须输出·shot_type必须从三角形机位选择
→ Agent 的"可选菜单"根据激活的规则动态生成
```

**好处:**
- 新增一条规则自动关联到已有网络（不需要重新"理解"整个KB）
- 违规时知道影响了哪些关联规则（D-TRI-02违规→D-TRI-05,06,D-DUO-01全部受影响）
- 规则冲突自动裁决（两个关联规则给出矛盾建议时→查冲突矩阵）

## 五、新旧对比

| 维度 | 旧架构 (v6.x) | 新架构 (v7.0) |
|------|-------------|-------------|
| 规则存在形式 | markdown表格·LLM"读"和"理解" | 结构化约束·系统强制执行 |
| P0检查 | LLM审计Agent (177K tokens) | Python脚本 (0 tokens·100%准确) |
| Agent输入 | 866条KB全文(~42K) + 5个公共文件(~32K) | Layer1约束菜单(~3K) + Layer2历史模式(~2K) + 剧本 |
| 经验积累 | P-STATE失败记录·被动规避 | decision_patterns/·主动继承成功方案 |
| Agent工作方式 | 每次从头设计 | 检索相似场景→继承验证方案→只改差异 |
| 规则更新 | 人手动写新规则·Agent重新"读" | 新规则编译为约束·自动关联到已有网络 |
| Prompt优化 | 人手写·人手改 | DSPy自动优化·贝叶斯搜索最优prompt |
| 场景适配 | 全部场景同一管道深度 | Layer0-2自适应·简单场景Agent只做微调 |

---

> **核心原则:**
> 1. 规则不该被"读"——规则应该被"编译"成系统能检查的约束
> 2. Agent不该"从头设计"——Agent应该"检索相似→继承方案→适配当前"
> 3. LLM不该做确定性检查——正则和数学能做的事不给LLM
> 4. 经验不该只记录失败——成功方案比失败模式更有价值
