# GOAL：导演知识库改造与导演决策能力构建

## 1. 顶层结论

将现有以书籍摘要、镜头术语和案例胶囊为主的知识库，改造成一个由 LLM 持续执行的
**导演决策系统**。系统必须先理解整集和场次的戏剧变化，再把变化演绎为调度、视点、
摄影、剪辑和生成约束；不得从台词、句子或关键词直接跳到镜头模板。

系统最终能力公式：

```text
导演能力
= 可执行知识
× 全剧状态建模
× 候选方案搜索
× 可审计评价
× 失败经验迭代
```

任一项为零，系统都会退化为安全覆盖、镜头词堆叠或形式模仿。

## 2. 导演金字塔

所有分析和执行必须遵循五层金字塔：

```text
L1 本集导演命题
   观众从本集开始到结束，应在认知、关系判断或情绪上发生什么变化？

L2 序列与场次功能
   每个场次如何推动本集导演命题？本场最多三个主要功能。

L3 戏剧节拍
   人物目标、权力、关系、信息或情绪在哪个事件后发生状态变化？

L4 调度与视听策略
   如何通过人物位置、运动、遮挡、视点、时间和声音表达该变化？

L5 镜头与生成执行
   景别、机位、焦段、构图、运动、切点、时长、首尾状态与参考职责。
```

下层决策必须支持上层结论。任何镜头无法沿以下链路追溯时，应视为冗余或无动机候选：

```text
镜头 → 节拍状态变化 → 场次功能 → 本集导演命题
```

## 3. 归纳与演绎

### 3.1 归纳：发现这场戏真正是什么

归纳用于完整剧本理解、人物模式、场次功能、情绪曲线、失败模式和经验提炼。

固定步骤：

```text
收集事实
→ 按剧情/人物/关系/信息/情绪/空间分类
→ 识别重复、对比和关键变化
→ 提出多个候选解释
→ 搜索反例和冲突事实
→ 选择解释力最强且最简的结论
```

重要结论至少需要两项相互独立的证据。单一证据只能形成低置信度假设。

### 3.2 演绎：从导演目标推出如何拍

演绎用于技能检索、调度、摄影、剪辑、连续性和失败修复。

固定步骤：

```text
已确认导演目标
+ 已验证导演规则
+ 当前剧本/空间/能力约束
→ 候选执行策略
→ 例外与冲突检查
→ 单一可执行决策
```

禁止先想到推镜、过肩、长镜头或特写，再倒推其戏剧理由。

## 4. 可审计推理，不输出无限思维链

系统只保存可验证的决策摘要：

```yaml
conclusion: 本节点结论
confidence: high | medium | low
supporting_reasons: 相互独立的理由
script_evidence: 带出处的剧本事实
alternatives: 其他可能解释
rejected_because: 拒绝理由
rules_used: 被调用的知识规则
exception_check: 规则是否存在失效条件
downstream_constraints: 对下一节点的明确约束
```

不要求保存自由联想、隐藏思维过程或冗长自述。可信度来自证据、反证和产物，不来自文字长度。

## 5. 不可违反的导演原则

1. **完整剧本先于局部镜头**：首次设计必须理解完整分集、人物弧线和场次关系。
2. **场次功能先于镜头语言**：无法说明场次存在理由时，不得进入摄影设计。
3. **状态变化先于切镜**：禁止只因说话人变化而切镜。
4. **调度先于摄影**：先决定人物怎样争取、躲避、接近、离开和占据空间，再决定摄影机。
5. **观众状态必须显式建模**：记录观众知道、误解、等待和感受到什么。
6. **镜头必须有不可替代职责**：若更简单镜头无损替代，应删除或合并。
7. **候选方案必须存在实质差异**：重要场次至少比较克制观察、主观情绪、关系调度三类策略。
8. **多样性不是目标**：不得为避免重复而随机变景别、焦段或运镜。
9. **逐秒设计只属于执行层**：它用于动作阶段和首尾状态，不用于发现场次功能。
10. **知识是可反驳建议，不是模板**：当前剧本事实、空间和能力证据优先。
11. **错误回退到最早层级**：无意义正反打应回退到场次/节拍/调度，不只改镜头词。
12. **生产系统保持稳定**：候选方案在隔离区验证，未经质量门不得修改 MODE:P 当前真源。

## 6. 知识资产目标

每条书籍知识必须转化为一种或多种资产：

- `Principle`：上位导演原则；
- `DecisionRule`：条件—判断—行动规则；
- `PlanningSkill`：剧集或场次规划技能；
- `FunctionalSkill`：可复用的导演过程；
- `AtomicSkill`：具体调度、摄影或剪辑操作；
- `FailurePattern`：症状、根因和检测条件；
- `RepairStrategy`：回退层级和修复步骤；
- `Case`：正确、错误、边界与冲突案例；
- `EvaluationRule`：质量评价规则；
- `ConflictRule`：多个原则冲突时的优先级。

知识不再按书名作为主要检索入口，而按导演问题组织：

```text
story_diagnosis
episode_strategy
scene_architecture
beat_analysis
audience_state
blocking
spatial_relationship
viewpoint
cinematography
editing
continuity
scene_patterns
failure_patterns
repair_strategies
evaluation
```

来源书名、章节和页码仍须保留，用于追溯和版权边界管理。

## 7. LLM 执行目标

LLM 必须能够：

1. 从 `project_state.json` 恢复任务，不重复从头规划；
2. 一次只执行一个最小可验证工作单元；
3. 先读仓库治理规则和当前有效真源；
4. 把所有生成结果写入隔离工作区；
5. 对每条候选技能执行去重、冲突、反例和场景测试；
6. 用固定 Schema 读写，不依赖聊天记录作为唯一状态；
7. 对完成声明附带文件、数量、测试结果和未解决问题；
8. 在证据不足时标记低置信度，而不是虚报；
9. 连续两轮无改进时回退上一级，不继续空转；
10. 每轮结束更新 `project_state.json` 并停止。

## 8. 最终成功标准

项目只有同时满足以下条件才算完成：

- Director 能先输出本集命题、场次功能和观众状态，再进入镜头；
- 重要镜头均具备完整追溯链；
- 正反打、过肩、逐句切镜和无动机运镜的默认率显著下降；
- 人物调度能表达权力、关系、信息和心理变化；
- Critic 能指出错误首次发生在哪个决策层；
- 同一场景能生成并比较真正不同的导演策略；
- 用户反馈能转化为结构化经验并被后续检索；
- 基准集可重复运行，且相较当前基线有量化提升；
- 新知识通过试点、测试和人工复核后再接入生产；
- 不破坏现有 MODE:P 的单一设计真源、Director/DP 边界与提交机制。
