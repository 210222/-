# EXECUTION PLAN：LLM 可持续执行路线

## 0. 总体策略

采用“Graph 管总流程、Loop 管局部校验”的方式。

```text
Phase Graph
资产盘点 → Schema → 试点蒸馏 → 最小决策链 → 基准集 → 批量迁移
→ 训练数据 → 模型训练准备 → 生产接入

Local Loop
生成候选 → 检查 → 修正（最多三轮）
```

一次运行不得跨越多个 Phase。每个任务必须具有明确输入、输出、质量门和停止条件。

## 2. Phase 0：资产盘点

### 目标

建立当前知识、Agent、索引、经验、测试和输出契约的事实地图。

### 输入

- `CLAUDE.md`
- `03_知识库/书籍蒸馏草案_v1.0.md`（既有 RIA-TV++ 与导演链草案，作为待验证输入）
- `MODE_P_MIGRATION.md`
- `02_Agent/director_agent.md`
- `02_Agent/dp_agent.md`
- `01_调度器/mode_p/knowledge/`
- `05_修复与反馈/`
- `05_项目经验/`
- `06_测试/`
- 与知识生成、选择、验证有关的脚本

### 任务

1. 列出所有知识资产和格式；
2. 标记摘要型、规则型、案例型、经验型、测试型；
3. 识别生产读取路径和索引关系；
4. 统计重复、冲突、无来源、无触发条件和无反例的资产；
5. 建立旧资产到新 Schema 的映射；
6. 选择三类试点：基础电影语言、调度/大师镜头、剪辑/节奏；
7. 明确不能直接迁移的内容。

### 产物

- `knowledge_inventory.json`
- `knowledge_gap_report.md`
- `migration_map.json`
- `pilot_selection.md`
- `task_001_report.md`

### 质量门

- 所有结论必须绑定路径；
- 不把文件名推断为文件内容；
- 盘点覆盖生产实际读取的知识；
- 未修改生产文件；
- 不生成大量候选技能。

## 3. Phase 1：Schema 与验证器

### 目标

冻结候选技能、状态、失败模式、案例和评价记录的数据契约。

### 任务

1. 用本项目 Schema 对 10—20 条现有资产做映射演练；
2. 记录无法表达的字段；
3. 修订 Schema；
4. 建立 JSON/YAML 语法校验；
5. 建立唯一 ID、版本、来源和状态检查；
6. 建立重复和冲突候选报告格式；
7. 冻结 `schema_version: 1.0.0`。

### 质量门

- 现有代表性资产至少 80% 可无损映射；
- 所有必要字段可被机器验证；
- “候选、待审、已验证、已弃用”状态不可混淆；
- Schema 不包含模型内部思维链字段。

## 4. Phase 2：试点蒸馏

### 目标

用少量章节验证“书籍 → 决策技能”过程，不追求数量。

### 单章节流程

```text
全章结构扫描
→ 章节核心命题
→ 原则组归纳
→ 条件化规则
→ 技能分层
→ 正确/错误/边界案例
→ 冲突与例外
→ 场景测试
→ 人工复核
```

### 蒸馏 Agent 分工

- `Structure Reader`：理解章节结构，不写技能；
- `Principle Extractor`：归纳上位原则；
- `Decision Compiler`：转成触发—判断—行动—评价；
- `Adversarial Critic`：制造误用、边界和冲突案例；
- `Deduplicator`：与现有资产比较；
- `Human Review Packet Builder`：输出人工审核包。

这些是执行角色，不要求变成生产运行时 Agent。

### 每批规模

20—50 条候选知识：

```text
候选 → 去重 → 冲突 → 反例 → 场景测试 → 人工审核 → 入候选库
```

### 质量门

- 每条技能有明确触发和禁用条件；
- 至少三类案例；
- 来源可追溯；
- 能在场景任务中改变决策，而非只增加解释文字；
- 未通过的资产保留失败原因，不进入候选库。

## 5. Phase 3：最小导演决策链

### 目标

在隔离测试中验证新的知识与推理纪律是否改善当前 Director 的决策，不立即重构生产 Agent。

### 最小 Graph

```text
剧本事实
→ 本集/场次导演命题
→ 观众状态
→ 节拍状态变化
→ 调度
→ 三类候选策略
→ 镜头执行
→ Director Critic
→ DP/连续性检查
→ 修订
```

### 核心状态

所有节点通过 `director_state` 交换，不靠自然语言长对话传递关键事实。

### 候选策略

重要场次至少比较：

1. 克制观察型；
2. 主观情绪型；
3. 关系调度型。

不得把焦段或景别变化伪装成策略差异。

### 质量门

- 每个镜头有上层追溯；
- Critic 能定位首次错误层；
- 相同输入可复现结构化中间结果；
- 生产 `DIRECTOR_MASTER.md` 契约保持不变。

## 6. Phase 4：基准测试集

### 目标

建立可重复评价，不凭主观印象宣布改善。

### 场景覆盖

至少 30 个场次：

- 双人对话；
- 三人权力变化；
- 群戏；
- 揭密与背叛；
- 压抑、恐惧、告别；
- 撒谎与信息差；
- 追逐和复杂动作；
- 无对白；
- 独立 15 秒生成单元；
- 跨镜动作和连续性。

### 每个样本包含

- 原始剧本；
- 事实清单；
- 人工场次功能；
- 关键节拍；
- 基线方案；
- 已知失败方案；
- 合格参考方案或评价区间；
- 评分依据。

### 指标

- 镜头追溯完整率；
- 无动机切镜率；
- 正反打/过肩默认率；
- 调度变化覆盖率；
- 信息泄露率；
- 连续性错误率；
- 冗余镜头率；
- Critic 根因定位准确率；
- 人工偏好胜率；
- 运行成本和时长。

不能只用“镜头多样性”作为指标。

## 7. Phase 5：批量迁移

### 前置条件

- Schema 冻结；
- 三类试点通过；
- 基准集已建立；
- 最小决策链相对基线有稳定提升。

### 迁移顺序

```text
P0 失败模式与修复
P1 场次/节拍/观众状态规则
P2 调度与空间关系
P3 摄影与剪辑技能
P4 案例和冲突规则
P5 低价值摘要归档
```

### 批次规则

每批 20—50 条，必须保留：

- 原始资产 ID；
- 新资产 ID；
- 来源；
- 迁移原因；
- 差异；
- 审核状态；
- 失败原因。

## 8. Phase 6：训练数据

### 目标

积累导演决策轨迹，而非只有“剧本 → 分镜”。

### 样本结构

```text
剧本事实
→ 归纳出的导演命题
→ 证据与反证
→ 场次功能
→ 观众状态
→ 节拍
→ 调度
→ 候选策略
→ 方案比较
→ 拒绝理由
→ 最终选择
→ Critic 反馈
→ 修订结果
```

同时保留成对偏好样本和反事实任务：

- 观众提前知道真相时如何改；
- 只能使用三个镜头时保留什么；
- 禁止近景时如何表达；
- 角色真实意图相反时如何重构；
- 删除一个镜头时哪个最不可替代。

## 9. Phase 7：模型训练准备

满足以下条件前不得微调：

- 至少 100 个高质量场次；
- 每场有多个实质候选；
- 有人工或可靠 Judge 偏好；
- 有失败和修正轨迹；
- 基准测试可重复；
- Schema 稳定；
- 训练/验证/测试无数据泄漏。

推荐顺序：

```text
SFT 结构化决策
→ 偏好训练
→ Critic 训练
→ Judge/过程奖励
→ 必要时强化学习
```

先验证 Prompt + Graph + Knowledge 是否有效，再训练权重。

## 10. Phase 8：生产接入

### 原则

接入必须是独立 PR，不能在知识迁移 PR 中顺便修改运行时。

### 接入候选

- 新知识索引适配器；
- Director 读取经过验证的决策资产；
- 状态投影到现有 Visual Bible、Continuity Ledger 和 Master；
- DP 增加有限的根因定位字段；
- 回写经验进入候选区，不能自动晋升为生产知识。

### 回滚

- 保留旧索引；
- 新旧知识可配置切换；
- 失败时恢复当前 Director/DP；
- 不删除历史知识；
- 每次接入有基准对比和变更日志。

## 11. 持续执行任务队列

每个任务包含：

```yaml
task_id: 唯一编号
phase: 0-8
goal: 单一目标
inputs: 精确路径
allowed_writes: 允许写入范围
forbidden_writes: 禁止写入范围
steps: 有限步骤
deliverables: 文件列表
acceptance: 验收条件
stop_conditions: 停止条件
next_on_success: 下一个任务
next_on_failure: 修复或回退任务
```

## 12. 经验回写

每次场景测试后只产生候选经验：

```json
{
  "new_skills": [],
  "updated_skills": [],
  "new_failure_patterns": [],
  "new_cases": [],
  "evaluation_updates": [],
  "unresolved_questions": []
}
```

经验晋升条件：

- 在多个独立场景中复现；
- 能写出触发和失效条件；
- 有反例；
- 不与现有知识重复；
- 通过人工复核；
- 版本、来源和置信度完整。
