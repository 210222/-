# §2 验证维度

## V1: 存在性来源验证 — "这个东西从哪来的？"

> **核心问题:** 台本中出现的每一个物品，在OBJECT_TIMELINE中是否有对应的存在性来源？
> **验证方法:** 逐镜提取物品清单 → 与OBJECT_TIMELINE逐行比对 → 判定来源合法性

### V1.1 物品提取

```
从台本【生成指令】和【镜头参数卡】的画面描述中提取所有可见物品:

提取规则:
  · 名词短语(物理实体·非抽象概念)
  · 排除: 人物(人物有独立的人物表·不纳入物体验证)
  · 排除: 环境光/自然现象(雨/雪/雾/阳光·属于光源验证)
  · 排除: 声音(在【音轨】中·不纳入物体验证)
  · 排除: 纯运镜描述中的元素("镜头推近"不是物品)
  · ✅ 纳入: 服装/配饰(如果台本描述了具体服装细节)
  · ✅ 纳入: 武器/道具/家具/装饰物/食物/饮品/电子设备
  · ✅ 纳入: 角色手持/穿戴/使用的物品

提取标注:
  [镜#] [物品名] [位置/状态描述] [台本原文摘录]
```

### V1.2 逐项比对

```
对于台本中提取的每个物品 → 在OBJECT_TIMELINE中查找匹配:

匹配条件 (需同时满足):
  ① 物品名称匹配或语义等价
     → "手枪" = "格洛克17" = "配枪" → 同一物品
     → "咖啡" ≠ "咖啡杯" → 不同物品·需分别匹配
  ② 场景/镜#在OBJECT_TIMELINE中记录的存在范围内
     → OBJECT_TIMELINE记录首次出现镜#3 → 在镜#1-2中出现 = 违规
  ③ 状态描述与OBJECT_TIMELINE变化链一致
     → OBJECT_TIMELINE记录"满"→ 台本描述"空"且无中间变化镜 → 违规

匹配结果分类:
  ✅ 精确匹配 — 物品名/位置/来源/状态全部一致
  ⚠️ 语义匹配 — 物品名不同但确认同一物("格洛克17"与"手枪")
  ❌ 无匹配   — OBJECT_TIMELINE中无此物品记录 → V1违规
  ❌ 来源不符 — OBJECT_TIMELINE记录来源A·但台本暗示来源B → V1违规
```

### V1.3 来源合法性判定

```
🅰 参考图已存在:
  → 验证: 在参考图标注格位中是否确实可见该物品？
  → 不能仅凭OBJECT_TIMELINE标注了🅰就通过
  → 需逐格确认: 物品在参考图中的位置/外观/状态与台本描述一致？

🅱 角色随身携带:
  → 🅱-A: 人物表中声明 → 核对人物表原文
  → 🅱-B: 行为推断 → 核对推断推理链是否成立
  → 需确认: 该角色在物品首次出现的镜头中确实在场

🅲 前序镜引入:
  → 验证: 引入镜#中是否确实描述了该物品的引入动作？
  → 引入方式是否明确？("Rico从口袋掏出照片" = 明确·"桌上有一张照片" = 需追溯)
  → 引入镜必须在物品首次出现镜之前·或同一个镜
```

### V1.4 违规裁决

```
V1违规:
  🛑 OBJ-01: 台本物品在OBJECT_TIMELINE中无任何记录 → 凭空出现
  🛑 OBJ-02: OBJECT_TIMELINE标注的🅰参考图来源·但参考图该格中无此物品 → 来源造假
  ⚠️ OBJ-07: OBJECT_TIMELINE标记为⚠️ LEVEL-C·未经人工确认 → 标注
```

## V2: 变化链验证 — "这个东西什么时候变的？"

> **核心问题:** OBJECT_TIMELINE记录的物品状态变化，在台本中是否有对应的中间镜描述？
> **验证方法:** 状态变化事件 → 跨镜追踪 → 检测跳跃

### V2.1 变化链提取

```
从OBJECT_TIMELINE的"变化链"列提取所有状态变化事件:

示例:
  O-03 咖啡杯: #3→半空 #5→空
    → 变化事件①: 镜#3 从"满"变为"半空"
    → 变化事件②: 镜#5 从"半空"变为"空"

  O-05 Rico配枪: #6→拔出放桌上
    → 变化事件①: 镜#6 从"枪套中"变为"桌上"
```

### V2.2 变化合理性验证

```
每个状态变化事件 → 检查台本中对应镜#的描述:

变化类型分类:

  消耗型 (食物减少/液体喝掉/烟燃尽):
    → 必须有"喝/吃/燃烧"等消耗动作在台本中描述
    → 不可从"满"直接跳到"空"·中间应有"半空"或"喝了一口"
    
  转移型 (物品从A点移到B点/从身上取出/被交给他人):
    → 必须有"拿起/放下/递给/掏出/放回"等位移动作
    → 不可从"枪套中"直接变成"在桌上"·中间应有"拔出"动作
    
  变形型 (门开关/灯亮灭/窗户开合/书本翻页):
    → 必须有"推/拉/按/翻"等操作动作
    → 不可从"关"直接变成"开"·除非有明确的开启动作用时
    
  生成型 (原本不存在·被创造出来):
    → 必须有"拿出/摆上/倒入/点燃"等引入动作
    → 这个物品本身必须已经在OBJECT_TIMELINE中有🅲来源

状态跳跃检测:
  OBJECT_TIMELINE变化链: #1满 → #5空 (中间无变化事件)
    → 检查镜#1-#5之间是否有消耗描述？
    → 如无 → 🛑 OBJ-03: 状态跳跃
```

### V2.3 违规裁决

```
V2违规:
  🛑 OBJ-03: 状态跳跃 — 变化链某步骤在台本中无对应描述
     → OBJ-03-1: 消耗型跳跃 (咖啡从满到空·无人喝)
     → OBJ-03-2: 转移型跳跃 (枪从枪套到桌上·无拔出动作)
     → OBJ-03-3: 变形型跳跃 (门从关到开·无推门动作)
     → OBJ-03-4: 生成型跳跃 (物品突然出现·无引入动作)

  ⚠️ OBJ-06: 位置漂移 — 物品位置与空间地图标注位置偏差
     → 桌面物品在参考图中位置A·台本描述在位置B
     → 不阻断·但标注供人工确认
```

## V3: 消失重现验证 — "这个东西刚才不见了·现在怎么又回来了？"

> **核心问题:** 物品从画面消失后重新出现，是否在台本中有重新引入的描述？
> **验证方法:** 物品出现时间线 → 检测消失区间 → 验证重现方式

### V3.1 出现时间线重建

```
从台本和OBJECT_TIMELINE重建每个物品的出现时间线:

  物品X的时间线:
    镜#1: ✅ 在画面中 (首次出现·🅰参考图)
    镜#2: ✅ 在画面中
    镜#3: ❌ 不在画面中 (角色离开桌子·物品不在新机位视野内)
    镜#4: ❌ 不在画面中
    镜#5: ✅ 在画面中 (重新出现)
    
  → 消失区间: 镜#3-#4
  → 重现方式: 镜#5重新出现·需要验证重现是否合理
```

### V3.2 重现合法性验证

```
消失重现判定:

  情况A: 物品位置未变·机位变化导致视野切换
    → 如果物品是固定位置(桌子/柜子上的物品)
    → 机位切回物品所在区域时自然重现 → ✅ 合法
    → 但需满足: 物品在OBJECT_TIMELINE中有🅰来源·固定在参考图已知位置

  情况B: 物品随角色携带·角色离开时消失·角色回来时重现
    → 如果物品是该角色的随身物品(🅱类)
    → 随角色进出画面自然延续 → ✅ 合法
    → OBJECT_TIMELINE中标记🅱-A或🅱-B的物品自动适用

  情况C: 物品被移除后重现·但无重新引入
    → 镜#3中被某人拿走/收起/丢弃
    → 镜#7中又出现·但无人归还/重新放置/再次拿出
    → 🛑 OBJ-04: 消失重现无重新引入

  情况D: 物品从未消失·但台本漏写
    → OBJECT_TIMELINE记录物品应在某镜出现
    → 台本中该镜无此物品描述
    → ⚠️ V3-WARN: 可能的台本遗漏·标注供人工确认

  注意: V3-C和V3-D的区别:
    · V3-C: 台本明确描述了物品被移除 → 再出现时需重新引入
    · V3-D: 台本可能遗漏了描述(物品应该还在·只是台本没写)
```

### V3.3 违规裁决

```
V3违规:
  🛑 OBJ-04: 消失重现无重新引入
     → 物品被明确移除/拿走/丢弃后·后续镜重新出现·台本中无重新引入描述
     → 例外: 随身物品(🅱类)随角色进出画面·自动延续
     → 例外: 固定位置物品(🅰类)因机位切换视野·自然重现
  
  ⚠️ V3-WARN: 可能台本遗漏
     → OBJECT_TIMELINE记录的物品在预期的镜中未被台本描述
     → 可能是台本遗漏而非物品消失·标注供人工确认
```

## V4: 最终一致性验证 — "台本和OBJECT_TIMELINE的最后状态对得上吗？"

> **核心问题:** 台本中每个物品的最终状态是否与OBJECT_TIMELINE记录的终态一致？
> **验证方法:** 终态逐项比对

### V4.1 终态提取

```
从OBJECT_TIMELINE提取每个物品的最终状态:
  O-03 咖啡杯: 最终状态="空"
  O-05 Rico配枪: 最终状态="桌上"

从台本最后一镜提取每个物品的描述状态:
  逐镜追踪→找到每个物品在台本中最后一次出现的状态描述
```

### V4.2 一致性比对

```
逐物品比对:

  完全一致: 台本终态 = OBJECT_TIMELINE终态 → ✅
  
  台本无终态: OBJECT_TIMELINE记录了终态·但台本最后一镜未描述该物品
    → ⚠️ V4-WARN: 物品可能在画面中但台本未描述·也可能是被忽略
    → 不阻断·但标注供人工确认
  
  终态不一致: 台本描述与OBJECT_TIMELINE记录不同
    → 🛑 OBJ-05: 终态不一致
    → 例: OBJECT_TIMELINE记录"空"·台本终镜描述"半满"
    → 例: OBJECT_TIMELINE记录"枪在桌上"·台本终镜描述"枪在腰间"
  
  台本多出终态物品: 台本终镜中出现了OBJECT_TIMELINE未记录的物品
    → 🛑 OBJ-01: 凭空出现·且出现在终镜

### V4.3 违规裁决

```
V4违规:
  🛑 OBJ-05: 终态不一致
     → 台本终态与OBJECT_TIMELINE终态不同
     → 需追溯: 是台本写错了·还是OBJECT_TIMELINE提取时遗漏了变化事件
  
  ⚠️ V4-WARN: 终态物品缺失
     → OBJECT_TIMELINE记录的物品在台本终镜中未被描述

## V5: 凭空出现检测 — "台本里有没有OBJECT_TIMELINE完全不知道的东西？"

> **核心问题:** 台本中出现了OBJECT_TIMELINE完全没有记录的物品。
> **这是最严重的违规——意味着编造。**
> **验证方法:** 全量交叉比对

### V5.1 全量交叉比对

```
Step 1: 台本物品全集
  逐镜提取台本中描述的所有物品 → 去重 → 台本物品全集S

Step 2: OBJECT_TIMELINE物品全集
  提取OBJECT_TIMELINE中所有物品O-ID → OBJECT_TIMELINE物品全集T

Step 3: 差集检测
  S - T = 台本中有·OBJECT_TIMELINE中无的物品 = 疑似凭空出现
  T - S = OBJECT_TIMELINE中有·台本中无的物品 = 可能遗漏(⚠️·标注但不断)

Step 4: 每种物品的个案分析
  对于S - T中的每个物品:
    → 是否有合理的🅱来源(随身)但未被OBJECT_TIMELINE提取？
      例: 剧本人物表中写了"配枪"·但OBJECT_TIMELINE漏提取
      → 标注为"OBJECT_TIMELINE遗漏·建议补充"
      → 不阻断·但需要更新OBJECT_TIMELINE
    
    → 是否是台本中的环境描述·而非具体物品？
      例: "房间里有家具" — "家具"太泛化·无法逐项追踪
      → ⚠️ 标注为"泛化描述·建议具体化"
    
    → 是否是台本中的临时描述·无法归类为可追踪物品？
      例: "空气中弥漫着咖啡的香气" — 这是嗅觉描述·不是物品
      → ✅ 排除·非物品
    
    → 是否是真正的凭空编造？
      例: 台本镜#5描述"桌上有一把手枪"·但OBJECT_TIMELINE中无此枪
        ·参考图中无此枪
        ·人物表中此角色不配枪
        ·前序镜中无引入
      → 🛑 OBJ-01: 凭空出现
```

### V5.2 个案深度分析模板

```
对于S - T中发现的每个疑似凭空出现物品，按以下模板深度分析:

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
物品: [名称]
台本位置: 场景[名]·镜#[N]·[X-Y]秒段
台本原文: "[摘录台本中描述该物品的原文]"

排除分析:
  □ 是否在参考图中存在？
    → 检查场景参考图各格 → 是/否
    → 如果是 → 标注🅰来源·建议更新OBJECT_TIMELINE
    
  □ 是否是人物表中声明的随身物品？
    → 检查人物表 → 是/否
    → 如果是 → 标注🅱-A来源·建议更新OBJECT_TIMELINE
    
  □ 是否可从剧本行为推断为随身物品？
    → 检查剧本中角色是否从身上取出/使用 → 是/否
    → 如果是 → 标注🅱-B来源·标注推断推理链·建议更新OBJECT_TIMELINE
    
  □ 是否可在前序镜中找到引入描述？
    → 逐镜回溯台本 → 是/否
    → 如果是 → 标注🅲来源·标注引入镜#·建议更新OBJECT_TIMELINE
    
  □ 是否是泛化/抽象描述而非具体物品？
    → 判断描述是否足够具体 → 是/否
    → 如果是 → 标注为"泛化描述·建议具体化"
    
  □ 是否根本不存在合理来源？
    → 以上全部为否 → 🛑 OBJ-01: 凭空出现

裁决:
  🛑 凭空出现 / ⚠️ OBJECT_TIMELINE遗漏 / ✅ 可追溯但OBJECT_TIMELINE需更新
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

# §5 修复-重验证回环

## 5.1 回环规则

```
┌──────────────────────────────────────────────────────────────────┐
│  Round 1: 初始验证                                                │
│    → 输出 OBJECT_VERIFIER_REPORT.md                               │
│    → 🛑裁决 → 打回prompt_composer·附带修复指令                     │
│                                                                   │
│  Round 2: 修复后重验证                                             │
│    → prompt_composer只修改问题镜的物品描述                          │
│    → 本Verifier重新独立验证·不读修复推理·只看修复结果               │
│    → 同一镜仍有🛑 → 标记·进入最终裁决                              │
│                                                                   │
│  Round 3 (如需要): 更换Verifier                                    │
│    → 同一镜被同一verifier驳回2次 → 轮换verifier                     │
│    → 新verifier独立验证·不读前两轮verifier的报告                   │
│    → 仍不通过 → 降级⚠️已知缺陷·标注后交付                          │
│                                                                   │
│  降级条件:                                                        │
│    · 2轮修复后仍有🛑 → 降级为⚠️已知缺陷                           │
│    · 降级交付必须标注: "⚠️ 已知物体存在链缺陷·超出自动修复上限·    │
│      [N]项未修复·[物品清单]"                                       │
│    · 降级交付不违反画布宪法·宪法第六条定义了降级条件                │
│                                                                   │
│  避免惯性措施:                                                     │
│    · 重验证时只读取修复后的台本·不读取之前的验证报告                 │
│    · 同一镜被驳回≥2次 → 自动触发verifier轮换                       │
│    · 轮换时新verifier不被告知之前为什么被驳回                       │
└──────────────────────────────────────────────────────────────────┘
```

## 5.2 与prompt_composer的修复协议

```
打回时附带的信息:
  ✅ 传达: 违规物品名 + 违规代码 + 影响镜# + 修复建议方向
  ❌ 不传达: 本Verifier的推理过程·为什么判定为违规的详细分析
  ❌ 不传达: 其他物品的验证结果
  
  prompt_composer收到的指令:
    "[物品名]在[镜#]中的存在性无法验证([违规代码])。
     修复方向: [A/B/C选项]。
     仅修改影响镜的物品描述·其他镜和物品保持原样。"

  原因(画布宪法第七条):
    提示词修复者应该基于原始设计意图修复·而不是基于验证者的推理过程修复。
    看到验证者的推理过程会导致"迎合性修复"——为了通过验证而做表面修改。
```

# §6 边界案例处理手册

## 6.1 声音物品

```
问题: 音轨描述中的物品是否需要纳入物体存在链？
  → "音轨: 电话铃声响起" — "电话"是否需要在OBJECT_TIMELINE中？

判定: 声音源如果在画面中 → 需要存在性来源
  · 铃声从画面中的电话发出 → 电话必须在OBJECT_TIMELINE中
  · 铃声从画面外传来 → 不纳入物体验证·音轨描述已足够
  · VO/旁白/音乐 → 不纳入物件验证
```

## 6.2 隐含物品

```
问题: 台本说"他坐在椅子上"·但OBJECT_TIMELINE中没有"椅子"？
  
判定: 动作隐含的物品 → 如果隐含物品在参考图中 → 不强制台本显式描述
  · "坐在椅子上" → 椅子在参考图中有 → ✅(不需要台本重复声明椅子)
  · "他打开门" → 门在参考图中有 → ✅
  · "他按下开关" → 开关在参考图中有 → ✅

  但如果:
  · "他坐在椅子上" → 参考图中该位置没有椅子 → ⚠️ 空间矛盾
  · "他打开保险柜" → 参考图中没有保险柜 → 🛑 凭空出现
```

## 6.3 同一物品的多个实例

```
问题: 台本中有"两把相同的椅子"·OBJECT_TIMELINE中只有"椅子"一条记录？

判定: 同型号多实例 → OBJECT_TIMELINE中标注实例数量
  · 参考图中可见的所有椅子 → 合并为一条·标注数量
  · 剧本明确引入的新椅子 → 单独一条·🅲来源
  · 台本描述了第N把不在参考图中的椅子 → 🛑 数量超限
```

## 6.4 跨场景物品追踪

```
问题: 物品在场景A出现·场景B中又出现？

判定: 跨场景物品 → 通过场景末状态快照传递
  · 场景A末快照中记录了物品最终状态 → 场景B以该状态为初始
  · 如果物品是角色随身(🅱类) → 自动跨场景延续
  · 如果物品是场景固定(🅰类) → 只在原场景有效·新场景需新来源
  
  · 场景A的物品出现在场景B · 但物品不是随身·也没有被携带的描述 → 🛑
  · 角色从场景A走到场景B · 手里拿着场景A的物品 → 需在过渡镜中描述"拿着"
```

## 6.5 台本省略与泛化

```
问题: 台本说"房间里陈设简单"·然后没有列出具体物品？

判定: 泛化描述不能替代物品清单
  · "陈设简单" = 合法但不够精确
  · 如果画面中实际需要出现具体物品 → 必须显式描述
  · 如果画面中只有参考图已有的陈设 → 不需要额外描述

  ⚠️ V5-WARN-2: 连续3个以上镜只依赖参考图+泛化描述·无具体物品描述
  → 标注·建议在关键镜增加物品描述以辅助Seko渲染一致性
```

## 6.6 时间-空间换位物品

```
问题: OBJECT_TIMELINE记录"手枪在桌上"·台本镜#4描述"手枪在抽屉里"
  → OBJECT_TIMELINE中手枪从未被移动

判定: 空间换位 = 物品状态变化 = 需要中间动作
  → 如果OBJECT_TIMELINE中枪支的变化链没有"#X→被放入抽屉"
  → 🛑 OBJ-03(状态跳跃) + OBJ-05(终态不一致)
  → 或台本错误·或OBJECT_TIMELINE遗漏变化事件
  → 交叉验证后确定责任方
```
