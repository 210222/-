# P-Verifier v3.0 — 多维深度探究 · 独立专项专家架构

> **定位:** MODE:P管道最终验证层。6个独立专项专家，每个以不同的探究方法论（红队对抗·边界测验·假设驱动·模式匹配·结构同构·确定性扫描）审视全貌。不是"一个专家一个维度"，是"六个专家六种方法，各自覆盖全部维度"。
> **核心原则:** 多方会诊 > 分工检查 · 探究方法论多样性 > 验证维度覆盖 · 假设-验证-反驳循环
> **设计依据:** 红队对抗（MAVEN Skeptic演进）· 边界测验（Fable 5 AC/DC框架）· 假设驱动（因果链追踪）· 模式匹配（P-STATE FSRS信号）· 结构同构（TIME_SKELETON三视图一致）
> **版本:** v3.0 · 2026-07-07
> **被调用者:** dispatcher_v5.0.md MODE:P · Step 9（全场景完成后）
> **前身:** v2.0 方案二（7专家·单维分工） → v3.0（6专家·多维探究）

## Expert 1: Gate 0 Deterministic Scanner (确定性规则扫描)

> **方法论:** 正则+数值·零模型判断·100%准确率
> **定位:** 所有可确定性验证的规则集中在此。不探究·不假设·不猜测——只做确定性检查。
> **与v2.0差异:** 无。Gate 0的逻辑不依赖探究方法论。

```
输入:
  ├─ 全部场景 VIDEO_PROMPT_[场景].md
  ├─ 全部场景 TIME_SKELETON (从 PLAN_[场景].md §B)
  └─ P-CONSTITUTION.md §5

检查项 (一次扫描·全部场景):

R01 时长硬约束:      任一段>15.0秒 → 🛑

R03 时间模糊词:      含"缓缓/渐渐/慢慢/逐渐/徐徐/冉冉" → 🛑
R04 跨镜引用:        含"同上/参考上镜/如前/同镜#/与镜#" → 🛑
R05 参考图引用:      @图片格式异常或引用不存在 → 🛑

## Expert 2: Red Team Adversarial (红队对抗)

> **方法论:** "假设一切都有问题。找到证据证明它确实有问题。"
> **探究维度:** 全部——从对抗视角审视故事板、视频提示词、TIME_SKELETON、空间地图、参考图的一致性。
> **核心姿态:** 默认立场=不信任·主动寻找反例·构造攻击场景

```
输入:
  ├─ TIME_SKELETON (全部场景)
  ├─ 全部 STORYBOARD_[场景].md
  ├─ 全部 VIDEO_PROMPT_[场景].md
  ├─ 空间地图 + 参考图 + IMAGE_AUDIT
  ├─ 三Agent设计报告
  └─ P-STATE.md §2 (已知失败模式·作为攻击向量)

探究方法:

2A 构造攻击场景 (Attack Scenario Construction)
  对每个关键断言构造反例:
    断言: "Rico的深蓝西装在全场景中逐字一致"
    攻击: 逐镜提取所有角色外观描述 → 寻找措辞偏移(哪怕一个同义词替换)
    攻击: 跨场景对比——场景A的"深蓝单排扣西装" vs 场景B是否变成了"藏蓝外套"?
    攻击: 视频提示词中是否出现了骨架中不存在的服装细节?
    发现 → 报告"Character Anchor漂移·攻击面: [具体差异]"

  断言: "所有光源有物理锚点"
    攻击: 逐句扫描光源描述 → 对每个光源追问"这个光源的物理位置在参考图哪个格?"
    攻击: 找不到锚点的光源 → 尝试推断锚点 → 推断失败 → 报告
    攻击: 同一场景内色温值是否矛盾? (一段说2800K·另一段说3200K)

  断言: "TIME_SKELETON.frames[N] = 故事板格N = 视频提示词第N秒"
    攻击: 随机抽样3个场景×3个秒位 → 三方逐字对比
    攻击: 找"几乎一致但不完全一致"的微妙漂移(措辞偏移·细节遗漏·多余细节)
    发现 → 报告"三视图同构断裂·攻击面: [具体秒位·具体差异]"

2B 边缘案例压力测试 (Edge Case Stress)
  对每个规则寻找边界突破:
    段时长: 有没有恰好15.0秒的段?(边界·Seko可能不稳定)
    人物占位: 标注"可站3人"的区域·剧本是否放了4人?
    运镜: 有没有"极慢推近0.02x"运镜跨越段边界?(运镜被段切打断)
    道具: 有没有道具在段末秒消失·段首秒立即出现?(跨段道具瞬移)
    音效: 有没有同一秒内3个音效事件?(边界·AI可能合并)

2C 对抗性重构 (Adversarial Reconstruction)
  尝试从视频提示词"反向推导"TIME_SKELETON → 与原始TIME_SKELETON对比:
    从提示词提取: 每段时长·景别序列·运镜序列·角色位置序列
    对比原始: TIME_SKELETON.segments·frames.hard·frames.soft
    差异 → 信息在派生过程中丢失或变形

2D 沉默失败检测 (Silent Failure Detection)
  寻找"没有🛑但实质上错了"的问题:
    门是"深色金属门"→ 参考图中门是浅色木门 → Gate 0不会阻断(门确实在参考图中)
    角色"坐姿挺拔"→ 但空间地图中该位置没有座位 → 角色悬空
    光源"从窗户射入"→ 但空间地图中该墙没有窗户 → 光源穿透墙壁

输出: REDTEAM_REPORT.md
  攻击面清单 (每个攻击面含: 断言·攻击方法·发现·严重度·修复建议)
  边缘案例清单 (每个案例含: 边界条件·当前值·风险·建议)
  沉默失败清单 (每个失败含: 为什么Gate 0没发现·为什么它仍然有问题)

裁决:
  🛑 攻击面确认(构造的反例确实存在·非假设) → 阻断
  ⚠️ 攻击面疑似(无法100%确认·需要更多信息) → 标注
  💡 边缘案例(当前未触发·但风险存在) → 建议
```

## Expert 3: Empirical Boundary Tester (边界测验)

> **方法论:** "能测量的就不要猜测。每个约束都有数字——测它。"
> **探究维度:** 全部——所有可量化的维度（时间·空间·数量·速度·色温·精度）。
> **核心姿态:** 量化一切·模拟渲染行为·边界值测试

```
输入:
  ├─ TIME_SKELETON (全部场景)
  ├─ 全部 VIDEO_PROMPT_[场景].md
  ├─ 空间地图 (物理尺寸)
  ├─ P-STATE.md §2 (已知平台边界)
  ├─ sd2_model_capability.md (模型能力边界)
  └─ canvas_runtime.md (Seko平台约束)

探究方法:

3A 时间边界测试 (Temporal Boundary Testing)
  逐段测试:
    段时长: [实际值] vs [15s硬上限] · 安全余量 = 15 - 实际值
    关键帧间隔: 相邻关键帧之间的秒数 · >4s → ⚠️(AI可能自行填充过渡)
    静止时间: 段末静止秒数 · <0.5s → ⚠️(画面未落定就转场)
    运镜速度: 实际秒数 vs 距离 vs 速度倍数是否自洽?
      例: "0.03x·3秒推约15cm" → 验证: 0.03×3=0.09x ≠ 15cm/? 
      → 需要知道基准距离才能验证速度自洽性 → 标注"速度参数无法闭环验证"
    过渡秒: ①→②过渡标记的秒数是否与frames中的is_transition_frame一致?

3B 空间边界测试 (Spatial Boundary Testing)
  逐场景测试:
    房间尺寸 vs 人物数量: 空间地图标注"约4m×4m"·可站3人 → 剧本描述"一群人(10+)"→ ⚠️
    窄空间运镜: 纵深<3m → 是否有横移运镜? → P-FAL-06触发 → 🛑
    摄影机路径: transition.path 在空间地图中可追踪? → 逐段绘制摄影机运动轨迹
    人物穿墙: 人物从位置A移动到位置B → 路径是否穿过墙壁/家具?
    光源方向 vs 空间结构: "光从左侧窗射入" → 空间地图中左侧有窗? → 验证

3C 模型能力边界测试 (Model Capability Boundary)
  对照 sd2.0 已知边界逐一测试:
    瞳孔控制: 提示词中有瞳孔变化描述? → P-FAL-01触发
    mm级精度: 提示词中有"5mm间距"等? → P-FAL-02触发
    亚秒级时序: 提示词中有"每0.5秒"等? → P-FAL-03触发
    同时音效: 同一秒内≥3个独立音效? → P-FAL-04触发
    VO语速: VO字数÷画面时长 > 4字/秒? → P-FAL-05触发
    高频视觉噪声: 精细纹理+快速切换? → P-FAL-07触发
    画面文字: 提示词中有文字渲染要求? → P-FAL-08触发
    极端运动形变: 快速/大幅度运动? → P-FAL-09触发
    多人口型: ≥2人同时说话? → P-FAL-10触发

3D 量化一致性测试 (Quantitative Consistency)
  跨镜数值对比:
    色温: 同一场景所有色温值 → 计算方差 → 方差>0 → ⚠️
    景别序列: 相邻镜景别跳跃 → 全景→大特写(跳跃≥4档) → ⚠️
    运镜速度序列: S1(极慢)→S8(极快) → 跳跃≥4档 → ⚠️
    焦段序列: 24mm→135mm → 跳跃≥3档 → ⚠️

输出: BOUNDARY_REPORT.md
  边界违规清单 (每个违规含: 约束名·实际值·边界值·偏差量·严重度)
  模型能力冲突清单 (每个冲突含: P-FAL-ID·触发位置·规避方案)
  量化一致性热图 (色温/景别/运镜/焦段的跨镜方差可视化数据)

裁决:
  🛑 硬边界突破(>15s·P-FAL触发·物理不可能) → 阻断
  ⚠️ 边界接近(余量<20%·方差显著) → 标注
  💡 数值无法闭环(参数自洽性无法验证) → 建议补充基准数据
```

## Expert 4: Hypothesis-Problem Investigator (假设驱动探究)

> **方法论:** "如果X出了问题，那么Y应该表现出症状Z。去找Z。"
> **探究维度:** 全部——但以因果链为线索，追踪根因而非罗列症状。
> **核心姿态:** 形成假设→预测症状→验证预测→锁定根因→提出修复

```
输入:
  ├─ TIME_SKELETON (全部场景)
  ├─ 全部 STORYBOARD_[场景].md
  ├─ 全部 VIDEO_PROMPT_[场景].md
  ├─ 三Agent设计报告
  ├─ P-STATE.md §2-§3
  ├─ STATE.md §3 (跨管道模式)
  └─ Expert 2+3 的报告 (红队攻击面 + 边界违规)

探究方法:

4A 假设形成 (Hypothesis Generation)
  从以下来源生成假设:
    来源1: Expert 2的攻击面 → "如果这个攻击面是真的，还有什么会跟着出问题?"
    来源2: Expert 3的边界违规 → "如果这个边界被突破，下游影响是什么?"
    来源3: P-STATE §2的已知失败模式 → "已知X会失败，这次X出现了吗?"
    来源4: 跨管道信号(STATE.md) → "MODE:A也出现了类似模式·这是系统性问题吗?"
  
  假设模板:
    H-[ID]: 如果 [根因] 发生在 [位置]
            那么 [下游症状A] 应该出现在 [位置A]
            并且 [下游症状B] 应该出现在 [位置B]
            并且 [这些症状不应该独立出现——它们应该共现]
    置信度: 基于历史模式·FSRS信号强度·跨管道信号

4B 症状预测与验证 (Symptom Prediction & Verification)
  对每个假设:
    Step 1: 根据因果链预测具体症状
      例: H-01: 如果"台灯光源锚点漂移"
               那么 → 不同镜中台灯色温不一致(症状A·Expert 3已检测)
               那么 → 光锥范围描述矛盾(症状B·需验证)
               那么 → 阴影方向不一致(症状C·需验证)
    
    Step 2: 在全部输出中搜索预测症状
      症状B验证: 逐镜提取光锥范围描述 → 对比 → 发现矛盾? ✅/❌
      症状C验证: 逐镜提取阴影方向描述 → 对比 → 发现矛盾? ✅/❌
    
    Step 3: 判定假设是否成立
      症状A+B+C同时出现 → 假设成立·根因锁定·置信度高
      只有症状A(Expert 2已发现) → 可能是孤立问题·置信度中
      症状A+B+C都不成立 → 假设驳回·Expert 2的攻击面可能是假阳性

4C 因果链追踪 (Causal Chain Tracing)
  对已验证的假设·追踪完整因果链:
    根因 → 直接后果 → 下游后果 → 跨场景后果 → 渲染失败模式
    
    例: 光源锚点漂移(根因)
         → 色温描述不一致(直接后果·Expert 3检测)
         → 不同镜中同一场景色调不同(下游后果·本Expert验证)
         → 跨场景时色调跳跃(跨场景后果·本Expert验证)
         → Seko渲染时色调振荡→画面闪烁(渲染失败·P-FAL-07相关)

4D 根因分类与修复建议 (Root Cause Classification)
  将已验证的根因分类:
    🔴 骨架级根因: TIME_SKELETON本身有矛盾 → 返回storyboard_planner修正
    🟡 派生级根因: 骨架正确·prompt_composer展开时引入偏差 → 返回prompt_composer修正
    🟢 约束级根因: 骨架和展开都正确·与外部约束(P-STATE/sd2.0)冲突 → 标注·人工裁决
    ⚫ 环境级根因: 不是系统问题·参考图/空间地图信息不足 → 补充输入后重验证

输出: HYPOTHESIS_REPORT.md
  假设清单 (每个假设含: 假设ID·根因·因果链·预测症状·验证结果·置信度)
  已验证根因 (含: 分类·严重度·修复方向·修复后需要重新验证的假设)
  驳回假设 (含: 驳回原因·对Expert 2攻击面的反馈)
  因果链图 (根因→下游后果的完整因果拓扑)

裁决:
  🛑 根因确认·置信度高·P0级 → 阻断·指定修复目标
  ⚠️ 根因确认·置信度中·P1级 → 标注·建议修复
  💡 假设存疑·需要更多数据 → 标记·下次MODE:P重检
```

## Expert 5: Pattern-Match Hunter (模式匹配·存在问题)

> **方法论:** "所有已知的失败模式——历史问题·FSRS高频信号·跨管道系统性缺陷——在这个输出中是否存在？"
> **探究维度:** 全部——但聚焦于"已知会出问题的地方"。
> **核心姿态:** 不重新发现——直接匹配已知模式·防止问题复现

```
输入:
  ├─ TIME_SKELETON (全部场景)
  ├─ 全部 VIDEO_PROMPT_[场景].md
  ├─ P-STATE.md §1(已验证模式) §2(已知失败·含FSRS信号) §5(KB蒸馏候选)
  ├─ STATE.md §3(未解决失败·MODE:A管道)
  ├─ distillation_engine_v1.0.md (跨管道模式)
  └─ Expert 2+3+4 的报告 (可能触发的已知模式)

探究方法:

5A P-STATE §2 已知失败模式匹配
  逐条扫描P-STATE §2的全部P-FAL条目:
    P-FAL-01(瞳孔控制): 搜索所有瞳孔相关描述 → 匹配? → 标记·建议规避方案
    P-FAL-02(mm级精度): 搜索所有mm级描述 → 匹配? → 标记
    P-FAL-03(亚秒时序): 搜索"每Xs"模式 → 匹配? → 标记
    P-FAL-04(≥3音效): 逐秒统计音效事件数 → ≥3? → 标记
    P-FAL-05(VO语速): 计算每段VO字数÷时长 → >4? → 标记
    P-FAL-06(窄空间横移): 纵深<3m + 横移运镜 → 标记
    P-FAL-07(高频视觉噪声): 精细纹理+快速切换组合 → 标记
    P-FAL-08(画面文字): 搜索文字渲染描述 → 标记
    P-FAL-09(极端形变): 快速运动+大幅度 → 标记
    P-FAL-10(多人口型): ≥2人同时说话 → 标记

## Expert 6: Structural Isomorphism Verifier (结构同构验证)

> **方法论:** "三样东西——TIME_SKELETON·故事板·视频提示词——必须结构同构。逐秒·逐格·逐字验证。"
> **探究维度:** 结构对齐——三个视图的逐元素对比。
> **核心姿态:** 不检查"对不对"——只检查"是不是同一个东西的三个视图"。

```
输入:
  ├─ TIME_SKELETON (对齐基准·单一真源)
  ├─ 全部 STORYBOARD_[场景].md (视觉视图)
  └─ 全部 VIDEO_PROMPT_[场景].md (文本视图)

探究方法:

6A 逐秒三视图对齐 (Per-Second Three-View Alignment)
  对 TIME_SKELETON.frames 的每一秒:
    
    sec N | TIME_SKELETON      | 故事板               | 视频提示词
    ──────┼────────────────────┼──────────────────────┼────────────────────
          | camera_position: ① | 格N+1标注: ①位置     | 第N秒: ①段
          | hard.shot_type     | 格N+1标注: 景别      | Camera段: 景别
          | hard.focal_length  | 格N+1标注: 焦距      | Camera段: 焦距
          | hard.camera_mvmt   | 格N+1标注: 运镜      | Camera段: 运镜
          | soft.action_anchor | 格N+1画面: 人物姿态   | 第N秒: 画面描述
          | soft.spatial_anchor| 格N+1画面: 空间结构   | (不出现·铁律§5.1)
          | prop_state         | 格N+1画面: 道具位置   | 第N秒: 道具描述
          | audio.events       | 格N+1音效标注        | 时序描述: 音效
    
    三项必须全等 → ✅
    任一项不对齐 → ⚠️ 记录偏移量(具体哪个字段·两个视图分别是什么)
    
    对齐精度分级:
      硬字段(hard): 必须逐字一致 → 任何差异 = 🛑
      软字段(soft): 故事板是空间锚点·提示词是展开文本 → 语义等价即可
      音频字段(audio): 必须逐字一致 → 任何差异 = 🛑

6B 编号系统一致性 (Numbering System Consistency)
  验证 TIME_SKELETON.segments 中的编号系统:
    ①②③④ 序列是否连续?
    ①→② 过渡是否在两个有效位置之间?
    "切"标记是否正确(无过渡)?
    
  验证故事板中的编号:
    每格标注的摄影机位置与 TIME_SKELETON.frames[N].camera_position 一致?
    运镜过渡标记与 TIME_SKELETON.segments[transition] 一致?
    
  验证视频提示词中的编号:
    分段标记(①②③④)与 TIME_SKELETON.segments 一致?
    过渡段(①→②)与 TIME_SKELETON.segments[transition] 一致?

6C 全局锚点逐字一致性 (Global Anchor Verbatim Consistency)
  验证 TIME_SKELETON.global_anchors 在三视图中的逐字复制:
    
    global_anchors.character     → 故事板"共享视觉锚·贯穿人物" = 逐字相同?
                                → 视频提示词 Subject = 逐字相同?
    global_anchors.environment   → 故事板"共享视觉锚·场景空间" = 逐字相同?
    global_anchors.style_spine   → 视频提示词 Style = 逐字相同?
    global_anchors.lighting      → 故事板"共享视觉锚·固定光源" = 逐字相同?
                                → 视频提示词 Style = 逐字相同?
    global_anchors.constraints   → 视频提示词 Constraints = 逐字相同?
    
    逐字对比·任何措辞差异(即使同义词) → ⚠️ "锚点漂移·[具体差异]"

6D 道具状态跨视图追踪 (Cross-View Prop State Tracking)
  逐帧验证:
    TIME_SKELETON.frames[N].prop_state[item].state
    = 故事板格N+1中该道具的视觉状态?
    = 视频提示词第N秒中该道具的描述状态?
    
    三者状态描述必须语义等价
    差异 → ⚠️ "道具状态三视图不一致·[道具名]·[秒位]"

6E 信息分工铁律验证 (Information Division Iron Law)
  验证 storyboard_planner §5.1 铁律是否被执行:
    故事板中是否出现了材质/光影/色彩描述? → 违规·这些应在提示词中
    视频提示词中是否重复了故事板已有的空间信息? → 冗余·违反§5.1
    TIME_SKELETON.soft 锚点是否被故事板和提示词同时尊重? → 验证

输出: ISOMORPHISM_REPORT.md
  逐秒对齐表 (N秒×3视图·每字段标注✅/⚠️/🛑)
  锚点漂移清单 (global_anchors在三视图中的差异)
  编号系统完整性验证
  信息分工违规清单

裁决:
  🛑 hard字段不对齐·编号系统断裂·global_anchors漂移 → 阻断
  ⚠️ soft字段语义偏差·道具状态描述差异·信息分工违规 → 标注
```
