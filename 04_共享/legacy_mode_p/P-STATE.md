## 维护规则

```
1. 自动更新: P-Verifier每次完成验证后自动追加§4会话日志
2. 人工审核: 每10次MODE:P运行后人工审查§1-§3·确认/修正/迁移条目
3. 升级规则:
   ┌─ §3 问题找到可靠规避方案 → 迁移到 §2(失败模式·含规避方案)
   ├─ §2 规避方案连续5次有效 → 迁移到 §1(已验证模式)
   ├─ §1 模式在新版Seko上失效 → 降级到 §2(失败模式)
   └─ §3 问题连续3次未触发 → 标记为🟢已解决·迁移到归档
4. 与MODE:F联动:
   └─ MODE:F用户反馈Seko渲染结果 → 提取失败模式 → 更新§2/§3
5. 与prompt_composer联动:
   └─ prompt_composer启动时Read §1-§2 → 优先使用已验证模式·规避已知失败模式
6. 与Render-Verifier联动:
   └─ Render-Verifier发现新失败模式 → 更新§2(FSRS S=1.0)
   └─ Deep Repair降级问题 → 更新§3
   └─ 连续3次同一根因 → 更新§5 KB蒸馏候选 → 触发distillation_engine
7. 与distillation_engine联动:
   └─ §5候选规则积累到阈值 → 触发蒸馏引擎Stage 2(Investigate)
   └─ 影子测试通过 → Stage 4(Distill) → 候选规则卡片
   └─ 候选≥3条 → Stage 5(Consult) → 人工确认 → 合并到KB
8. 🆕 与STATE.md联动 (跨管道模式识别):
   └─ MODE:A和MODE:P独立维护各自的STATE文件
   └─ 每次Render-Verifier完成后 → 检查STATE.md §3是否有同类失败
   └─ 同一失败在双管道同时出现 → 标记为"跨管道系统性缺陷"·提升优先级
   └─ 跨管道缺陷≥2条 → 触发MODE:R离线体检
9. 🆕 FSRS信号管理 (§2失败模式):
   └─ 新增失败模式 → S=1.0·D=人工评估(1-10)·R=1.0
   └─ 复现 → S增长(1.0→2.5→6.0→14.0…)·R重置为1.0
   └─ 未复现 → R自然下降·S不变
   └─ S≥6+复现≥3次 → 🟡触发蒸馏候选(§5)
   └─ S≥10+复现≥5次 → 🔴高优先级蒸馏
   └─ R<0.2 → 信号失活·移出活跃追踪
```
