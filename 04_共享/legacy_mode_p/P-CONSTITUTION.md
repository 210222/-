# 序言

MODE:P 管道的本质是**将导演意图翻译为Seko画布可精确执行的视频指令**。这个翻译过程的核心约束不是导演教材（Arijon/Katz），而是Seko平台的渲染能力边界。

MODE:A 问的是"拍出来能看吗？"——这是美学的、物理的、可拍性的问题。
MODE:P 问的是"Seko能渲染出来吗？"——这是平台的、像素的、可执行性的问题。

两个问题有交集，但约束体系完全不同。因此画布宪法独立存在。

本宪法基于以下认知建立：
1. **Seko不是一个通用物理引擎**——它有明确的渲染盲区（瞳孔控制、mm级精度、亚秒级时序）
2. **LLM有画面外描述的倾向**——模型会自然地添加文学修饰，但这些修饰在渲染时变成无法执行的噪音
3. **物体不会凭空存在**——画面中的每个物品必须有可追溯的来源（参考图/随身/引入）
4. **确定性检查比概率性验证更可靠**——正则扫描零过程动词的准确率是100%，而LLM判断"这段描述是否可渲染"的准确率约73%

# 第一条：画面可见性优先于文学描述

> **优先级声明：** 只描述画面内可见物 > 文学修饰
> **编码依据：** Seko的核心行为——AI会生成你描述的每一个字。描述不在画面内的东西，AI也会试图生成它们。

## 1.1 规则定义

```
┌──────────────────────────────────────────────────────────────────────┐
│ 📜 画布第一条 · 不可违反                                              │
│                                                                      │
│  ① 每段【生成指令】只描述该段画面中实际可见的:                          │
│     · 人物(及其面部表情·身体姿态·服装)                                 │
│     · 物体(在画面内的·有存在来源的)                                    │
│     · 环境(光线·阴影·天气·背景)                                       │
│     · 运镜参数(速度·方向·起止状态)                                     │
│                                                                      │
│  ② 禁止描述画面外元素:                                                │
│     · ❌ "画面外传来脚步声" — Seko会生成脚步声的画面                   │
│     · ❌ "她想起了童年的那棵树" — 记忆/想法不可渲染                    │
│     · ❌ "气氛紧张得像要爆炸" — 比喻/情绪抽象不可渲染                  │
│     · ❌ "镜头外的他正在走来" — 画面外动作不可描述                     │
│                                                                      │
│  ③ 画面外元素的正确处理:                                              │
│     · 画面外声音 → 放在【音轨】中·不放在【生成指令】画面描述中          │
│     · 角色内心活动 → 转化为外部可见行为("她的手在发抖" 而非 "她很紧张") │
│     · 空间外存在 → 只在【设计依据】/OBJECT_TIMELINE中记录·不进入提示词  │
│                                                                      │
│  ④ 文学修饰的硬约束:                                                  │
│     · ❌ "像幽灵一样飘过" → ✅ "以0.1x极慢速度平移·身体无起伏"         │
│     · ❌ "眼神深邃如深渊" → ✅ "瞳孔固定·虹膜深棕色·角膜反光点固定"    │
│     · ❌ "光线温柔地拥抱她" → ✅ "暖色光(约3200K)·从右侧窗户45°角射入" │
│                                                                      │
│  ⑤ 检测方法:                                                         │
│     → 逐句扫描: 每句主语是否是画面中的物体/人物/光线？                  │
│     → 抽象词扫描: 有无"气氛/情绪/感觉/仿佛/如同/像是"？                │
│     → 画面外扫描: 有无"画面外/镜头外/屏幕外/画框外"？                  │
└──────────────────────────────────────────────────────────────────────┘
```

## 1.2 冲突矩阵

| 文学描述 | 画面对应 | 裁决 |
|---------|---------|------|
| "她感到深深的悲伤" | "她眼角泪珠滚落·嘴唇微颤·视线固定在窗外" | 使用画面描述 |
| "画面外警笛声渐近" | 音轨: "警笛声从远处逐渐增强·第3秒达到峰值" | 移到音轨 |
| "空气中有种说不出的压抑" | "低色温单光源(2700K)·浓重阴影覆盖画面2/3面积" | 使用光线描述 |
| "他仿佛看到了过去" | 不可转化 → 🛑 删除此描述 | 🛑 阻断·重新设计 |

## 1.3 引用规范

Agent引用格式：`参照画布宪法第一条·画面可见性·本描述主语[在/不在]画框内`

## 1.4 违反后果

- 任一段含画面外描述 → 🛑 VIS-01阻断

> **优先级声明：** Seko能渲染出来的效果 > 导演教材推荐的理想效果
> **编码依据：** MODE:P的交付物是Seko视频，不是真实摄影机拍摄的影片。Seko平台的能力边界是不可协商的硬约束。

```

│                                                                      │

│     · 不能"两个都要"                                                  │

│  ⑤ 模型选择硬约束:                                                    │
│     · 动作密集镜头 → 必须用海螺02·禁用静态模型(即梦4.0)               │
│     · 亚洲面部特写 → 即梦4.0优先                                      │
│     · 一镜到底长镜头 → Vidu Q2优先                                     │
│     · 模型选择错误导致渲染失败 → 不修提示词·换模型                     │
└──────────────────────────────────────────────────────────────────────┘
```

# 第三条：空间锚定优先于创意自由

> **优先级声明：** 参考图/空间地图中的物理事实 > 任何凭空描述的空间位置
> **编码依据：** Seko依赖参考图建立场景。任何与参考图不一致的空间描述都会导致渲染结果漂移。

## 3.1 规则定义

```
┌──────────────────────────────────────────────────────────────────────┐
│ 📜 画布第三条 · 不可违反                                              │
│                                                                      │
│  ① 所有空间位置必须可追溯参考图:                                       │
│     · 机位坐标 → 空间地图中标注·不穿墙·不悬空                         │
│     · 人物位置 → 在空间地图"人物可放置区域"内                         │
│     · 物体位置 → 在参考图中可见·或在OBJECT_TIMELINE中有来源            │
│                                                                      │
│  ② 所有光源必须有物理锚点:                                            │
│     · 自然光 → 窗户/门口·方向+角度可追溯参考图                        │
│     · 人工光 → 灯具/屏幕/火光·位置可追溯参考图                        │
│     · ❌ "感觉有一束光从上方照下来" → 光源无锚点·🛑                   │
│                                                                      │
│  ③ 场景结构元素一致性:                                                │
│     · 建筑结构(墙/柱/门/窗) → 与参考图一致                             │
│     · 固定家具(桌子/柜子/床) → 与参考图一致                            │
│     · 固定灯具(吊灯/壁灯/台灯) → 与参考图一致                          │
│     · 人物/人群/动态道具 → 可由剧本驱动·不受参考图空场景限制           │
│                                                                      │
│  ④ 参考图未覆盖空间的处理:                                            │
│     · 标注为"未确认" → 须补充物理属性(纵深/地面/尽头/宽度/天花板)      │
│     · 未标注物理属性的未覆盖空间 → 🛑 禁止进入视频提示词               │
│                                                                      │
│  ⑤ 禁止凭空编造空间描述:                                              │
│     · ❌ "远方有一座山" — 参考图中没有·凭空编造                       │
│     · ❌ "天花板上有一个天窗" — 参考图天花板不可见·未确认             │
│     · ❌ "角落有一盆植物" — 参考图角落看不清楚·风险描述               │
└──────────────────────────────────────────────────────────────────────┘
```

## 3.2 参考图锚定检测表

```
逐镜检测:
  □ 机位坐标: 是否在空间地图中有对应位置？
  □ 背景元素: 是否在参考图格中可见？
  □ 光源方向+色温: 是否在参考图/空间地图中有来源？
  □ 物体位置: 是否在OBJECT_TIMELINE中有存在性来源？
  □ 人物位置: 是否在空间地图"人物可放置区域"内？
  
4/5 ✅ → 通过
任一项❌ → 对应违规级别裁决
```

## 3.3 引用规范

Agent引用格式：`参照画布宪法第三条·空间锚定·[元素]锚定于[参考图格号/空间地图坐标]`

## 3.4 违反后果

- 机位穿墙/悬空 → 🛑 SPA-01阻断

# 第四条：运镜-画面分离

> **优先级声明：** 画面描述不含运镜语义·跨镜零引用·工程符号不进提示词
> **编码依据：** Seko的【生成指令】是逐段独立执行的。每段是独立的生成上下文——不知道上一段的长相和运镜。跨镜引用会造成Seko执行不确定性。

## 4.1 规则定义

```
┌──────────────────────────────────────────────────────────────────────┐
│ 📜 画布第四条 · 不可违反                                              │
│                                                                      │
│  ① 画面描述块不含运镜语义:                                            │
│     · ❌ "镜头缓缓推向她的脸" → 在画面描述中混入运镜                   │
│     · ✅ 画面描述: "面部大特写·浅景深·皮肤纹理清晰"                    │
│     · ✅ 📐运镜参数: "0.03x推近·3秒推约15cm"                          │
│     · 规则: 画面描述说"是什么"·📐参数卡说"怎么拍"                     │
│                                                                      │
│  ② 跨镜零引用:                                                        │
│     · ❌ "同上镜"·"参考上镜"·"如前所述"·"与镜#3同机位"               │
│     · ✅ 每镜独立完整描述·不依赖其他镜的上下文                         │
```

| Shot Architect | Shot Reviewer | 机位类型·覆盖策略·180度线·视线匹配 |
| Movement Designer | Movement Reviewer | 运镜类型·速度·空间可行性·7-DOF |
| Composition Designer | Visual Reviewer | 构图·光影·色彩·画面空间结构 |
| prompt_composer (场景台本) | Scene Script Auditor | 台本格式·铁律合规·参数可渲染性 |
| prompt_composer (故事版) | Storyboard Auditor | 帧间连续性·参考图锚定·快照完整性 |
| 🆕 prompt_composer (物体描述) | 🆕 Object Existence Verifier | 存在性来源·变化链·消失重现·终态一致 |
| 全局 (Step 9) | Cross-Scene Continuity Auditor | 跨场景锚点链·时间线连续 |
| 全局 (Step 9.5) | Render Packager (R00) | 格式完整性·引用有效性 |
| 全局 (Step 9-9.6后) | P-Verifier (Gate 0 + PASS 1-3) | 总体裁决·汇集所有审查报告 |

## 7.3 引用规范

Agent引用格式：`参照画布宪法第七条·独立验证·本验证由[Verifier名]执行·设计Agent推理不可见`

## 7.4 违反后果

- 设计Agent自我验证 → 验证结果无效·重新执行独立验证
- Verifier读取设计Agent推理过程 → 该轮验证无效·重置·重新隔离执行
- 管道中跳过任一Verifier → P-Verifier Judge检测阻断
