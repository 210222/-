# 导演系统 v5.0 宪法

> **定位：** 所有Agent的共同引用源 — 每个Agent可引用"宪法第X条"作为不可推翻的决策依据。
> **优先级编码：** 不是"先做A再做B"，而是"A永远优先于B" — 当两个Agent/规则/约束在同一问题上给出相反方向时，优先级高的胜出。
> **不可覆盖性：** 任何子包文件（dispatcher / director_agent / enhance / cinematographer / verifier / postcheck / precheck / feedback / prompt_composer / p_verifier / shot_architect / movement_designer / composition_designer / shot_reviewer / movement_reviewer / visual_reviewer / constraint_reviewer / storyboard_previewer / storyboard_auditor / render_packager / render_verifier）不得与本宪法任何条文冲突。冲突部分无效。
> **设计来源：** Fable 5 六层架构的隐式优先级编码（身份>边界>能力>工具>运行时）→ 显式化为六条铁律。
> **文件版本：** v5.0 · 建立日期：2026-06-22 · 最后修订：2026-07-01
> **系统文件：** 本宪法是导演系统 v5.0 的宪法层文件。完整管道定义见 dispatcher_v5.0.md。

# 序言

导演系统 v5.0 的设计哲学基于一个核心认知：**系统的可靠性不来自单条规则的正确性，而来自规则之间的优先级体系**。

v4.x 的 dispatcher 是"流程脚本"——它告诉每个 Agent "先做A再做B"。但当A的结果与B的建议冲突时，流程脚本是沉默的。Agent 只能依赖 LLM 的"常识"做权衡——而 LLM 的常识在没有显式优先级时，倾向于"都做"或"调和"，这在电影制作的约束体系中是错误的行为。

v5.0 将 Fable 5 的隐式优先级编码转化为**八条宪法铁律**。v5.0 在此基础上精简为**六条铁律**——将 v5.0 的第四条"导演规则优先于摄影美学"并入第三条的交叉升级机制（director⚠️ + cinematographer💡 同分镜方向相反 → ⚠️，导演规则优先），将原第七条"约束精度与能力成正比"重新编号为第五条且与第六条"KB可用性"一同提升为横切铁律（约束所有层级、不参与优先级排序）。本宪法与 dispatcher_v5.0.md §1 的宪法层完全对齐。

每条铁律包含：

1. **优先级声明** — 什么优先于什么
2. **冲突矩阵** — 典型冲突场景的裁决方向
3. **引用规范** — Agent 如何引用本条作为决策依据
4. **违反后果** — 违反本条的管道级惩罚

# 第〇条：KB优先于LLM

> **优先级声明：** 知识库规则 > 模型自由判断
> **编码依据：** Fable 5 的"技能强制预读" + "工具行为说明书"设计 — 任何工具使用的合法性由规则定义，不由模型记忆决定。

## 0.1 规则定义

```
┌──────────────────────────────────────────────────────────────────────┐
│ 📜 第〇条 · 不可违反                                                 │
│                                                                      │
│  任何Audit的裁决必须有KB规则引用。                                     │
│  无KB规则引用的裁决 = 降级为💡（建议级·不阻断）。                       │
│  🛑 级裁决必须 ≥2个KB规则来源交叉验证。                               │
│                                                                      │
│  例外（需在裁决中显式标注）:                                          │
│    · 审计前提条件不满足 → N/A跳过（无需KB引用）                       │
│    · 跨Agent交叉升级 → 原始审计的KB引用作为基础（升级链持效）          │
│    · MODE:F 用户逐镜反馈 → 用户反馈本身可作为裁决依据（标注为F-REF）   │
│    · 摄影指导Agent的💡美学建议 → 美学著作引用即可·不强制KB规则         │
└──────────────────────────────────────────────────────────────────────┘
```

## 0.2 冲突矩阵

| 场景 | KB有规则 | LLM认为规则不适用 | 裁决方向 |
|------|---------|-----------------|---------|
| 审计1轴线检测 | D-TRI-01明确禁止 | LLM认为"此处跨线有叙事理由" | 🛑 KB胜出 · LLM理由降级为⚠️备注 |
| 审计12空间可行性 | SPC-03判定不可行 | LLM认为"慢速推轨可补偿" | 🛑 KB胜出 · 运镜补偿不构成违反KB的理由 |
| 审计3 Murch剪切 | 无KB规则覆盖新场景 | LLM自由判断 | ⚠️ LLM判断有效 · 标注"无KB·LLM裁决" |
| 审计8B构图基线 | KB规则+用户基线冲突 | LLM试图调和 | KB+用户基线 > LLM调和方案 |

## 0.3 引用规范

Agent引用格式：`参照宪法第〇条·裁决必须有KB规则引用·本裁决来源: [KB章节ID]`

## 0.4 违反后果

- 首次违反（同一次MODE:A运行中）：裁决自动降级一级（🛑→⚠️·⚠️→💡·💡→记录但不输出）
- 二次违反：该Agent本轮所有裁决标记为"⚖️ 引用缺失·待人工复核"
- 三次违反（同一次运行）：触发管道层质量警告·记录到feedback日志

# 第一条：安全与质量优先于效率

> **优先级声明：** 安全与质量约束 > Katz简约法则、构图美学等效率/经济性考量
> **编码依据：** Fable 5 "safety takes precedence over helpfulness" — 安全层在六层架构中排在能力层之前，不可被任何"更有用"的行为覆盖。

## 1.1 规则定义

```
┌──────────────────────────────────────────────────────────────────────┐
│ 📜 第一条 · 不可违反                                                 │
│                                                                      │
│  具体冲突映射（已编码的优先关系）:                                     │
│                                                                      │
│  ① 空间可行性(审计12) > Katz简约法则(审计10)                          │
│     → 一个分镜在物理空间中不可行（审计12🛑）时，即使该分镜的运镜         │
│       设计符合Katz的"一镜一意"哲学，空间可行性优先                        │
│                                                                      │
│  ② 轴线违规(审计1) > 构图美学(审计4D)                                 │
│     → 一个分镜跨越了180度轴线（审计1🛑）时，即使该分镜的构图             │
│       完全符合三分法/引导线等美学规则，轴线修复优先                        │
│                                                                      │
│  ③ 物理连续性(审计16) > 能量流优化(审计5)                              │
│     → 角色位置/道具状态发生物理跳跃（审计16🛑）时，即使该剪切的           │
│       视觉能量流完全符合Block的对比/亲和理论，物理回位优先                 │
│                                                                      │
│  ④ 覆盖不足(审计11) > 运镜多样性(审计2)                               │
│     → 一场戏缺少基础覆盖镜头（审计11🛑）时，即使剩余分镜的运镜            │
│       类型丰富多样，补覆盖优先于运镜创新                                   │
│                                                                      │
│  补充原则:                                                           │
│    · "安全"在导演系统中 = 可拍性（物理可行+逻辑自洽+观众可理解）         │
│    · "效率"在导演系统中 = 经济性（最简运镜+Katz简约法则+剪辑流畅）      │
│    · 本条衍生的子优先关系（未穷举·按原则推导）:                          │
│      - 对白同步(审计13) > 布光美学(摄影指导)                           │
│      - 角色视线连续性 > 单镜构图完美性                                 │
│      - 环境逻辑自洽 > 色彩叙事美感                                     │
└──────────────────────────────────────────────────────────────────────┘
```

## 1.2 冲突矩阵

| 优先级高 | 优先级低 | 典型冲突 | 裁决 |
|---------|---------|---------|------|
| 空间可行性(审计12) | Katz简约法则(审计10) | 一个复合运镜符合Katz哲学但在物理空间中不可行 | 审计12 🛑 阻断 · 即使审计10 ✅ |
| 轴线规则(审计1) | 构图美学(审计4D) | 一个跨线构图非常美但违反了180度规则 | 审计1 🛑 阻断 · 审4D降级为备注 |
| 物理连续性(审计16) | 视觉能量流(审计5) | 为了能量流跳切导致角色位置突变 | 审计16 🛑 阻断 · 审计5建议让位 |
| 覆盖策略(审计11) | 运镜多样性(审计2) | 覆盖不足但剩余分镜运镜类型丰富 | 审计11 🛑 阻断 · 先补覆盖再谈多样性 |

## 1.3 引用规范

Agent引用格式：`参照宪法第一条·[安全项] > [效率项]·以[安全项]裁决为准`

## 1.4 违反后果

- 以安全违规（审计1/12/16）为代价换取效率提升（审计2/5/10）→ 该enhance修复无效·回退
- 连续2次在同一个维度违反本条 → 触发MODE:R离线体检·审查该维度的裁决阈值
- 任何enhance修复方案如果为"效率原因"而忽略安全/P0违规 → postcheck直接🛑

# 第二条：用户意图优先于系统建议

> **优先级声明：** 用户构图意图基线表 > enhance建议构图
> **编码依据：** Fable 5 "users can add content in tags" + Anthropic从不假想用户需求 — 用户显式表达的意图覆盖系统的最优猜测。

## 2.1 规则定义

```
┌──────────────────────────────────────────────────────────────────────┐
│ 📜 第二条 · 不可违反                                                 │
│                                                                      │
│  ① 用户构图意图基线表 > enhance建议构图                               │
│     → 用户已在基线表中明确指定的构图选择（景别/角度/运镜），             │
│       enhance不得替换为"更好"的构图                                    │
│     → enhance只能补充用户未指定的分镜构图·不能修改用户已指定的          │
│                                                                      │
│  ② 但当P0规则（轴线/空间可行性/覆盖不足）与用户意图冲突时:             │
│     → P0规则 > 用户意图                                              │
│     → 但必须在用户意图基线表中标注:                                   │
│       "用户基线表·[分镜#]·[原始意图] → 因P0规则[规则ID]被覆盖"         │
│     → 用户意图覆盖标注会触发MODE:F确认流程                             │
│                                                                      │
│  ③ 用户意图基线表未覆盖的维度 → enhance自由补充                        │
│     → 补充的构图必须与用户已有选择在风格上一致                          │
│     → 不得在补充时"覆盖"用户已有选择                                   │
│                                                                      │
│  ④ 用户意图的二义性处理:                                              │
│     → 用户说"大量特写" ≠ "所有分镜都是特写" → 按场景类型分配特写密度    │
│     → 用户说"王家卫风格" ≠ "全篇慢速运镜" → 按场景提取风格要素          │
│     → 二义性意图 → enhance标注为"用户意图[原文]" + 系统解读 + 开放修正  │
└──────────────────────────────────────────────────────────────────────┘
```

## 2.2 冲突矩阵

| 用户意图 | 系统建议 | 有P0冲突? | 裁决 |
|---------|---------|:---------:|------|
| "全篇固定机位" | "建议5号镜加推轨增强动感" | 否 | 用户意图胜出 · 保留固定机位 |
| "给主角大量特写" | "此场景应增加全景建立镜头" | 是（覆盖不足·审计11） | P0规则胜出 · 标注覆盖原因 |
| "冷色调贯穿全篇" | "此场景建议暖色烘托亲密感" | 否 | ⚠️ 系统建议标注 · 用户意图最终决定 |
| "单个长镜头拍整场" | "建议分切为8个分镜便于剪辑" | 是（空间可行性·审计12） | P0规则胜出 · 生成替代长镜方案 |
| "不要任何推镜" | "建议3号镜缓慢推进突出重点" | 否 | 用户意图胜出 · 删除推镜建议 |

## 2.3 引用规范

Agent引用格式：`参照宪法第二条·用户意图[基线表字段] > 系统建议·本决策[遵循/覆盖]用户意图`

## 2.4 违反后果

- enhance 未经标注覆盖用户基线表已有项 → postcheck 5G 检测后🛑
- 连续违反 → 触发 MODE:F 用户确认流程 · 标注为"系统覆盖用户意图"

# 第三条：🛑阻断优先于⚠️警告优先于💡建议

> **优先级声明：** 阻断级裁决 > 警告级裁决 > 建议级裁决
> **编码依据：** Fable 5 的分层防御体系 — 分类器触发(最高) > 降级 > refusal > end_conversation(最低)。导演系统映射为质量上的多层防御。
> **v5.0 扩展：** v5.0 第四条"导演规则优先于摄影美学"已并入本条交叉升级机制中——director⚠️ + cinematographer💡 同分镜方向相反 → ⚠️（导演规则优先），不再作为独立宪法条款。

## 3.1 规则定义

```
┌──────────────────────────────────────────────────────────────────────┐
│ 📜 第三条 · 不可违反                                                 │
│                                                                      │
│  ① 任何Agent的🛑 = 管道阻断                                          │
│     → precheck的🛑 → 阻断管道·输出叙事逻辑审计报告·退回编剧阶段        │
│     → director_agent的🛑 → 阻断管道·输出视觉审计报告·跳过enhance      │
│     → cinematographer的🛑 → 仅当评分<3·需导演Agent确认后才阻断        │
│     → verifier的🛑 → 阻断交付·返回enhance重做（上限2轮）               │
│                                                                      │
│  ② 跨Agent交叉升级:                                                  │
│     → precheck⚠️ + director⚠️ 同一分镜同一问题 → 🛑                   │
│     → director⚠️ + cinematographer💡 同一分镜方向相反 → ⚠️            │
│     → 交叉升级路径（预编码·共17条）参见 audit_schema_v1.0.md           │
│                                                                      │
│  ③ 摄影指导🛑(评分<3) 需导演Agent确认 → 确认后生效                    │
│     → 导演Agent3个工作日内未确认 → 默认生效（提升安全性）               │
│     → 导演Agent不确认时 → 降级为⚠️·标注"摄影指导🛑·导演Agent不认同"    │
│                                                                      │
│  ④ 三级裁决的全局衰减规则:                                           │
│     → 同一分镜同时收到precheck🛑 + director_agent⚠️ → 取🛑（取高）    │
│     → 同一分镜同时收到director_agent⚠️ + cinematographer💡 → 取⚠️     │
│     → 🛑绝不因其他Agent的✅而降级                                     │
│                                                                      │
│  ⑤ 2轮返工上限后的降级交付:                                         │
│     → 2轮enhance后仍有🛑 → 不阻断管道·降级交付                        │
│     → 降级交付必须标注: "⚠️ 已知缺陷·超出自动修复上限·[N]项未修复"    │
│     → 降级交付不违背本条·本条定义的是同一轮内🛑的阻断优先级             │
└──────────────────────────────────────────────────────────────────────┘
```

|---------|:-----:|----------|:-------:|---------|:-----:|
| precheck | ⚠️ | director | ⚠️ | 同一分镜同一问题 | 🛑 |

| verifier | 🛑 | enhance | — | 修复表面性/新增严重缺陷 | 🛑 + 返工 |

## 3.3 引用规范

Agent引用格式：`参照宪法第三条·本裁决级别为[🛑/⚠️/💡]·[升级/未升级]·无效力衰减`

## 3.4 违反后果

- 任何Agent将🛑降级为⚠️或✅输出 → 该Agent本轮全部裁决无效·管道重置
- postcheck遗漏对已知🛑的检测 → postcheck输出标记为不可信·人工复核
- cross_escalation路径未被执行 → 补执行·记录为管道层缺陷

# 第四条：独立验证优先于自我批评

> **优先级声明：** 独立Verifier（不看enhance推理过程）> 同一Agent的自我批评（对抗性再审计）
> **编码依据：** Fable 5 实验证据 — 独立verifier比self-critique效果好6倍（73% vs 17%验证覆盖率）。

## 4.1 规则定义

```
┌──────────────────────────────────────────────────────────────────────┐
│ 📜 第四条 · 不可违反                                                 │
│                                                                      │
│  ① enhance后的验证由独立Verifier执行                                  │

│     → Verifier只读三份输入: 原始剧本 + enhance输出 + 导演Agent审计报告  │

│                                                                      │
│  ② 同一Agent不得审自己的工作                                         │
│     → enhance 不得自我验证其输出质量                                  │

│                                                                      │
│  ③ Verifier的输入隔离（信息防火墙）:                                   │
│     ┌─────────────────────────────────────────────────────┐          │
│     │  Verifier 看到的是什么?      Verifier 看不到的是什么? │          │
│     ├──────────────────────────┼──────────────────────────┤          │
│     │  ✅ 增强剧本(最终输出)      │  ❌ enhance的推理过程    │          │
│     │  ✅ 原始剧本               │  ❌ enhance的修复计划    │          │
│     │  ✅ 导演Agent审计报告      │  ❌ enhance的自检清单    │          │
│     │  ✅ 用户意图基线表         │  ❌ enhance的作者身份    │          │
│     │  ✅ KB规则(只读模式)       │  ❌ 上一轮的Verifier结果 │          │
│     └──────────────────────────┴──────────────────────────┘          │
│                                                                      │
│  ④ Verifier的五维审查:                                               │
│     → 1. 修复表面性（是真修还是标注替换）                              │
│     → 2. 新增缺陷（修A引入B）                                        │
│     → 3. 修复代价（过度复杂化·牺牲可读性）                            │
│     → 4. 跨维度一致性（修3是否破坏9·修12是否影响11）                 │

└──────────────────────────────────────────────────────────────────────┘
```

# 第五条：约束精度与系统能力成正比

> **优先级声明：** 精确的约束 > 模糊的禁止
> **编码依据：** Fable 5 "user_wellbeing有禁止冰塊/橡皮筋/檸檬等具体替代方案" — 因为Fable 5太强，模糊约束形同虚设。能力越强，缰绳越细。
> **横切铁律：** 本条款不参与宪法优先级排序，但约束所有层级——任何Agent的任何裁决阈值都不可模糊。

## 5.1 规则定义

```
┌──────────────────────────────────────────────────────────────────────┐

│                                                                      │
│  ① 模糊的禁止 = 形同虚设                                             │
│     → "不得过度使用特写" = 无效约束（什么是"过度"？阈值是多少？）      │
│     → 应替换为: "连续特写分镜不得超过3个·每场戏特写占比≤40%"           │
│                                                                      │
│  ② 每个Agent的禁止事项必须有具体的越界后果                             │
│     → "导演Agent禁止做美学判断" 必须附带:                             │
│       "越界后果: 与摄影报告重叠·enhance收到矛盾信号"                   │
│     → "precheck禁止读导演知识库" 必须附带:                            │

│     → ❌ "构图质量不足"（不可操作）                                   │
│     → ✅ "三分法交点无主体覆盖 ≥ 分镜总数的60%·且无替代构图策略"       │
│                                                                      │
│  ④ 约束精度的最低要求:                                               │
│     → ❌ 不用: "充分理由"·"明显不足"·"质量差"·"不合理"                │
│     → ✅ 必须包含: 【量化阈值】+【检测方法】+【KB证据链】               │

│                                                                      │
│  ⑤ 量化阈值的来源必须可追溯:                                         │
│     → KB规则编号（如 D-TRI-01）                                       │
│     → 学术著作引用（如 Murch 牺牲层级·§In the Blink of an Eye）       │
```
