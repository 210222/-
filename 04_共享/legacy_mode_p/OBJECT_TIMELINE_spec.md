# OBJECT_TIMELINE 格式规范 v1.0

> **定位:** OBJECT_TIMELINE_[剧本名].md 的格式规范。Step 0.5(调度器自执行)按此规范生成，Object Existence Verifier(Step 9.6)按此规范消费。
> **设计依据:** 画布宪法第六条(物体存在链)·dispatcher Step 0.5 + Step 9.6
> **版本:** v1.0 · 2026-07-05

---

## §1 文件格式

### 1.1 文件命名

```
OBJECT_TIMELINE_[剧本名].md

示例: OBJECT_TIMELINE_枪王EP8.md
```

### 1.2 文件结构

```markdown
# 物体存在链 · [剧本名]

> 生成时间: [ISO时间戳]
> 生成方式: Step 0.5·调度器自执行
> 场景数: [N] · 总镜数: [M] · 物品总数: [K]
> 人物表随身物品: [角色名]: [物品清单] (🅱-A)

---

## 场景[N]: [场景名]

### 参考图物品清单 (🅰类)

| O-ID | 物品名 | 存在来源 | 参考图格位 | 初始状态 | 备注 |
|------|--------|:------:|----------|------|------|
| O-XX | ...    | 🅰      | 格N       | ...   | ... |

### 动态物品清单 (🅱🅲类)

| O-ID | 物品名 | 存在来源 | 首次镜# | 初始状态 | 变化链 | 最终状态 | 验证状态 |
|------|--------|:------:|:-----:|------|------|------|:------:|
| O-XX | ...    | 🅱-A    | #1    | ...   | #N→... #M→... | ... | ✅/⚠️ |

### 场景末状态快照

| O-ID | 物品名 | 场景末状态 | 位置 | 携带者(如随身) |
|------|--------|------|------|------|
| O-XX | ...    | ...   | ...   | ... |

---

## 全剧物品索引

| O-ID | 物品名 | 类别 | 首次出现 | 最后出现 | 跨场景 | 最终状态 |
|------|--------|------|:---:|:---:|:---:|------|
| O-XX | ...    | ...   | S1#1 | S2#5 | ✅/❌ | ... |
```

## §2 字段定义

### 2.1 O-ID (物品唯一标识)

```
格式: O-[序号]  (三位数字·不足补零)
示例: O-001, O-042, O-103

分配规则:
  · 按物品首次出现的场景顺序分配
  · 同一物品跨场景 → 只分配一个O-ID·在首次出现场景中定义
  · 序号全局唯一·不按场景重置
```

### 2.2 存在来源编码

```
🅰-格位    = 参考图已存在
  → 标注参考图格位编号
  → 如多格可见同一物品·标注主要格位
  → 例: 🅰-格3

🅱-A       = 随身物品·人物表声明
  → 剧本人物表"随身物品"字段中显式列出
  → 最高置信度·自动通过

🅱-B-N#    = 随身物品·行为推断
  → 从剧本中角色"掏出/拿出/使用/穿戴"等行为推断
  → N#为推断来源的镜号
  → 例: 🅱-B-#3 (境#3中Rico从口袋掏出照片)

🅱-B-OCC   = 随身物品·职业默认
  → 警察→配枪·手铐·警徽·对讲机
  → 医生→听诊器·白大褂
  → 律师→公文包·文件
  → 标注职业和推断依据

🅱-B-APP   = 随身物品·外貌推断
  → 从角色外貌描述推断(眼镜·手表·戒指·耳环)
  → 标注外貌描述所在的镜#

🅲-N#      = 场景引入
  → 在镜#N中被首次引入场景
  → 必须有引入方式描述("拿出/摆上/倒入/打开/脱下/放下")
  → 例: 🅲-#2 (镜#2中Rico把档案文件夹放在桌上)

⚠️-LVLC    = Level-C·不确定
  → 无法从以上来源确定·需人工确认
  → 标注不确定的原因
  → 例: ⚠️-LVLC (参考图格5中有一模糊小物件·可能是打火机也可能是U盘)
```

### 2.3 变化链格式

```
格式: 镜#→新状态 (多个变化以空格分隔)

示例:
  #3→半空 #5→空                    — 两次状态变化
  #6→拔出·放在桌上                  — 一次变化中的复合动作
  #2→打开 #7→合上 #9→再次打开       — 三次状态变化
  —                                 — 无变化(静态物品)

变化类型标注(可选·用于复杂变化):
  [消耗]: #3→喝了一口·半空 #5→喝完·空
  [转移]: #6→拔出(从枪套)→放置(桌上)
  [变形]: #2→推门·门开 #7→关门·合上
  [生成]: #4→倒入咖啡·杯子从空变满
  [消失]: #8→被Rico收进抽屉·从画面消失
```

### 2.4 最终状态

```
描述物品在场景结束时的状态 + 位置:

格式: [状态描述]·[位置]·[携带者(如随身)]

示例:
  "空·桌上"                           — 静态物品
  "满·Rico手中"                       — 角色手持
  "枪套中·Rico腰间"                    — 随身物品·未取出
  "散落·工作台面·部分零件在盒中"        — 复杂状态
  "已被Rico带走·跨场景延续"            — 跨场景物品
```

## §3 提取方法论 (Step 0.5执行指南)

### 3.1 提取流程

```
Step 0.5A: 人物表随身物品提取
  1. Read 剧本【人物表】
  2. 逐角色提取"随身物品"字段
  3. 每件物品 → 分配O-ID → 标记🅱-A
  4. 如人物表无"随身物品"字段 → 标注⚠️·建议补充

Step 0.5B: 参考图物品扫描
  1. Read 所有场景参考图
  2. 逐格标注可见物品:
     · 固定家具(桌/椅/柜/床/沙发)
     · 固定灯具(吊灯/壁灯/台灯/落地灯)
     · 装饰物(画/钟/花瓶/植物/窗帘)
     · 散落物品(书/杯子/文件/工具/杂物)
  3. 每件物品 → 分配O-ID → 标记🅰-格位

Step 0.5C: 剧本物品扫描 (核心·最耗时)
  1. Read 剧本全文(包含MODE:A增强剧本的镜头方向卡)
  2. 逐场景·逐镜扫描:
     a. 提取所有名词短语(物理实体)
     b. 过滤: 人物/自然现象/抽象概念/声音
     c. 保留: 可触知的·有物理形态的·可被看见的物品
  3. 每件物品 → 在已有O-ID中查找匹配:
     a. 找到匹配 → 记录出现镜号·检查状态变化
     b. 未找到 → 判定存在来源:
        · 参考图中有? → 补充到🅰类
        · 角色从身上取出? → 🅱-B(行为推断)
        · 背景中自然存在? → 🅲(场景引入)
        · 不确定 → ⚠️ LEVEL-C

Step 0.5D: 行为推断随身物品
  1. 扫描剧本中所有"掏出/拿出/取出/摘下/戴上/打开(随身物品)"动作
  2. 动作对象如果是未标记物品 → 推断为随身 → 🅱-B
  3. 标注推断推理链: "镜#N中[角色]从[身上部位]掏出[物品]"
  4. 职业默认随身 → 🅱-B-OCC·标注职业字段

Step 0.5E: 变化链构建
  1. 对于每个物品·追踪其每次出现时的状态描述
  2. 状态发生变化 → 记录变化事件(镜#→新状态)
  3. 注意: "没有描述状态变化" ≠ "状态没变" · 需要区分
  4. 如台本中物品存在但状态未描述 → 标注"状态未描述·假设不变"

Step 0.5F: 完整性检查
  1. 所有O-ID全局唯一？
  2. 所有🅰物品都有参考图格位标注？
  3. 所有🅱物品都有推断依据标注？
  4. 所有🅲物品都有引入镜#和引入方式标注？
  5. 所有⚠️ LEVEL-C都有不确定原因标注？
  6. 变化链格式正确？
  7. 最终状态都已填写？
  8. 场景末状态快照完整？
```

### 3.2 物品名称规范

```
命名规则(避免Object Existence Verifier匹配失败):

  ✅ 使用具体名称:
    "格洛克17手枪" 优于 "手枪"
    "白色陶瓷咖啡杯" 优于 "杯子"
    "深木色长方形办公桌" 优于 "桌子"
  
  ⚠️ 名称中包含关键特征以区分类似物品:
    "Rico的咖啡杯" vs "律师的咖啡杯"
    "桌上的文件" vs "Rico手中的文件"
  
  ❌ 避免泛化名称:
    "家具" → 拆解为具体家具
    "杂物" → 列出具体杂物
    "装饰品" → 列出具体装饰品

  同一物品的多个名称 → 在备注中记录同义词:
    例: O-005 | "格洛克17" | ... | 备注: 同义词="手枪""配枪""Rico的枪"
```

### 3.3 排除规则

```
以下不纳入OBJECT_TIMELINE:

  ❌ 人物/角色 (有人物表独立管理)
  ❌ 自然现象 (雨/雪/雾/阳光/闪电·属于光源和环境验证)
  ❌ 抽象概念 ("气氛""情绪""感觉")
  ❌ 纯声音 (如声音源不在画面中 → 不纳入·音轨管理)
  ❌ 身体部位 (手/脸/眼睛/头发 → 属于人物描述)
  ❌ 临时性·一次性出现且不可追踪的物品
     (如"一片落叶飘过"·但如果落叶反复出现就需要追踪)
  ❌ 群演随身物品 (群演的通用物品·除非剧本特别强调)
  ❌ 食物/饮料的一次性提及 (如"午餐""一杯水"且后续不再出现)
```

## §5 常见陷阱

### 陷阱1: OBJECT_TIMELINE漏提物品导致V5误报

```
症状: Object Existence Verifier报告OBJ-01(凭空出现)·但物品实际上在参考图中
原因: Step 0.5扫描参考图时遗漏
修复: 补充OBJECT_TIMELINE·重新运行验证
预防: Step 0.5B需逐格仔细标注·不要只扫"主要物品"
```

### 陷阱2: 同一物品的不同名称导致匹配失败

```
症状: OBJECT_TIMELINE记录"格洛克17"·台本描述"手枪"·验证器报告OBJ-01
原因: 名称不匹配
修复: OBJECT_TIMELINE备注中记录同义词·或验证器使用语义匹配
预防: 提取时记录台本中实际使用的名称作为同义词
```

### 陷阱3: 状态变化被遗漏

```
症状: 验证器报告OBJ-03(状态跳跃)·但实际上中间有描述
原因: Step 0.5C扫描时遗漏了变化描述
修复: 逐镜仔细追踪物品状态·更新变化链
预防: 对于OBJ_TIMELINE中的"关键物品"(武器/文件/饮品)·逐镜确认状态
```

### 陷阱4: 跨场景物品被当作新物品

```
症状: 场景B中出现了场景A的物品·OBJECT_TIMELINE给分配了新O-ID
原因: 未识别为同一物品
修复: 合并O-ID·记录跨场景延续
预防: 场景末状态快照中标记"已被[角色]带走·跨场景延续"的物品·下一场景以此为基础
```
