# MODE:P v8.0 — 导演协作循环

> 导演设计 → DP审查(自然语言) → 导演修改 → DP确认 → 交付故事板+视频提示词

---

## 循环

```
导演读剧本 → 出场景设计(含故事板+视频提示词)
              ↓
         DP审查 → 自然语言反馈
              ↓
    DP说"没问题" → 交付
    DP有问题   → 导演修改 → DP再审 → ... → 交付
```

循环结束的唯一条件：**DP说"没问题"**。没有max_rounds·没有block_count·没有收敛公式。

---

## 两个Agent

### 导演
- 加载 `03_知识库/导演手册_视觉叙事决策框架.md` 作为内化知识
- 产出: 故事板提示词 + 视频提示词(完整场景设计·一个文档)
- 三个工作阶段:
  - **draft**: 读剧本→首次设计
  - **revise**: 读DP反馈→修改设计
  - **fix**: 读SD2.0兼容性问题→定向修复(极少触发·因为SD2.0约束已内化)

### 摄影指导(DP)
- 加载 `03_知识库/导演手册_视觉叙事决策框架.md` 作为内化知识
- 审查维度(内化的思考框架·不作为输出格式):
  - 空间可行: 机位穿墙？运镜越界？光源锚定？
  - 视觉连续: 关系线同侧？动作方向一致？视线匹配？
  - 运镜: 运动有动机？速度匹配空间？
  - 构图: 景别合适？视觉重心清晰？
  - 光影: 色温匹配情绪？光比连贯？
  - SD2.0: 正向描述？≤15秒？
- 输出: 自然语言反馈(几句话·指出问题和建议)

---

## 调用方式

调度器(人 or 主会话)用Agent工具分别调用导演和DP。调度器只做三件事:
1. 启动导演 → 拿到场景设计
2. 启动DP → 拿到反馈
3. 如果DP说"没问题" → 交付。否则 → 回步骤1(导演revise阶段)

调度器不做: 复杂度判定·收敛计算·格式检查·正则扫描·审计·声明。

---

## 交付物

1. **故事板提示词** — 逐镜·逐秒·画面描述(正向语言)+运镜+构图+光影+转场
2. **视频提示词** — 逐镜·逐秒(0.5s网格)·画面描述(正向语言)+音轨方向+转场

无审计报告·无YAML·无合规检查清单·无Gate 0报告。

---

## SD2.0兼容性

导演内化了SD2.0的知识(所有token视为正向指令·无否定词架构·15秒硬上限·多人面部≤2人·文字不可渲染)。DP审查时也会自然地发现兼容性问题。

不设确定性扫描脚本——如果DP或导演漏掉了某个SD2.0问题，这是创作过程中的疏漏，在DP审查时会被发现和纠正。
