# MODE:P v8.0 Final — 导演协作循环系统

> **定位：** 用最少的大模型注意力，产出最好的场景视觉设计。
> **核心洞察：** 知识内化 > 规则检索 · 自然对话 > 结构化审计 · 导演直觉 > 合规检查。
> **版本：** v8.0-final · 2026-07-15

---

## 系统概述

```
剧本 + 空间地图 + 参考图
        │
        ▼
┌──────────────────┐     ┌──────────────────┐
│   导演 Agent      │────→│   DP Agent       │
│   (创作·设计)     │←────│   (审查·反馈)     │
│                  │     │                  │
│ 知识内化:         │     │ 知识内化:         │
│ · 运镜 (8类型·S0-S8) │  │ · 空间可行性       │
│ · 构图 (6景别·7原则)  │  │ · 视觉连续性       │
│ · 光影 (5光源·色温光比)│  │ · 运镜动机         │
│ · 切换 (6类型·4铁律)  │  │ · 构图清晰度       │
│ · SD2.0渲染铁律      │  │ · 光影锚定         │
│                  │     │ · SD2.0兼容性      │
└──────────────────┘     └──────────────────┘
        │                       │
        │     DP:"没问题"        │
        ▼                       ▼
   故事板提示词 + 视频提示词     自然语言反馈 → 导演修改
   (最终交付)                  (回到导演继续循环)
```

**只有 2 个 Agent。只有 2 个产出文件。没有其他任何东西。**

## 快速开始

### 所需输入

启动前准备三个文件：
1. **剧本文本**：场景的对白和动作描述（.txt/.md）
2. **空间地图**：房间尺寸、门窗位置、家具布局、光源位置（.md）
3. **参考图描述**：空间照片的文本描述（.md）

### 执行步骤

```
1. 读取输入文件
2. 用 director_agent.md 作为 system prompt，启动导演Agent（draft模式）
   → 输入：剧本 + 空间地图 + 参考图描述
   → 输出：完整场景设计（故事板提示词 + 视频提示词）
3. 用 dp_agent.md 作为 system prompt，启动DP Agent
   → 输入：导演的场景设计 + 空间地图
   → 输出：自然语言反馈
4. 判断DP反馈：
   ✅ "没问题" → 交付故事板提示词 + 视频提示词
   🔄 有修改意见 → 将反馈传给导演（revise模式）→ 回到步骤3
5. 最多5轮。第5轮仍未通过 → 强制交付，标注已知问题
```

### 传递给导演的内容

**draft 模式（首次设计）：**
```
你看到的信息：
- 剧本：[剧本内容]
- 空间地图：[空间地图内容]
- 参考图描述：[参考图描述内容]

请进入 draft 阶段，设计完整的场景。产出包含故事板提示词和视频提示词两部分。
```

**revise 模式（DP反馈后修改）：**
```
你看到的信息：
- 剧本、空间地图、参考图描述（同上）
- 你上一版的场景设计：[上一版设计全文]
- DP审查反馈：[DP的反馈全文]

请进入 revise 阶段。逐条处理反馈。
```

### 传递给DP的内容

```
你看到的信息：
- 导演的场景设计：[设计全文]
- 空间地图（供参考）：[空间地图内容]

请审查这份场景设计。用自然语言给反馈，像片场沟通一样。
```

## 关键设计原则

### 知识内化 > 规则检索
Agent 的 system prompt 中嵌入了全部所需的电影摄影知识和SD2.0约束。Agent 不读KB文件、不引用规则ID、不做合规检查。知识是直觉，不是法典。

### 自然对话 > 结构化审计
导演和DP之间的通信是自然语言。没有YAML、没有JSON、没有审计报告格式。DP说"镜3穿桌了"——不是说"维度一（空间可行性）：block_count=1"。

### 循环是自然的
循环的唯一结束条件是DP说"没问题"。没有max_rounds收敛算法、没有block_count判定、没有Gate 0正则扫描。上限5轮是安全网，不是控制机制。

### 所有约束内化
SD2.0的铁律（正向语言、无否定词、≤15秒、≤2面部）内化在导演的"本能"和DP的"眼睛"中。不需要确定性扫描脚本——如果导演漏了"不要"这个词，DP会自然地指出来。

## 与v7.2的对比

| 维度 | v7.2（旧） | v8.0-final（新） |
|------|-----------|-----------------|
| Agent数量 | ~18个 | **2个** |
| 协议层 | 11层（YAML/审计/合规/缓存/复杂度路由） | **0层** |
| 输出格式 | YAML + .md 双文件 + 审计报告 | **自然语言** |
| 知识获取 | Agent Read KB文件 → 检索规则 → 引用规则ID | **System prompt嵌入 → 内化为直觉** |
| 质量保证 | Gate 0正则 + SDA + SSA + 5专家 + 多方会诊 | **DP自然语言审查** |
| 循环控制 | max_rounds=2 + block_count + 收敛判定 | **DP说"没问题"即交付** |
| Token消耗（7镜·31秒） | ~875K（指令+执行） | **~50-100K（预估）** |
| 纯浪费占比 | ~72.4% | **~10-20%（预估）** |
| 交付物 | 10+文件（台本·PLAN·审计·验证·打包） | **2文件（故事板+视频）** |
