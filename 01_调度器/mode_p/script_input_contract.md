# Script Input Contract v1.0

> 本文档定义 MODE:P 系统的剧本输入契约。它是 L0（剧本锁定）的机械边界，由本地解析器实现，不消耗 LLM 调用。
> 剧本是唯一叙事真源。本契约保证每个事实都有原文定位，同时明确解析器能力的硬边界。

## 1. 文件编码

| 优先级 | 编码 | 说明 |
|---|---|---|
| 1 | UTF-8 with BOM | BOM 自动剥离，不进入事实文本 |
| 2 | UTF-8 without BOM | 直接读取 |
| 3 | GBK / GB2312 | 回退编码；仅当 UTF-8 解码失败时尝试 |
| — | 其他编码 | 不自动猜测；解析失败时报告 `encoding: unknown` 并请求用户提供 UTF-8 或 GBK 版本 |

解析器必须尝试 UTF-8 后再尝试 GBK；不得使用 `chardet` 等统计猜测库，也不得静默替换不可解码字节。

## 2. 场景边界识别

### 2.1 场景标题模式（按优先级）

解析器按以下顺序匹配，第一个匹配的行开始一个新场景：

| 优先级 | 模式 | 示例 | 说明 |
|---|---|---|---|
| 1 | `^##\s+Scene\b` | `## Scene 3` | Markdown 二级标题 + Scene 关键字 |
| 2 | `^##\s+第.+场` | `## 第三场` | 中文数字场景标题 |
| 3 | `^#+\s+第.+场` | `# 第一场` | 任意级别 Markdown 标题 + 中文场景 |
| 4 | `^(INT\.\|EXT\.\|INT/EXT\.\|EXT/INT\.)\s` | `INT. 刑警总部 - 日` | 标准影视剧本场景头 |
| 5 | `^【场景.*】` | `【场景2：案情室】` | 中文括号场景标记 |
| 6 | `^场景\s*\d+` | `场景 4` | 中文场景编号 |

### 2.2 场景边界规则

1. **显式边界**：匹配上述任一模式的标题行，场景从标题行开始，到下一个场景标题行或文件末尾结束。
2. **隐式边界**：当剧本使用空行分隔但无明确标题时，解析器不自动切分。整段文本标记为 `unresolved: implicit_scene_boundary` 并请求用户标注。
3. **嵌套标题**：如果 `## Scene 2` 内部出现 `### 小节`，小节不创建新场景；仅同级或更高级标题触发切分。
4. **前置内容**：第一个场景标题之前的文本（扉页、人物表、前言）归类为 `front_matter`，不参与场景处理。
5. **空场景**：连续两个场景标题之间无实质内容（仅空白行），第二个标题生效，空场景不登记。

### 2.3 场景标题内的元数据提取

如果标题行包含以下信息，解析器提取但不解释：

| 字段 | 模式 | 提取为 |
|---|---|---|
| 场景编号 | `Scene\s*(\d+)` 或 `第(\d+|[一二三四五六七八九十]+)场` | `scene_number` (int) |
| 地点 | 标题中 `-` 或 `—` 之后的文本，或 `INT./EXT.` 之后、`-` 之前的文本 | `location_hint` (str) |
| 时间 | `-\s*(日\|夜\|晨\|黄昏\|傍晚\|凌晨)` | `time_hint` (str) |

以上均为可选字段。缺少时不补全，标记为 `null`。

## 3. 原文行号

### 3.1 行号规则

1. 行号从 1 开始计数（非 0）。
2. 空行计入行号；BOM 字符不计入任何行。
3. 每个场景记录其起始行号和结束行号（闭区间 `[start_line, end_line]`）。
4. `SCRIPT_FACTS.md` 中的每项事实必须标注原文行号；单行可写 `[Lx]`，跨行写 `[Lstart-Lend]`。
5. 事实引用的行号范围必须在该场景的 `[start_line, end_line]` 内。

### 3.2 行号验证

本地程序检查（L0.4 的一部分）：

- 每个场景的 `[start_line, end_line]` 不重叠、不越界。
- 每个 `story_fact` 的 `[Lstart-Lend]` 引用存在且不超出文件范围。

## 4. 剧本格式支持

### 4.1 支持的格式

| 格式 | 标识 | 说明 |
|---|---|---|
| Markdown 剧本 | 场景标题用 `##` / `#` | 优先支持；当前 EP14 S1 先导篇格式 |
| 影视标准格式 | `INT.` / `EXT.` 场景头，角色名大写居中，对话缩进 | 场景切分支持 |
| 中文混合格式 | 中文场景标记 + `角色名：` 对话 | 场景切分支持 |

### 4.2 不支持且不自动解释的格式

- 纯对话列表（无场景头、无动作描述）→ 标记 `unresolved: no_scene_structure`
- 小说或散文 → 标记 `unresolved: prose_format`
- PDF / DOCX / 富文本 → 要求用户先转为 UTF-8 纯文本
- 分镜脚本（已含 Shot 编号和技术参数）→ 标记 `unresolved: shotlist_format`

## 5. 角色与对话事实

### 5.1 Director 提取角色名

本地解析器不提取或猜测角色名。Director 在同一事实批次中从原文提取角色名，每项携带首次出现行号和确定度，但不改变角色关系事实：

- 场景头下的角色列表（`**角色**：A, B` 或 `- A：描述`）
- 对话前缀（`角色名：` 或 `角色名（动作）：` 或全大写角色名行）
- 动作描述中的人物专名（启发式，标记 `confidence: low`）

### 5.2 Director 提取对白

- 有明确角色归属的对话记录为 `{speaker, text, line_range}`
- 无法确定说话人的对话标记 `speaker: UNKNOWN`
- 多人同时说话标记 `speaker: MULTIPLE` 并附所有可能角色

本地程序只验证引用行号存在并位于对应场景范围内，不判断角色、事件或对白文本是否语义正确。

## 6. 无法确定时的处理

### 6.1 标记而非猜测

| 情况 | 标记 | 后续动作 |
|---|---|---|
| 场景边界模糊 | `unresolved: implicit_scene_boundary` | 请求用户标注边界 |
| 场景标题存在但无编号 | `scene_number: null` | 按出现顺序分配临时编号 |
| 角色名模糊 | `speaker: UNKNOWN` | Director 可基于上下文推断，但必须在 `SCRIPT_FACTS` 中标注 `inferred` |
| 地点未明确 | `location: UNKNOWN` | 不编造空间事实 |
| 时间未明确 | `time: UNKNOWN` | Director 可基于场景事件推断并标注 `inferred` |
| 编码无法确定 | `encoding: unknown` | 报错退出，请求用户提供 UTF-8 版本 |
| 文件不可读 | `error: unreadable` | 报错退出，不创建部分会话 |

### 6.2 禁止行为

- 解析器不得将模糊场景边界自动按空行切分。
- 解析器不得从角色名推断人物关系、情感或动机。
- 解析器不得为缺失的地点/时间编造默认值。
- 解析器不得将 `inferred` 事实静默升级为确定事实。
- Director 不得新增剧本外角色、对白、事件或结局（LOOP_SPEC 原则 1）。

## 7. 输出边界

### 7.1 本地输出：SCRIPT_STRUCTURE.json

本地解析器只输出：文件路径、编码、规范化内容 SHA-256、总行数、显式场景范围、标题原文、可直接读取的地点/时间提示和 unresolved 原因。它不输出事件、角色、对白或连续性判断。

### 7.2 Director 输出：SCRIPT_FACTS.md

Director 基于完整剧本和 `SCRIPT_STRUCTURE.json` 填写 `SCRIPT_FACTS.md`，保证包含：

- 文件路径、编码、总行数、场景数
- 场景清单：编号、标题、行号范围、地点提示、时间提示、解析状态
- 角色清单：角色名、首次出现行号、确定度
- 逐场事实：事件（附行号）、对白（附说话人和行号）、连续性入口
- 未确定项列表（如有）

每项事件、对白和连续性事实必须使用 `- [Lstart-Lend] ...`，并由本地程序验证。事实文件必须保存源内容 SHA-256；剧本变化后旧事实文件立即失效。

### 7.3 明确不包含

- 镜头设计、机位、运镜、构图。
- 光影方案、色彩策略。
- 人物内心状态解读。
- 任何视觉生成参数。
- 规则 ID、知识库引用、审计证据。

## 8. 契约版本与兼容性

- 本契约版本为 `1.0`，对应 LOOP_SPEC v3.0 的当前分集输入层。
- 解析器实现必须声明所实现的契约版本。
- 契约新增可选字段时递增次版本号；修改或删除必需字段时递增主版本号。
- `SCRIPT_FACTS.md` 文件头部必须包含 `<!-- contract: script_input v1.0 -->` 注释。
